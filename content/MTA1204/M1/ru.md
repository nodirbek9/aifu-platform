## Почему это важно

Слово «алгоритм» мы слышим каждый день: навигатор находит маршрут, социальная сеть упорядочивает ленту, банк оценивает кредит. Но что именно можно назвать алгоритмом? Рецепт — алгоритм? А указание «напиши хорошую программу»? Эти вопросы всерьёз стояли перед математиками в начале XX века: чтобы ответить, «существует ли механический способ решить любую математическую задачу?», сначала надо было точно определить сам «механический способ».

На этой лекции рассмотрим три определения понятия алгоритма, его свойства и самую известную формальную модель — **машину Тьюринга**. Эти знания — фундамент всего курса: сравнивая скорость алгоритмов в следующих темах, мы будем опираться именно на эти понятия.

## Три определения алгоритма

| Определение | Содержание | Кому удобно |
|---|---|---|
| **Интуитивное** | точная упорядоченная последовательность указаний исполнителю для достижения определённой цели | повседневная жизнь, обучение программированию |
| **Формальное** | процесс, записанный в рамках точной математической модели (машина Тьюринга, нормальный алгоритм Маркова, рекурсивные функции) | математика, теория вычислений |
| **Кибернетическое** | система команд, переводящая объект управления из начального состояния в целевое; исполнитель — человек, автомат или компьютер | системы управления, автоматика |

Слово «алгоритм» происходит от *Algoritmi* — латинской формы имени великого учёного IX века из Хорезма **Мухаммада ибн Мусы аль-Хорезми**. Его труд о счёте индийскими цифрами распространил в Европе правила арифметических действий.

## Свойства алгоритма

| Свойство | Смысл | Пример нарушения |
|---|---|---|
| **Дискретность** | процесс состоит из отдельных последовательных шагов | «медленно нагревайте» — шаг не ясен |
| **Определённость** (детерминированность) | каждый шаг однозначен, исполнитель точно знает, что делать | «добавьте немного соли» |
| **Результативность** | алгоритм даёт требуемый результат | цикл, никогда не выдающий результат |
| **Массовость** | работает не для одной задачи, а для класса однотипных задач | указания, находящие НОД только чисел 12 и 18 |
| **Конечность** | при любых допустимых входных данных останавливается за конечное число шагов | `while true:` — бесконечный цикл |

Доказать конечность не всегда просто. Знаменитая **гипотеза Коллатца**: начав с любого натурального числа и деля его на 2, если оно чётное, или умножая на 3 и прибавляя 1, если нечётное, в итоге придём к 1. Это проверено на компьютере для очень больших чисел, но **не доказано** — значит, пока никто не может гарантировать, что этот процесс конечен для любого входа.

## Виды алгоритмов

| Вид | Структура | Пример |
|---|---|---|
| Линейный | команды подряд, без условий | вычисление площади прямоугольника |
| Ветвящийся | разные пути в зависимости от условия | корни квадратного уравнения (знак дискриминанта) |
| Циклический | группа команд выполняется многократно | сумма массива |
| Рекурсивный | алгоритм вызывает себя с меньшим входом | факториал, Ханойские башни |

Способы описания алгоритмов: **словесный**, **блок-схема** (ромб — условие, прямоугольник — действие, параллелограмм — ввод/вывод), **псевдокод** и **язык программирования**.

## Машина Тьюринга

В 1936 году английский математик **Алан Тьюринг** предложил воображаемую машину, чтобы определить «механическое вычисление». Она очень проста, но может сделать всё, что умеет любой компьютер.

| Часть | Назначение |
|---|---|
| **Лента** | бесконечна в обе стороны, разделена на ячейки; в каждой ячейке один символ алфавита (пустая ячейка — `_`) |
| **Головка** | видит одну ячейку: читает символ, записывает и сдвигается на одну ячейку влево (L) или вправо (R) |
| **Состояния** | конечная «память» машины: начальное, рабочие и состояние останова |
| **Таблица переходов** | программа: (текущее состояние, прочитанный символ) → (записываемый символ, движение, новое состояние) |

На каждом шаге машина находит одну строку таблицы и выполняет её. Если подходящей строки нет или достигнуто состояние останова, машина останавливается; результат — то, что осталось на ленте.

## Тезис Чёрча–Тьюринга

**Тезис Чёрча–Тьюринга**: любую функцию, вычислимую алгоритмом в интуитивном смысле, может вычислить и машина Тьюринга. Это не теорема — поскольку «интуитивный алгоритм» точно не определён, доказать его нельзя. Но все предложенные до сих пор модели вычислений (алгоритмы Маркова, лямбда-исчисление, современные языки программирования) доказуемо **равносильны** машине Тьюринга.

Важное следствие: существуют задачи, которые **вообще нельзя решить** алгоритмом. Самая известная — **проблема останова**: нет алгоритма, который для любой программы и входа всегда правильно отвечает «остановится ли эта программа?» (Тьюринг, 1936).

## Разобранный пример 1: последовательность Коллатца и конечность

Дано *n* (1 ≤ *n* ≤ 10⁹). Выведите, сколько шагов по правилу Коллатца нужно, чтобы дойти до 1, и наибольшее значение на этом пути.

```python
n = int(input())
qadam = 0
eng_katta = n
while n != 1:                   # цикл, конечность которого не доказана!
    if n % 2 == 0:
        n //= 2
    else:
        n = 3 * n + 1
    qadam += 1
    eng_katta = max(eng_katta, n)
print(qadam, eng_katta)
```
```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        long n = new Scanner(System.in).nextLong();
        long qadam = 0, engKatta = n;
        while (n != 1) {                // цикл, конечность которого не доказана!
            if (n % 2 == 0) n /= 2;
            else n = 3 * n + 1;
            qadam++;
            engKatta = Math.max(engKatta, n);
        }
        System.out.println(qadam + " " + engKatta);
    }
}
```
```cpp
#include <algorithm>
#include <iostream>
using namespace std;

int main() {
    long long n;
    cin >> n;
    long long qadam = 0, engKatta = n;
    while (n != 1) {                    // цикл, конечность которого не доказана!
        if (n % 2 == 0) n /= 2;
        else n = 3 * n + 1;
        qadam++;
        engKatta = max(engKatta, n);
    }
    cout << qadam << " " << engKatta << endl;
    return 0;
}
```

Для `6`: 6 → 3 → 10 → 5 → 16 → 8 → 4 → 2 → 1, выводится `8 16`. Для `27` — `111 9232`: маленькое число поднимается до 9232 и опускается за 111 шагов (*qadam* — шаг, *eng_katta* — наибольшее). Эта программа **дискретна** (каждый проход цикла — один шаг), **определённа** (на каждом шаге одно правило) и **массова** (для любого *n*). Но её **конечность** — открытая проблема математики. Значения могут намного превысить *n*, поэтому в Java и C++ использован `long`.

## Разобранный пример 2: машина Тьюринга — прибавление единицы к двоичному числу

На ленте записано двоичное число, головка стоит на его **последней** цифре. Машина прибавляет к числу 1:

| Состояние | Прочитано | Записать | Движение | Новое состояние |
|---|---|---|---|---|
| `q0` | `1` | `0` | L | `q0` (перенос продолжается) |
| `q0` | `0` | `1` | — | `stop` |
| `q0` | `_` | `1` | — | `stop` (новая цифра в начале) |

Дано двоичное число. Смоделируйте машину и выведите результат и число выполненных шагов.

```python
lenta = list(input().strip())
kallak = len(lenta) - 1         # последняя цифра
holat = "q0"
qadam = 0

# таблица переходов: (состояние, символ) -> (записать, движение, новое состояние)
jadval = {
    ("q0", "1"): ("0", -1, "q0"),
    ("q0", "0"): ("1", 0, "stop"),
    ("q0", "_"): ("1", 0, "stop"),
}

while holat != "stop":
    if kallak < 0:              # лента бесконечна влево: добавляем пустую ячейку
        lenta.insert(0, "_")
        kallak = 0
    yoz, harakat, holat = jadval[(holat, lenta[kallak])]
    lenta[kallak] = yoz
    kallak += harakat
    qadam += 1

print("".join(lenta).strip("_"))
print(qadam)
```
```java
import java.util.HashMap;
import java.util.Map;
import java.util.Scanner;

public class Main {
    record Otish(char yoz, int harakat, String holat) {}

    public static void main(String[] args) {
        StringBuilder lenta = new StringBuilder(new Scanner(System.in).next());
        int kallak = lenta.length() - 1;    // последняя цифра
        String holat = "q0";
        int qadam = 0;

        // таблица переходов: состояние + символ -> (записать, движение, новое состояние)
        Map<String, Otish> jadval = new HashMap<>();
        jadval.put("q0 1", new Otish('0', -1, "q0"));
        jadval.put("q0 0", new Otish('1', 0, "stop"));
        jadval.put("q0 _", new Otish('1', 0, "stop"));

        while (!holat.equals("stop")) {
            if (kallak < 0) {               // лента бесконечна влево: добавляем пустую ячейку
                lenta.insert(0, '_');
                kallak = 0;
            }
            Otish o = jadval.get(holat + " " + lenta.charAt(kallak));
            lenta.setCharAt(kallak, o.yoz());
            kallak += o.harakat();
            holat = o.holat();
            qadam++;
        }

        System.out.println(lenta.toString().replace("_", ""));
        System.out.println(qadam);
    }
}
```
```cpp
#include <iostream>
#include <map>
#include <string>
#include <tuple>
using namespace std;

int main() {
    string lenta;
    cin >> lenta;
    int kallak = lenta.size() - 1;          // последняя цифра
    string holat = "q0";
    int qadam = 0;

    // таблица переходов: (состояние, символ) -> (записать, движение, новое состояние)
    map<pair<string, char>, tuple<char, int, string>> jadval = {
        {{"q0", '1'}, {'0', -1, "q0"}},
        {{"q0", '0'}, {'1', 0, "stop"}},
        {{"q0", '_'}, {'1', 0, "stop"}},
    };

    while (holat != "stop") {
        if (kallak < 0) {                   // лента бесконечна влево: добавляем пустую ячейку
            lenta.insert(lenta.begin(), '_');
            kallak = 0;
        }
        auto [yoz, harakat, yangi] = jadval[{holat, lenta[kallak]}];
        lenta[kallak] = yoz;
        kallak += harakat;
        holat = yangi;
        qadam++;
    }

    string natija;
    for (char c : lenta) if (c != '_') natija += c;
    cout << natija << endl << qadam << endl;
    return 0;
}
```

Для `1011` (11) выводится `1100` (12) и `3`: две последние `1` превращаются в `0` (перенос), а на третьем шаге `0` становится `1`. Для `111` (7) результат `1000` (8) за `4` шага: на последнем шаге головка выходит за начало ленты и записывает `1` в пустую ячейку (*lenta* — лента, *kallak* — головка, *holat* — состояние, *jadval* — таблица). Программа машины — таблица всего из трёх строк, а симулятор работает с любой таблицей: замените таблицу — получите другую машину. Современный компьютер, по сути, такой же: процессор — «симулятор», программа — «таблица».

:::warning
**Частые ошибки**

- **Считать алгоритмом любой список указаний.** Расплывчатые шаги вроде «немного», «до готовности» нарушают определённость.
- **Не проверять конечность.** Если условие цикла никогда не станет ложным, программа зависнет; для каждого цикла спрашивайте: «почему он остановится?».
- **Называть тезис Чёрча–Тьюринга теоремой.** Он не доказан, хотя общепринят.
- **Считать машину Тьюринга реальным устройством.** Это математическая модель; бесконечная лента — лишь теоретическая.
:::

:::tip
Проследите работу машины Тьюринга на бумаге: для каждого шага записывайте состояние ленты и подчёркивайте ячейку под головкой. «Выполнение» одной машины вручную объясняет идею лучше десятков определений.
:::

## Итоги

- Интуитивное определение алгоритма — последовательность точных указаний; формальное — математическая модель; кибернетическое — система команд, переводящая объект в целевое состояние.
- Свойства алгоритма: дискретность, определённость, результативность, массовость, конечность.
- По структуре алгоритмы бывают линейными, ветвящимися, циклическими и рекурсивными.
- Машина Тьюринга состоит из ленты, головки, конечного числа состояний и таблицы переходов; она может сделать всё, что умеет любой компьютер.
- Тезис Чёрча–Тьюринга: интуитивно вычислимое = вычислимое машиной Тьюринга; проблема останова алгоритмически неразрешима.

## Проверьте себя

:::check
Q: От чьего имени происходит слово «алгоритм»?
A: От *Algoritmi* — латинской формы имени учёного IX века Мухаммада ибн Мусы аль-Хорезми.
Q: Какое свойство нарушает указание «пеките пирог до готовности»?
A: Определённость (и конечность тоже): состояние «готов» точно не определено.
Q: Что означает одна строка таблицы переходов машины Тьюринга?
A: Для пары (текущее состояние, прочитанный символ): какой символ записать, куда сдвинуть головку и в какое состояние перейти.
Q: Сколько шагов сделает машина прибавления единицы для `1111`?
A: 5: превратит четыре `1` в `0` и на пятом шаге запишет `1` в пустую ячейку.
Q: Почему тезис Чёрча–Тьюринга нельзя доказать?
A: В нём участвует понятие «интуитивного алгоритма», которое математически точно не определено.
