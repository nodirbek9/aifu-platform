## Почему это важно

На лекции мы теоретически рассмотрели обозначение *O* и рекуррентные соотношения. На практике вопрос простой: действительно ли моя программа работает за *O*(*n* log *n*), или я ошибся в расчёте? Надёжнее всего ответить, **посчитав** операции и понаблюдав, как они растут с ростом *n*.

На этом занятии проведём три эксперимента: посчитаем операции линейного, квадратичного и логарифмического циклов; измерим вызовы и глубину рекурсивного алгоритма «разделяй и властвуй»; увидим, как быстро «взрывается» число вызовов простой рекурсивной функции Фибоначчи.

:::note
**После этого занятия вы сможете:**

- добавлять в программу счётчик и измерять число операций;
- определять класс сложности методом удвоения *n*;
- составлять для рекурсивного алгоритма рекуррентное соотношение и заранее вычислять число вызовов;
- объяснять разницу между глубиной рекурсии и числом вызовов.
:::

## Экспериментальная проверка сложности

Метод: удваиваем *n* и смотрим, во сколько раз выросло число операций.

| Сложность | Операции при *n* → 2*n* | Признак |
|---|---|---|
| *O*(log *n*) | +1 | почти не меняется |
| *O*(*n*) | × 2 | удваивается |
| *O*(*n* log *n*) | чуть больше × 2 | |
| *O*(*n*²) | × 4 | учетверяется |
| *O*(2ⁿ) | возводится в квадрат | удваивается даже при *n* + 1 |

Можно измерять и время в секундах, но оно зависит от загрузки компьютера и неточно при малых *n*. Счётчик же всегда даёт один и тот же результат.

## Анализ рекурсивного алгоритма

Метод **«разделяй и властвуй»** (divide and conquer): разбить задачу на две половины, решить каждую рекурсивно и объединить результаты. Важны два показателя:

| Показатель | Смысл | Что определяет |
|---|---|---|
| Число вызовов | сколько всего раз вызвана функция | время |
| Глубина рекурсии | наибольшее число вызовов в стеке одновременно | память (стек) |

При поиске максимума делением массива пополам: *T*(*n*) = 2*T*(*n*/2) + 1, *T*(1) = 1. Решение: *T*(*n*) = 2*n* − 1 вызовов, а глубина — ⌈log₂ *n*⌉ + 1. Значит, время *O*(*n*), а память стека *O*(log *n*).

## Разобранный пример 1: подсчёт операций

Дано *n* (1 ≤ *n* ≤ 3000). Посчитайте и выведите число внутренних операций трёх циклов: (1) просмотр каждого элемента один раз; (2) просмотр всех пар (*i* < *j*); (3) деление *n* пополам до 1.

```python
n = int(input())

chiziqli = 0
for i in range(n):
    chiziqli += 1

kvadratik = 0
for i in range(n):
    for j in range(i + 1, n):       # все пары i < j
        kvadratik += 1

logarifmik = 0
m = n
while m > 1:
    m //= 2
    logarifmik += 1

print(chiziqli, kvadratik, logarifmik)
```
```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        int n = new Scanner(System.in).nextInt();

        long chiziqli = 0;
        for (int i = 0; i < n; i++) chiziqli++;

        long kvadratik = 0;
        for (int i = 0; i < n; i++)
            for (int j = i + 1; j < n; j++)     // все пары i < j
                kvadratik++;

        long logarifmik = 0;
        for (int m = n; m > 1; m /= 2) logarifmik++;

        System.out.println(chiziqli + " " + kvadratik + " " + logarifmik);
    }
}
```
```cpp
#include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;

    long long chiziqli = 0;
    for (int i = 0; i < n; i++) chiziqli++;

    long long kvadratik = 0;
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)         // все пары i < j
            kvadratik++;

    long long logarifmik = 0;
    for (int m = n; m > 1; m /= 2) logarifmik++;

    cout << chiziqli << " " << kvadratik << " " << logarifmik << endl;
    return 0;
}
```

| *n* | Линейный | Квадратичный | Логарифмический |
|---|---|---|---|
| 1000 | 1 000 | 499 500 | 9 |
| 2000 | 2 000 | 1 999 000 | 10 |
| 3000 | 3 000 | 4 498 500 | 11 |

При удвоении *n* линейный счётчик удвоился, квадратичный — почти учетверился (*n*(*n* − 1)/2), а логарифмический вырос всего на один. Одна эта таблица показывает сложность алгоритмов. Обратите внимание: квадратичному циклу при *n* = 3000 нужно 4,5 миллиона операций — при *n* = 10⁶ было бы 5 · 10¹¹, это не сосчитать.

## Разобранный пример 2: «разделяй и властвуй» — максимум, вызовы, глубина

В первой строке *n*, во второй — *n* чисел. Найдите максимум рекурсивно, деля массив пополам; выведите максимум, число вызовов и наибольшую глубину рекурсии.

```python
chaqiruvlar = 0
chuqurlik = 0


def maksimum(a, chap, ong, daraja):
    global chaqiruvlar, chuqurlik
    chaqiruvlar += 1
    chuqurlik = max(chuqurlik, daraja)
    if chap == ong:                             # один элемент
        return a[chap]
    orta = (chap + ong) // 2
    return max(maksimum(a, chap, orta, daraja + 1),
               maksimum(a, orta + 1, ong, daraja + 1))


n = int(input())
a = list(map(int, input().split()))
print(maksimum(a, 0, n - 1, 1), chaqiruvlar, chuqurlik)
```
```java
import java.util.Scanner;

public class Main {
    static long chaqiruvlar = 0;
    static int chuqurlik = 0;

    static int maksimum(int[] a, int chap, int ong, int daraja) {
        chaqiruvlar++;
        chuqurlik = Math.max(chuqurlik, daraja);
        if (chap == ong) return a[chap];            // один элемент
        int orta = (chap + ong) / 2;
        return Math.max(maksimum(a, chap, orta, daraja + 1),
                        maksimum(a, orta + 1, ong, daraja + 1));
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        int[] a = new int[n];
        for (int i = 0; i < n; i++) a[i] = in.nextInt();
        int m = maksimum(a, 0, n - 1, 1);
        System.out.println(m + " " + chaqiruvlar + " " + chuqurlik);
    }
}
```
```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

long long chaqiruvlar = 0;
int chuqurlik = 0;

int maksimum(const vector<int>& a, int chap, int ong, int daraja) {
    chaqiruvlar++;
    chuqurlik = max(chuqurlik, daraja);
    if (chap == ong) return a[chap];                // один элемент
    int orta = (chap + ong) / 2;
    return max(maksimum(a, chap, orta, daraja + 1),
               maksimum(a, orta + 1, ong, daraja + 1));
}

int main() {
    int n;
    cin >> n;
    vector<int> a(n);
    for (int& x : a) cin >> x;
    int m = maksimum(a, 0, n - 1, 1);
    cout << m << " " << chaqiruvlar << " " << chuqurlik << endl;
    return 0;
}
```

Для `8` и `3 9 2 7 5 1 8 6` выводится `9 15 4`: 2 · 8 − 1 = 15 вызовов и log₂ 8 + 1 = 4 уровня — как и предсказало рекуррентное соотношение. Для `3` и `5 1 4` — `5 5 3` (*chaqiruvlar* — вызовы, *chuqurlik* — глубина, *daraja* — уровень). Этот алгоритм не быстрее обычного поиска максимума в цикле (оба — *O*(*n*)), но именно эта схема лежит в основе сортировки слиянием и быстрой сортировки. Число вызовов определяет время, а глубина — память стека: на миллионе элементов будет 2 миллиона вызовов, но в стеке одновременно — лишь ~21.

## Разобранный пример 3: простая рекурсивная функция Фибоначчи

Дано *n* (0 ≤ *n* ≤ 30). Вычислите *F*(*n*) прямой рекурсией и выведите, сколько раз была вызвана функция.

```python
chaqiruvlar = 0


def fib(n):
    global chaqiruvlar
    chaqiruvlar += 1
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)


n = int(input())
print(fib(n), chaqiruvlar)
```
```java
import java.util.Scanner;

public class Main {
    static long chaqiruvlar = 0;

    static long fib(int n) {
        chaqiruvlar++;
        if (n < 2) return n;
        return fib(n - 1) + fib(n - 2);
    }

    public static void main(String[] args) {
        int n = new Scanner(System.in).nextInt();
        long f = fib(n);
        System.out.println(f + " " + chaqiruvlar);
    }
}
```
```cpp
#include <iostream>
using namespace std;

long long chaqiruvlar = 0;

long long fib(int n) {
    chaqiruvlar++;
    if (n < 2) return n;
    return fib(n - 1) + fib(n - 2);
}

int main() {
    int n;
    cin >> n;
    long long f = fib(n);
    cout << f << " " << chaqiruvlar << endl;
    return 0;
}
```

| *n* | *F*(*n*) | Вызовов |
|---|---|---|
| 10 | 55 | 177 |
| 20 | 6 765 | 21 891 |
| 25 | 75 025 | 242 785 |

Каждый раз, когда *n* растёт на 5, число вызовов растёт примерно в 11 раз (φ⁵ ≈ 11): это экспоненциальный рост. При *n* = 50 число вызовов достигает 4 · 10¹⁰. Причина — одни и те же значения вычисляются снова и снова; способ это исправить выполняется в самостоятельном задании. В Java и C++ результат `fib(n)` взят в отдельную переменную, чтобы он гарантированно вычислялся раньше `chaqiruvlar` в выражении вывода.

:::warning
**Частые ошибки**

- **Счётчик не на том месте.** Счётчик должен стоять рядом с подсчитываемой операцией (тело внутреннего цикла, вход в функцию).
- **Вывод по одному измерению.** Сложность — это скорость роста; сравнивайте хотя бы два разных *n*.
- **Путаница глубины и числа вызовов.** 15 вызовов могут иметь глубину 4 уровня — они измеряют разные ресурсы.
- **Опора на порядок вычисления в C++/Java.** В `cout << fib(n) << chaqiruvlar` порядок вычисления частей до C++17 не гарантирован; сначала сохраните результат в переменную.
:::

:::tip
Запишите результаты эксперимента в таблицу и вычислите отношение соседних строк (например, 1 999 000 / 499 500 ≈ 4). Если отношение остаётся постоянным, класс сложности найден верно.
:::

## Итоги

- Измеряя число операций счётчиком и удваивая *n*, класс сложности можно определить экспериментально.
- Алгоритм «разделяй и властвуй» анализируется рекуррентным соотношением: *T*(*n*) = 2*T*(*n*/2) + 1 → 2*n* − 1 вызовов.
- Число вызовов определяет время, глубина рекурсии — память стека.
- Простая рекурсивная функция Фибоначчи экспоненциальна: одни и те же значения вычисляются многократно.

A: Одни и те же малые значения (*F*(*n* − 2), *F*(*n* − 3), …) многократно пересчитываются; число вызовов растёт экспоненциально.
