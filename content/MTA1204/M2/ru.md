## Почему это важно

Два программиста решили одну задачу: программа одного работает на 1 000 записях 0,01 секунды, другого — 0,02 секунды. Какая лучше? Ответ зависит от того, что будет с ростом числа записей: на 1 000 000 записей первая может работать 3 часа, а вторая — 0,5 секунды. Именно поэтому алгоритмы сравнивают **не в секундах, а по скорости роста**.

На этой лекции разберём, как оценивать сложность алгоритма, как находить сложность рекурсивных алгоритмов и насколько быстры самые распространённые алгоритмы поиска — линейный, двоичный и интерполяционный.

- писать линейный, двоичный и интерполяционный поиск и сравнивать их сложность.

## Временна́я и пространственная сложность

**Временна́я сложность** — число основных операций *T*(*n*), выполняемых алгоритмом, в зависимости от размера входа *n*. **Пространственная сложность** — дополнительная память *S*(*n*), нужная алгоритму. Секунды зависят от компьютера, а число операций — нет, поэтому считают операции.

Обычно оценивают **худший случай**: вход, на котором алгоритм работает дольше всего. Иногда важен и **средний случай** (например, в быстрой сортировке и интерполяционном поиске).

| Обозначение | Смысл | Читается |
|---|---|---|
| *T*(*n*) = *O*(*f*(*n*)) | оценка сверху: при достаточно больших *n* *T*(*n*) ≤ *c* · *f*(*n*) | «не более порядка *f*» |
| *T*(*n*) = Ω(*f*(*n*)) | оценка снизу: *T*(*n*) ≥ *c* · *f*(*n*) | «не менее порядка *f*» |
| *T*(*n*) = Θ(*f*(*n*)) | оценка с обеих сторон | «ровно порядка *f*» |

Правила вычисления: постоянные множители отбрасываются (3*n* → *O*(*n*)), остаётся самый быстро растущий член (*n*² + 100*n* → *O*(*n*²)), последовательные части складываются, вложенные циклы перемножаются.

## Классы сложности

| Класс | Операций при *n* = 10⁶ | Пример |
|---|---|---|
| *O*(1) | 1 | обращение к элементу массива |
| *O*(log *n*) | ~20 | двоичный поиск |
| *O*(*n*) | 10⁶ | линейный поиск |
| *O*(*n* log *n*) | ~2 · 10⁷ | сортировка слиянием |
| *O*(*n*²) | 10¹² | сортировка пузырьком |
| *O*(2ⁿ) | невозможно вычислить | перебор всех подмножеств |

Современный компьютер выполняет ~10⁸–10⁹ простых операций в секунду. Значит, при *n* = 10⁶ *O*(*n* log *n*) — мгновенно, а *O*(*n*²) — несколько часов.

**Класс P** — задачи, решаемые за полиномиальное время (*O*(*n*ᵏ)). **Класс NP** — задачи, данное решение которых можно **проверить** за полиномиальное время (например, судоку: решить трудно, проверить легко). Верно ли P = NP? — самый известный открытый вопрос информатики; за его доказательство Институт Клэя назначил премию в миллион долларов.

## Сложность рекурсивных алгоритмов

Время рекурсивного алгоритма записывается **рекуррентным соотношением**: время большой задачи через время меньших.

| Рекуррентное соотношение | Алгоритм | Решение |
|---|---|---|
| *T*(*n*) = *T*(*n* − 1) + *O*(1) | рекурсивный факториал, сумма | *O*(*n*) |
| *T*(*n*) = *T*(*n*/2) + *O*(1) | двоичный поиск | *O*(log *n*) |
| *T*(*n*) = 2*T*(*n*/2) + *O*(*n*) | сортировка слиянием | *O*(*n* log *n*) |
| *T*(*n*) = *T*(*n* − 1) + *T*(*n* − 2) + *O*(1) | простая рекурсивная функция Фибоначчи | *O*(φⁿ) ≈ *O*(1,618ⁿ) |

Например, в двоичном поиске каждый шаг вдвое сокращает область поиска: *n* → *n*/2 → *n*/4 → … → 1. Это log₂ *n* шагов.

## Алгоритмы поиска

| Алгоритм | Условие | Худший случай | Средний |
|---|---|---|---|
| Линейный | нет | *O*(*n*) | *O*(*n*) |
| Двоичный | массив отсортирован | *O*(log *n*) | *O*(log *n*) |
| Интерполяционный | отсортирован, значения **распределены равномерно** | *O*(*n*) | *O*(log log *n*) |

**Интерполяционный поиск** похож на поиск имени в телефонной книге: ища «Юлдашев», мы открываем книгу не посередине, а ближе к концу. Следующая проверяемая позиция вычисляется линейной интерполяцией:

```text
позиция = левая + (x − a[левая]) · (правая − левая) / (a[правая] − a[левая])
```

Если значения распределены равномерно (например, 10, 20, 30, …), позиция находится почти сразу. При неравномерном распределении (1, 2, 4, 8, …) он может работать медленнее двоичного поиска.

## Разобранный пример 1: число сравнений в линейном и двоичном поиске

Даны *n* и *x*. Массив `a[i] = 2i + 1` (первые *n* нечётных чисел по возрастанию). Найдите *x* линейным и двоичным поиском и выведите в одной строке, сколько сравнений выполнил каждый.

```python
n, x = map(int, input().split())


def a(i):                           # массив не храним в памяти
    return 2 * i + 1


chiziqli = 0
for i in range(n):
    chiziqli += 1
    if a(i) == x:
        break

binar = 0
chap, ong = 0, n - 1
while chap <= ong:
    binar += 1
    orta = (chap + ong) // 2
    if a(orta) == x:
        break
    if a(orta) < x:
        chap = orta + 1
    else:
        ong = orta - 1

print(chiziqli, binar)
```
```java
import java.util.Scanner;

public class Main {
    static long a(long i) {                 // массив не храним в памяти
        return 2 * i + 1;
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        long n = in.nextLong(), x = in.nextLong();

        long chiziqli = 0;
        for (long i = 0; i < n; i++) {
            chiziqli++;
            if (a(i) == x) break;
        }

        long binar = 0, chap = 0, ong = n - 1;
        while (chap <= ong) {
            binar++;
            long orta = (chap + ong) / 2;
            if (a(orta) == x) break;
            if (a(orta) < x) chap = orta + 1;
            else ong = orta - 1;
        }

        System.out.println(chiziqli + " " + binar);
    }
}
```


| Ввод | Линейный | Двоичный | Комментарий |
|---|---|---|---|
| `1000000 1` | 1 | 19 | первый элемент — лучший случай для линейного |
| `1000000 1234567` | 617 284 | 20 | обычный случай |
| `1000000 4` | 1 000 000 | 20 | чётного числа нет — худший случай для обоих |

На миллионе элементов двоичный поиск делает не более 20 сравнений (2²⁰ ≈ 10⁶), а линейный — до миллиона (*chiziqli* — линейный, *binar* — двоичный, *chap*/*ong*/*orta* — левая/правая/середина). Но в первой строке выиграл линейный поиск: сложность описывает **худший** или **средний** случай, а не каждый отдельный вход.

## Разобранный пример 2: интерполяционный поиск

В первой строке *n*, во второй — *n* целых чисел по возрастанию, в третьей — *x*. Найдите позицию *x* (с 1; если нет — −1) интерполяционным поиском; выведите позицию и число шагов интерполяционного и двоичного поиска.

```python
def interpolyatsion(a, x):
    chap, ong = 0, len(a) - 1
    qadam = 0
    while chap <= ong and a[chap] <= x <= a[ong]:
        qadam += 1
        if a[ong] == a[chap]:
            orin = chap
        else:
            orin = chap + (x - a[chap]) * (ong - chap) // (a[ong] - a[chap])
        if a[orin] == x:
            return orin + 1, qadam
        if a[orin] < x:
            chap = orin + 1
        else:
            ong = orin - 1
    return -1, qadam


def binar(a, x):
    chap, ong = 0, len(a) - 1
    qadam = 0
    while chap <= ong:
        qadam += 1
        orta = (chap + ong) // 2
        if a[orta] == x:
            return orta + 1, qadam
        if a[orta] < x:
            chap = orta + 1
        else:
            ong = orta - 1
    return -1, qadam


n = int(input())
a = list(map(int, input().split()))
x = int(input())
orin, q1 = interpolyatsion(a, x)
_, q2 = binar(a, x)
print(orin, q1, q2)
```
```java
import java.util.Scanner;

public class Main {
    // результат: {позиция (с 1 или -1), шаги}
    static long[] interpolyatsion(long[] a, long x) {
        int chap = 0, ong = a.length - 1;
        long qadam = 0;
        while (chap <= ong && a[chap] <= x && x <= a[ong]) {
            qadam++;
            int orin = a[ong] == a[chap] ? chap
                    : (int) (chap + (x - a[chap]) * (ong - chap) / (a[ong] - a[chap]));
            if (a[orin] == x) return new long[] {orin + 1, qadam};
            if (a[orin] < x) chap = orin + 1;
            else ong = orin - 1;
        }
        return new long[] {-1, qadam};
    }

    static long[] binar(long[] a, long x) {
        int chap = 0, ong = a.length - 1;
        long qadam = 0;
        while (chap <= ong) {
            qadam++;
            int orta = (chap + ong) / 2;
            if (a[orta] == x) return new long[] {orta + 1, qadam};
            if (a[orta] < x) chap = orta + 1;
            else ong = orta - 1;
        }
        return new long[] {-1, qadam};
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        long[] a = new long[n];
        for (int i = 0; i < n; i++) a[i] = in.nextLong();
        long x = in.nextLong();
        long[] i1 = interpolyatsion(a, x), b1 = binar(a, x);
        System.out.println(i1[0] + " " + i1[1] + " " + b1[1]);
    }
}
```
```cpp
#include <iostream>
#include <utility>
#include <vector>
using namespace std;

// результат: {позиция (с 1 или -1), шаги}
pair<long long, long long> interpolyatsion(const vector<long long>& a, long long x) {
    long long chap = 0, ong = (long long) a.size() - 1, qadam = 0;
    while (chap <= ong && a[chap] <= x && x <= a[ong]) {
        qadam++;
        long long orin = a[ong] == a[chap] ? chap
                       : chap + (x - a[chap]) * (ong - chap) / (a[ong] - a[chap]);
        if (a[orin] == x) return {orin + 1, qadam};
        if (a[orin] < x) chap = orin + 1;
        else ong = orin - 1;
    }
    return {-1, qadam};
}

pair<long long, long long> binar(const vector<long long>& a, long long x) {
    long long chap = 0, ong = (long long) a.size() - 1, qadam = 0;
    while (chap <= ong) {
        qadam++;
        long long orta = (chap + ong) / 2;
        if (a[orta] == x) return {orta + 1, qadam};
        if (a[orta] < x) chap = orta + 1;
        else ong = orta - 1;
    }
    return {-1, qadam};
}

int main() {
    int n;
    cin >> n;
    vector<long long> a(n);
    for (auto& v : a) cin >> v;
    long long x;
    cin >> x;
    auto [orin, q1] = interpolyatsion(a, x);
    auto [_, q2] = binar(a, x);
    cout << orin << " " << q1 << " " << q2 << endl;
    return 0;
}
```

| Массив | *x* | Результат | Интерполяционный | Двоичный |
|---|---|---|---|---|
| `10 20 30 … 100` | 70 | 7 | 1 шаг | 4 шага |
| `10 20 30 … 100` | 75 | −1 | 1 шаг | 4 шага |
| `1 2 4 8 … 512` | 256 | 9 | 4 шага | 3 шага |

На равномерно распределённом массиве интерполяционный поиск нашёл позицию **с первой попытки**. На удваивающихся числах формула «смещается» к малым значениям и требует больше шагов, чем двоичный поиск (*orin* — позиция, *qadam* — шаг). Проверка `a[ong] == a[chap]` предотвращает деление на ноль. Произведение `(x − a[chap]) · (ong − chap)` может быть большим, поэтому в Java и C++ использован `long`.

:::warning
**Частые ошибки**

- **Излишнее внимание к постоянным множителям.** 2*n* и 100*n* — оба *O*(*n*); при больших *n* разница несущественна по сравнению с *n*².
- **Двоичный или интерполяционный поиск в неотсортированном массиве.** Результат неверен; сначала нужна сортировка (*O*(*n* log *n*)).
- **Деление на ноль в интерполяционном поиске.** Случай `a[ong] == a[chap]` проверяется отдельно.
- **Лучший случай как оценка алгоритма.** Линейный поиск находит первый элемент за один шаг, но его сложность всё равно *O*(*n*).
:::

:::tip
Практический способ проверить сложность алгоритма: удвойте *n* и посмотрите, как изменится время (или число операций). Для *O*(*n*) оно удвоится, для *O*(*n*²) — учетверится, а для *O*(log *n*) вырастет всего на один шаг.
:::

## Итоги

- Сложность — скорость роста числа операций с ростом размера входа; обычно оценивают худший случай.
- *O* — оценка сверху, Ω — снизу, Θ — с обеих сторон.
- Основные классы: *O*(1), *O*(log *n*), *O*(*n*), *O*(*n* log *n*), *O*(*n*²), *O*(2ⁿ); P и NP — задачи, решаемые и проверяемые за полиномиальное время.
- Сложность рекурсивного алгоритма находят по его рекуррентному соотношению.
- Линейный поиск — *O*(*n*), двоичный — *O*(log *n*), интерполяционный — в среднем *O*(log log *n*) (при равномерном распределении).

## Проверьте себя

:::check
Q: Какова сложность алгоритма с *T*(*n*) = 5*n*² + 3*n* + 100?
A: *O*(*n*²) — остаётся самый быстро растущий член, множитель отбрасывается.
Q: Сколько сравнений максимум делает двоичный поиск в отсортированном массиве из 1 000 000 элементов?
A: Около 20, потому что 2²⁰ ≈ 10⁶.
Q: Какую сложность даёт *T*(*n*) = *T*(*n*/2) + *O*(1)?
A: *O*(log *n*).
Q: Когда интерполяционный поиск быстрее двоичного?
A: Когда массив отсортирован, а значения распределены равномерно.
Q: Каков главный признак задачи из класса NP?
A: Предложенное решение можно проверить за полиномиальное время.
