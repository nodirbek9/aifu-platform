## Почему это важно

В алгоритмическом задании больше всего времени уходит не на написание кода, а на **поиск ошибки**. Программа проходит тест из примера, но в автоматической проверке получает «неверный ответ» — на каком входе? Профессиональные программисты и олимпиадники используют для этого **стресс-тестирование**: быстрое (но, возможно, ошибочное) решение сравнивается на тысячах случайных входов с медленным, но заведомо верным. Первое расхождение — маленький пример, показывающий ошибку.

:::note
**После этой самостоятельной работы вы сможете:**

- выполнять алгоритмическое задание по шагам: анализ, медленное решение, быстрое решение, проверка;
- писать программу стресс-теста и находить вход, показывающий ошибку;
- пользоваться генератором случайных чисел, дающим каждый раз один и тот же результат;
- составлять краткий отчёт о проделанной работе.
:::

## Порядок выполнения задания

1. **Анализ условия** — вход, выход, ограничения. По ограничениям определите нужную сложность: при *n* ≤ 10⁵ *O*(*n*²) не подойдёт.
2. **Список крайних случаев** — один элемент, все элементы равны, наибольшие значения, пустой результат.
3. **Медленное решение** — самый простой, заведомо верный способ (полный перебор, вложенные циклы). Быстрым оно быть не обязано.
4. **Быстрое решение** — алгоритм, соответствующий ограничениям.
5. **Проверка** — тесты из примера, крайние случаи и стресс-тест.
6. **Отчёт** — алгоритм, сложность, тесты и вывод.

## Стресс-тестирование

Стресс-тест состоит из трёх частей:

| Часть | Назначение |
|---|---|
| Генератор | создаёт маленький случайный вход (маленький — чтобы найденную ошибку было легко разобрать вручную) |
| Надёжное решение | медленное, но простое и заведомо верное |
| Сравнитель | запускает оба решения на одном входе и сравнивает результаты |

Для воспроизводимости случайные числа вычисляются из **зерна** (seed): одно и то же зерно — одна и та же последовательность тестов. Стандартные генераторы языков различаются, поэтому ниже используется простой **линейный конгруэнтный генератор**:

```text
состояние = (состояние · 1103515245 + 12345) mod 2³¹
```

Эта формула даёт в трёх языках в точности одинаковые числа — ошибочный тест можно воссоздать и на другом языке.

## Образец: ловим ошибку в двоичном поиске

Задача: посчитать в отсортированном массиве элементы **меньше** *x* (нижняя граница). Студент написал двоичный поиск, но ошибся в одном символе. Стресс-тест находит ошибку: вводятся зерно и число тестов; в каждом тесте создаются случайный отсортированный массив длины 1–8 со значениями 0–9 и *x*; надёжное решение — простой подсчёт.

    return sum(1 for v in a if v < x)

```java
import java.util.Arrays;
import java.util.Scanner;

public class Main {
    static long holat;

    static long tasodifiy() {
        holat = (holat * 1103515245L + 12345) % 2147483648L;    // линейный конгруэнтный генератор
        return holat;
    }

    static int ishonchli(int[] a, int x) {          // медленно, но заведомо верно
        int soni = 0;
        for (int v : a) if (v < x) soni++;
        return soni;
    }

    static int tez(int[] a, int x) {                // двоичный поиск — с ошибкой!
        int chap = 0, ong = a.length;
        while (chap < ong) {
            int orta = (chap + ong) / 2;
            if (a[orta] <= x) chap = orta + 1;      // ошибка: должно быть <
            else ong = orta;
        }
        return chap;
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        holat = in.nextLong();
        int testlar = in.nextInt();
        for (int t = 1; t <= testlar; t++) {
            int n = (int) (tasodifiy() % 8) + 1;
            int[] a = new int[n];
            for (int i = 0; i < n; i++) a[i] = (int) (tasodifiy() % 10);
            Arrays.sort(a);
            int x = (int) (tasodifiy() % 10);
            int kutilgan = ishonchli(a, x), olingan = tez(a, x);
            if (kutilgan != olingan) {
                System.out.println("Найдена ошибка: тест " + t);
                StringBuilder sb = new StringBuilder("a =");
                for (int v : a) sb.append(' ').append(v);
                System.out.println(sb);
                System.out.println("x = " + x);
                System.out.println("ожидалось " + kutilgan + ", получено " + olingan);
                return;
            }
        }
        System.out.println("Всё верно: " + testlar + " тестов");
    }
}
```
```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

long long holat;

long long tasodifiy() {
    holat = (holat * 1103515245LL + 12345) % 2147483648LL;     // линейный конгруэнтный генератор
    return holat;
}

int ishonchli(const vector<int>& a, int x) {        // медленно, но заведомо верно
    int soni = 0;
    for (int v : a) if (v < x) soni++;
    return soni;
}

int tez(const vector<int>& a, int x) {              // двоичный поиск — с ошибкой!
    int chap = 0, ong = a.size();
    while (chap < ong) {
        int orta = (chap + ong) / 2;
        if (a[orta] <= x) chap = orta + 1;          // ошибка: должно быть <
        else ong = orta;
    }
    return chap;
}

int main() {
    int testlar;
    cin >> holat >> testlar;
    for (int t = 1; t <= testlar; t++) {
        int n = tasodifiy() % 8 + 1;
        vector<int> a(n);
        for (int& v : a) v = tasodifiy() % 10;
        sort(a.begin(), a.end());
        int x = tasodifiy() % 10;
        int kutilgan = ishonchli(a, x), olingan = tez(a, x);
        if (kutilgan != olingan) {
            cout << "Найдена ошибка: тест " << t << endl;
            cout << "a =";
            for (int v : a) cout << ' ' << v;
            cout << endl << "x = " << x << endl;
            cout << "ожидалось " << kutilgan << ", получено " << olingan << endl;
            return 0;
        }
    }
    cout << "Всё верно: " << testlar << " тестов" << endl;
    return 0;
}
```

Для `1 100` выводится:

```text
Найдена ошибка: тест 5
a = 2 4 5 6 9 9
x = 4
ожидалось 1, получено 2
```

Теперь ошибку легко разобрать вручную: в массиве есть элемент, равный 4, и ошибочное решение посчитало и его «меньшим» — `<=` на самом деле вычисляет **верхнюю** границу (*holat* — состояние генератора, *ishonchli* — надёжное решение, *tez* — быстрое). После исправления на `<` стресс-тест сообщает `Всё верно`. Для `42 1` (один тест) ошибка не проявляется — программа, прошедшая тест из примера, ещё не верна: при `42 3` ошибка находится уже во 2-м тесте.

## Задание самостоятельной работы

Выберите **два** практических задания курса (например, пирамидальную сортировку и дерево Фенвика) и для них:

1. **Медленное решение** — напишите самый простой верный способ (например, готовый `sort` или сумму полным циклом).
2. **Стресс-тест** — сравните быстрое решение с медленным не менее чем на 1000 маленьких случайных тестов; запишите зерно генератора в отчёт.
3. **История ошибки** — опишите одну ошибку, найденную стресс-тестом (или внесённую намеренно): вход, ожидаемый и полученный результат, причину и исправление.
4. **Отчёт** — для каждого задания: идея алгоритма, сложность, таблица тестов, результат стресс-теста и вывод в 3–5 предложений.

:::warning
**Критерии оценки и частые ошибки**

- Медленное решение должно быть **независимым** от быстрого: та же идея, написанная дважды, повторит ту же ошибку.
- Пусть генератор создаёт маленькие входы: ошибочный тест из 10⁵ элементов вручную не разобрать.
- Случайные тесты без зерна не позволяют воссоздать ошибку — обязательно сохраняйте зерно.
- Написать в отчёте только «все тесты пройдены» недостаточно: укажите, какие тесты и сколько.
:::

:::tip
Подготовьте стресс-тест в самом начале работы над заданием: запустите его, как только напишете быстрое решение. Чем раньше найдена ошибка, тем легче её исправить.
:::

## Итоги

- Порядок работы: анализ → крайние случаи → медленное решение → быстрое решение → проверка → отчёт.
- Стресс-тест сравнивает быстрое решение с надёжным на тысячах маленьких случайных входов и находит пример, показывающий ошибку.
- Линейный конгруэнтный генератор с зерном воссоздаёт тесты одинаково всегда и на любом языке.
- Прохождение теста из примера не гарантирует верности программы.

Q: Каким должно быть «надёжное решение» в стресс-тесте?
A: Простым, заведомо верным и независимым от быстрого; скорость не важна.
Q: Почему генератор создаёт маленькие входы?
A: Чтобы найденную ошибку было легко разобрать вручную.
Q: Зачем случайным тестам зерно?
A: Чтобы в точности воссоздать ошибочный тест.
Q: Что вычисляет ошибочный двоичный поиск из образца?
A: Число элементов, меньших или равных *x*, — верхнюю границу.
