## Почему это важно

Когда вы подключаете компьютер к сети, за секунду происходит многое: он получает адрес от **DHCP**, находит MAC-адрес шлюза с помощью **ARP**, а пакеты идут по таблицам, построенным **протоколами маршрутизации**. Если что-то не так, **ICMP** сообщает: «адрес недостижим» или «время истекло». Не зная этих вспомогательных протоколов, невозможно найти неисправность сети.

:::note
**После этого занятия вы сможете:**

- различать статическую и динамическую маршрутизацию, дистанционно-векторные протоколы и протоколы состояния каналов;
- рассчитывать, как дистанционно-векторный алгоритм строит таблицы маршрутизации.
:::

## ARP — сопоставление адресов

Компьютер хочет отправить пакет на 192.168.1.1, но кадру Ethernet нужен **MAC-адрес**. Эту задачу решает **ARP** (Address Resolution Protocol):

1. Компьютер проверяет **кэш ARP** (`arp -a`). Если запись есть — сразу использует её.
2. Если нет — отправляет **широковещательный** запрос ARP: «У кого 192.168.1.1? Сообщите 192.168.1.10».
3. Владелец 192.168.1.1 отвечает **unicast**: «192.168.1.1 — это я, MAC: 00:1A:2B:3C:4D:5E».
4. Ответ записывается в кэш и хранится несколько минут.

Важно: если получатель **в другой сети**, компьютер запрашивает не его MAC, а MAC **основного шлюза** (маршрутизатора). **Gratuitous ARP** — устройство само объявляет свой адрес (для обнаружения конфликта IP). **ARP-спуфинг** — злоумышленник поддельными ответами выдаёт себя за шлюз и пропускает трафик через себя (man-in-the-middle); защита — Dynamic ARP Inspection на коммутаторе.

## ICMP — служебные сообщения

| Тип | Сообщение | Когда |
|---|---|---|
| 0 / 8 | Echo Reply / Echo Request | `ping` |
| 3 | Destination Unreachable | сеть, узел или порт не существует; нужна фрагментация, но стоит DF |
| 5 | Redirect | маршрутизатор указывает узлу лучший шлюз |
| 11 | Time Exceeded | TTL упал до 0 — этим пользуется `tracert` |

`ping` показывает, есть ли связь, и время кругового пути (RTT); `tracert` (в Linux `traceroute`) посылает пакеты с TTL = 1, 2, 3, … и находит каждый маршрутизатор на пути. В некоторых сетях ICMP закрыт межсетевым экраном — отсутствие ответа на `ping` не значит, что узел выключен.

## DHCP — автоматическое назначение адресов

Процесс **DHCP** (Dynamic Host Configuration Protocol, порты UDP: сервер 67, клиент 68) — **DORA**:

| Шаг | От кого → кому | Содержание |
|---|---|---|
| **D**iscover | клиент → широковещание | «Есть ли в сети сервер DHCP?» (у клиента ещё нет IP: источник 0.0.0.0) |
| **O**ffer | сервер → клиент | «Предлагаю 192.168.1.57, маску, шлюз, DNS, аренду на 24 часа» |
| **R**equest | клиент → широковещание | «Беру 192.168.1.57» (другие серверы тоже узнают) |
| **A**ck | сервер → клиент | «Подтверждаю» |

Адрес выдаётся в **аренду**; в середине срока аренды клиент продлевает её. Если сервер в другой подсети, **агент ретрансляции DHCP** на маршрутизаторе (`ip helper-address`) доставляет широковещательный запрос серверу. Командами `ipconfig /release` и `ipconfig /renew` процесс можно повторить вручную.

## Маршрутизация

Для каждого пакета маршрутизатор выбирает запись из **таблицы маршрутизации**: сеть/префикс → следующий шаг (next hop) или выходной интерфейс. Если подходят несколько записей, выбирается **самый длинный префикс** (программа такого выбора — задание практического занятия A8).

Как заполняется таблица:

- **Непосредственно подключённые** сети — сразу после назначения IP интерфейсу.
- **Статические** маршруты — администратор вводит вручную (`ip route 10.0.0.0 255.0.0.0 192.168.1.2`); для небольших сетей и маршрута по умолчанию `0.0.0.0/0`.
- **Динамические** — маршрутизаторы сообщают друг другу через протоколы маршрутизации, сами строят таблицу и при отказе находят новый путь.

Если к одной сети есть маршруты из разных источников, выбор идёт по **административному расстоянию** (уровню доверия; у Cisco: подключённые 0, статические 1, OSPF 110, RIP 120), а внутри одного протокола — по **метрике** (число переходов, стоимость канала).

## Протоколы маршрутизации

| Вид | Идея | Протокол | Метрика | Особенность |
|---|---|---|---|---|
| **Дистанционно-векторный** | каждый маршрутизатор отправляет соседям свою таблицу («какая сеть — какое расстояние») | **RIP** | число переходов (16 = недостижимо) | прост; медленно сходится, проблема «счёта до бесконечности» |
| **Состояния каналов** | каждый маршрутизатор получает карту всей сети и вычисляет кратчайшие пути алгоритмом Дейкстры | **OSPF**, IS-IS | стоимость канала (зависит от скорости) | быстро сходится, для крупных сетей; области (area) |
| **Векторный по пути** | вместе с маршрутом передаётся список автономных систем, через которые он проходит | **BGP** | политики, длина пути AS | межпровайдерский протокол Интернета |

**Автономная система** (AS) — группа сетей под управлением одной организации. Внутри AS — **внутренние** протоколы (IGP: RIP, OSPF, EIGRP), между AS — **внешний** протокол (EGP: BGP).

Способы смягчить проблемы RIP: **расщепление горизонта** (split horizon — не объявлять маршрут обратно соседу, от которого он пришёл), **poison reverse**, максимум 15 переходов и таймеры **hold-down**.

## Разобранный пример 1: дистанционно-векторный алгоритм

Даны *n* маршрутизаторов и *m* каналов (со стоимостью). В каждом раунде все маршрутизаторы одновременно берут векторы расстояний соседей из предыдущего раунда и обновляют свою таблицу: *d*(*i*, *j*) = min(*c*(*i*, *k*) + *d*(*k*, *j*)) по всем соседям *k*. Вначале каждый маршрутизатор знает только себя. Выведите, сколько раундов нужно, пока таблицы не перестанут меняться, затем таблицу маршрутизатора *s* (назначение, стоимость, следующий шаг; при равенстве — сосед с меньшим номером).

```python
CHEKSIZ = 10 ** 9
n, m = map(int, input().split())
qoshni = [dict() for _ in range(n + 1)]
for _ in range(m):
    u, v, c = map(int, input().split())
    qoshni[u][v] = c
    qoshni[v][u] = c
s = int(input())

d = [[CHEKSIZ] * (n + 1) for _ in range(n + 1)]
for i in range(1, n + 1):
    d[i][i] = 0
raund = 0
while True:
    yangi = [qator[:] for qator in d]
    for i in range(1, n + 1):
        for j in range(1, n + 1):
            for k, c in qoshni[i].items():             # старый вектор соседа
                if d[k][j] < CHEKSIZ and c + d[k][j] < yangi[i][j]:
                    yangi[i][j] = c + d[k][j]
    if yangi == d:
        break
    d = yangi
    raund += 1

print("раундов:", raund)
for j in range(1, n + 1):
    if j == s:
        continue
    keyingi = min(k for k, c in qoshni[s].items() if d[k][j] < CHEKSIZ and c + d[k][j] == d[s][j])
    print(j, d[s][j], keyingi)
```
```java
import java.util.Scanner;

public class Main {
    static final long CHEKSIZ = 1_000_000_000L;

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        int m = in.nextInt();
        long[][] narx = new long[n + 1][n + 1];                // 0 — канала нет
        for (int i = 0; i < m; i++) {
            int u = in.nextInt();
            int v = in.nextInt();
            long c = in.nextLong();
            narx[u][v] = c;
            narx[v][u] = c;
        }
        int s = in.nextInt();

        long[][] d = new long[n + 1][n + 1];
        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= n; j++) d[i][j] = i == j ? 0 : CHEKSIZ;
        }
        int raund = 0;
        while (true) {
            long[][] yangi = new long[n + 1][];
            for (int i = 0; i <= n; i++) yangi[i] = d[i].clone();
            boolean ozgardi = false;
            for (int i = 1; i <= n; i++) {
                for (int j = 1; j <= n; j++) {
                    for (int k = 1; k <= n; k++) {             // старый вектор соседа
                        if (narx[i][k] > 0 && d[k][j] < CHEKSIZ && narx[i][k] + d[k][j] < yangi[i][j]) {
                            yangi[i][j] = narx[i][k] + d[k][j];
                            ozgardi = true;
                        }
                    }
                }
            }
            if (!ozgardi) break;
            d = yangi;
            raund++;
        }

        System.out.println("раундов: " + raund);
        for (int j = 1; j <= n; j++) {
            if (j == s) continue;
            int keyingi = 0;
            for (int k = 1; k <= n && keyingi == 0; k++) {
                if (narx[s][k] > 0 && d[k][j] < CHEKSIZ && narx[s][k] + d[k][j] == d[s][j]) keyingi = k;
            }
            System.out.println(j + " " + d[s][j] + " " + keyingi);
        }
    }
}
```

Вывод:

У маршрутизатора 1 есть прямой канал к 4 (стоимость 5), но путь 1–2–3–4 дешевле (4) — алгоритм «обнаруживает» это во втором и третьем раундах. Самый длинный путь (из 1 в 5) состоит из 4 каналов, поэтому таблицы стабилизируются за 4 раунда: в дистанционно-векторных протоколах информация за раунд распространяется лишь на один переход.

## Разобранный пример 2: кэш ARP

В первой строке — время жизни записи кэша *T* (секунды) и число событий *k*. В следующих *k* строках — время (секунды, по возрастанию) и IP-адрес, на который компьютер хочет отправить пакет. Если запись есть в кэше и её возраст меньше *T* — `кэш`, иначе отправляется запрос ARP (`ARP`) и запись обновляется. В конце выведите число отправленных запросов ARP.

```python
t_yashash, k = map(int, input().split())
kesh = {}                                     # IP -> время записи
soni = 0
for _ in range(k):
    vaqt, ip = input().split()
    vaqt = int(vaqt)
    if ip in kesh and vaqt - kesh[ip] < t_yashash:
        print(vaqt, ip, "кэш")
    else:
        print(vaqt, ip, "ARP")               # широковещательный запрос и ответ
        kesh[ip] = vaqt
        soni += 1
print("запросов ARP:", soni)
```
```java
import java.util.HashMap;
import java.util.Map;
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int tYashash = in.nextInt();
        int k = in.nextInt();
        Map<String, Integer> kesh = new HashMap<>();          // IP -> время записи
        int soni = 0;
        for (int i = 0; i < k; i++) {
            int vaqt = in.nextInt();
            String ip = in.next();
            if (kesh.containsKey(ip) && vaqt - kesh.get(ip) < tYashash) {
                System.out.println(vaqt + " " + ip + " кэш");
            } else {
                System.out.println(vaqt + " " + ip + " ARP");  // широковещательный запрос и ответ
                kesh.put(ip, vaqt);
                soni++;
            }
        }
        System.out.println("запросов ARP: " + soni);
    }
}
```
```cpp
#include <iostream>
#include <map>
#include <string>
using namespace std;

int main() {
    int tYashash, k;
    cin >> tYashash >> k;
    map<string, int> kesh;                                    // IP -> время записи
    int soni = 0;
    for (int i = 0; i < k; i++) {
        int vaqt;
        string ip;
        cin >> vaqt >> ip;
        if (kesh.count(ip) && vaqt - kesh[ip] < tYashash) {
            cout << vaqt << " " << ip << " кэш" << endl;
        } else {
            cout << vaqt << " " << ip << " ARP" << endl;      // широковещательный запрос и ответ
            kesh[ip] = vaqt;
            soni++;
        }
    }
    cout << "запросов ARP: " << soni << endl;
    return 0;
}
```

:::warning
**Частые ошибки**

- **Думать, что ARP запрашивает MAC-адрес компьютера из другой сети.** Запрашивается MAC-адрес основного шлюза.
- **Делать вывод, что узел выключен, раз `ping` не проходит.** ICMP может быть закрыт межсетевым экраном.
- **Считать шаг Request в DHCP одноадресным.** Клиент рассылает Request тоже широковещательно — чтобы другие серверы отозвали свои предложения.
- **Думать, что метрика RIP — скорость канала.** RIP считает только переходы: медленный путь из 2 переходов для него «лучше» быстрого из 3.
- **Путать административное расстояние и метрику.** Административное расстояние сравнивает разные источники, метрика — пути внутри одного протокола.
:::

:::tip
Посмотрите кэш ARP командой `arp -a`, очистите его командой `arp -d *` (с правами администратора) и посмотрите снова после `ping`. В Wireshark с фильтром `arp or dhcp` найдите четыре шага DORA во время `ipconfig /release` и `ipconfig /renew`.
:::

## Итоги

- ARP находит MAC-адрес по IP-адресу широковещательным запросом и одноадресным ответом; результат хранится в кэше.
- ICMP — служебные сообщения: Echo (ping), Destination Unreachable, Time Exceeded (tracert).
- DHCP — DORA: Discover, Offer, Request, Ack; адрес выдаётся в аренду, для другой сети нужен агент ретрансляции.
- Таблица маршрутизации состоит из подключённых, статических и динамических записей; выбор — по самому длинному префиксу, административному расстоянию, метрике.
- Протоколы: дистанционно-векторный (RIP), состояния каналов (OSPF), векторный по пути (BGP); внутри AS — IGP, между AS — BGP.

## Проверьте себя

:::check
Q: На какой адрес отправляются запрос ARP и ответ ARP?
A: Запрос — широковещательно (FF:FF:FF:FF:FF:FF), ответ — одноадресно запросившему.
Q: Каким сообщением ICMP пользуется `tracert`?
A: Time Exceeded (тип 11) — сообщением, которое маршрутизаторы отправляют при истечении TTL.
Q: Что означает сокращение DORA?
A: Discover, Offer, Request, Acknowledge — шаги получения адреса через DHCP.
Q: Почему OSPF сходится быстрее RIP?
A: Каждый маршрутизатор получает карту всей сети и сам вычисляет кратчайшие пути; в RIP информация за одно обновление распространяется лишь на один переход.
Q: Что означает метрика 16 в RIP?
A: Сеть недостижима (бесконечность).
:::
