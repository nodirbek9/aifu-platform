## Почему это важно

Дома создать отдельного пользователя на каждом из трёх-четырёх компьютеров — не проблема. Но в университете с 1000 компьютеров и 5000 студентов нельзя заводить отдельную учётную запись на каждой машине: студент должен входить в любой класс со своим логином и паролем, а администратор — управлять политикой паролей, принтерами и программами из одного места. Это обеспечивают **серверные операционные системы** и модель **домена**.

## Серверные операционные системы

| | ОС рабочей станции (Windows 11, Ubuntu Desktop) | Серверная ОС (Windows Server, Ubuntu Server, RHEL) |
|---|---|---|
| Назначение | работа одного пользователя | обслуживание многих клиентов |
| Одновременные подключения | ограничены (например, 20 подключений к общей папке) | тысячи |
| Графический интерфейс | основной | необязателен (Server Core, только командная строка) |
| Оборудование | 1 процессор, обычная память | много процессоров, большой объём RAM, RAID, память ECC |
| Надёжность | перезагрузки — норма | непрерывная работа, кластеризация, резервные копии |
| Лицензия | дешёвая | по ядрам или числу клиентов (CAL) |

Редакции **Windows Server** (2016, 2019, 2022, 2025): **Standard** (до 2 виртуальных машин), **Datacenter** (неограниченная виртуализация). Варианты установки: **Desktop Experience** (графический) и **Server Core** (без графики, меньше ресурсов и меньше поверхность атаки). Управление — **Server Manager**, **PowerShell**, **Windows Admin Center**.

**Серверы Linux**: Ubuntu Server, Debian, Red Hat Enterprise Linux (RHEL), Rocky/AlmaLinux. Большая часть веб-серверов Интернета работает на Linux. Управление — SSH и командная строка.

## Роли сервера

| Роль | Назначение | Windows | Linux |
|---|---|---|---|
| Служба каталогов | база пользователей и компьютеров, вход | Active Directory Domain Services | Samba AD, FreeIPA, OpenLDAP |
| DHCP | автоматическое назначение адресов | DHCP Server | isc-dhcp, Kea |
| DNS | разрешение имён | DNS Server | BIND, Unbound |
| Файловый сервер | общие папки | File and Storage Services (SMB) | Samba, NFS |
| Сервер печати | общие принтеры | Print Services | CUPS |
| Веб-сервер | сайты и приложения | IIS | Nginx, Apache |
| Виртуализация | виртуальные машины | Hyper-V | KVM |
| Удалённый доступ | VPN, удалённый рабочий стол | RRAS, RDS | OpenVPN, WireGuard |

На одном физическом сервере можно запустить много ролей, но хорошая практика — держать каждую важную роль на отдельном (часто виртуальном) сервере.

## Рабочая группа и домен

| | **Рабочая группа** (workgroup) | **Домен** (domain) |
|---|---|---|
| Модель | одноранговая (peer-to-peer) | клиент–сервер |
| Учётные записи | отдельно на каждом компьютере (локальные) | в центральной базе (на контроллере домена) |
| Вход | только на этот компьютер | на любой компьютер домена с одним логином |
| Управление | вручную на каждом компьютере | централизованно, групповыми политиками |
| Размер | до ~10–20 компьютеров | сотни и тысячи |
| Сервер | не нужен | минимум один контроллер домена (лучше два) |
| Стоимость | бесплатно | серверы и лицензии |

Рабочая группа — для дома и маленького офиса: просто, но смена пароля на 10 компьютерах выполняется 10 раз. Домен — для организаций: централизованная безопасность и управление.

## Active Directory

**Active Directory** (AD) — служба каталогов Microsoft: иерархическая база всех объектов сети (пользователей, групп, компьютеров, принтеров).

- **Домен** — группа объектов с общей базой и политикой безопасности, с DNS-именем: `aifu.local`.
- **Контроллер домена** (DC) — сервер, хранящий базу AD и аутентифицирующий пользователей. Несколько DC **реплицируются** друг с другом — если один откажет, работает другой.
- **OU** (Organizational Unit) — «папки» внутри домена: `Студенты`, `Преподаватели`, `Компьютерные классы`. К ним привязываются политики и делегируются права управления.
- **Групповые политики** (GPO) — централизованно применяемые настройки: длина пароля, блокировка экрана, установка программ, подключение принтеров, запрет USB.
- **Дерево** (tree) и **лес** (forest) — домены, связанные отношениями доверия: `aifu.local`, `talaba.aifu.local`.
- Протокол аутентификации — **Kerberos** (билеты), доступ к каталогу — **LDAP** (порт 389). AD сильно зависит от DNS: клиенты находят DC по записям SRV в DNS.

Ввод компьютера в домен: свойства системы → «Домен» → `aifu.local` → логин и пароль администратора домена → перезагрузка. После этого на компьютер можно войти под учётной записью `AIFU\talaba01`.

## На практике: сеть университета

| Элемент | Решение |
|---|---|
| Учётные записи студентов и преподавателей | OU `Студенты`, `Преподаватели` в AD |
| Политика паролей | GPO домена: не менее 10 символов, смена каждые 90 дней |
| Компьютерные классы | OU `Лаборатории`, GPO для установки программ и ограничения USB |
| Файлы | файловый сервер, общая папка для каждой группы, права через группы |
| Адреса и имена | серверы DHCP и DNS (настраиваются в A11) |

:::warning
**Частые ошибки**

- **Думать, что домен и рабочая группа — одно и то же.** В рабочей группе нет центральной базы — каждый компьютер хранит свои учётные записи сам.
- **Работать с одним контроллером домена.** Если он откажет, никто не сможет войти; рекомендуется минимум два DC.
- **Указывать клиентам внешний DNS (8.8.8.8).** Компьютеры домена не смогут найти DC; клиентам нужно давать внутренний DNS-сервер.
- **Назначать права каждому пользователю отдельно.** Права назначаются группам, а пользователи добавляются в группы.
- **Выполнять повседневную работу на сервере под администратором.** Учётная запись администратора — только для управления.
:::

:::tip
В Windows определите, в рабочей группе или в домене ваш компьютер, командой `systeminfo | findstr /B "Domain"` (или в свойствах системы). На университетском компьютере выполните `whoami` и `echo %USERDOMAIN%`, чтобы увидеть имя домена.
:::

## Итоги

- Серверная ОС предназначена для непрерывного обслуживания многих клиентов; распространены Windows Server (Desktop Experience и Server Core) и серверы Linux.
- Основные роли: служба каталогов, DHCP, DNS, файлы и печать, веб, виртуализация, удалённый доступ.
- Рабочая группа — небольшая одноранговая сеть с локальными учётными записями; домен — центральные учётные записи и управление.
- Active Directory: домен, контроллеры домена и репликация, OU, GPO, дерево и лес; опирается на Kerberos, LDAP и DNS.

## Проверьте себя

:::check
Q: В чём преимущество варианта установки Server Core?
A: Нет графического интерфейса — меньше расход ресурсов, меньше обновлений и меньше поверхность атаки.
Q: Где хранятся учётные записи пользователей в рабочей группе?
A: На каждом компьютере (локальные учётные записи).
Q: Какую функцию выполняет контроллер домена?
A: Хранит базу Active Directory и аутентифицирует пользователей домена.
Q: Чем OU отличается от группы?
A: OU — контейнер для упорядочивания объектов и применения политик; группа — набор пользователей для назначения прав.
Q: Почему компьютеры домена должны использовать внутренний DNS-сервер?
A: Они находят контроллер домена по записям SRV в DNS; во внешнем DNS таких записей нет.
