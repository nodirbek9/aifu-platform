## Почему это важно

Сервер — «сердце» организации: на нём работают база пользователей, файлы, DHCP и DNS. Неправильно начатый сервер (случайное имя, адрес от DHCP, необновлённая система) потом доставляет много проблем. На этом занятии установим Windows Server на виртуальную машину и подготовим его к ролям следующих занятий (A11 — DHCP и DNS, A12 — пользователи, A13 — общие ресурсы).

:::note
**После этого занятия вы сможете:**

- подготовить виртуальную машину для Windows Server;
- выбрать подходящие редакцию и тип установки и установить систему;
- задать серверу осмысленное имя, статический IP-адрес и DNS;
- выполнять основную настройку через Server Manager и PowerShell;
- знать порядок добавления роли на сервер.
:::

## Подготовка

| Параметр | Минимум (Windows Server 2022) | Рекомендуется для лаборатории |
|---|---|---|
| Процессор | 1,4 ГГц, 64 бит | 2 виртуальных ядра |
| Память | 512 МБ (Server Core), 2 ГБ (Desktop Experience) | 4 ГБ |
| Диск | 32 ГБ | 60 ГБ |
| Сеть | 1 адаптер | внутренняя сеть или «Host-only» |

Используется **виртуальная машина** (Hyper-V, VirtualBox или VMware): реальному компьютеру ничто не угрожает, состояние можно сохранить **снимком** (snapshot) и вернуться после ошибки. Образ установки (ISO) — пробная версия на 180 дней из Microsoft Evaluation Center.

Режим сети: **NAT** — ВМ выходит в Интернет, но снаружи не видна; **Внутренняя/Host-only** — видят друг друга только ВМ и хост (безопасно для проверки DHCP-сервера — второй DHCP не попадёт в сеть университета); **Мост** (Bridge) — ВМ как отдельный компьютер в реальной сети.

## Этапы установки

1. Загрузите ВМ с ISO, выберите язык и клавиатуру, **Install now**.
2. Выберите редакцию: **Windows Server 2022 Standard (Desktop Experience)** — с графическим интерфейсом. Server Core — только командная строка.
3. Примите условия лицензии, выберите **Custom: Install Windows only**.
4. Диск: выберите незанятое место (системные разделы установщик создаст сам).
5. После установки и перезагрузок запрашивается пароль **Administrator** — задайте сложный (заглавные и строчные буквы, цифры, символы, не менее 8 знаков).
6. Вход: в ВМ вместо **Ctrl+Alt+Del** используйте соответствующую кнопку меню гипервизора (VirtualBox: Host+Del).

## Начальная настройка

После входа открывается **Server Manager** → **Local Server**. Настройте пункты по очереди:

| Пункт | Что сделать | Зачем |
|---|---|---|
| **Computer name** | осмысленное имя вроде `SRV-DC01`, затем перезагрузка | менять случайное имя `WIN-8F3K…` после установки ролей проблематично |
| **Ethernet** (IP) | статический: `192.168.50.10/24`, шлюз `192.168.50.1`, DNS `127.0.0.1` (если потом будет DNS-сервером) или внутренний DNS | клиенты находят сервер по постоянному адресу |
| **Time zone** | (UTC+05:00) Ташкент | от времени зависят Kerberos и журналы |
| **Windows Update** | установить все обновления | закрыть известные уязвимости |
| **Remote Desktop** | при необходимости включить, только для администраторов | удалённое управление |
| **IE Enhanced Security** | не пользуйтесь браузером на сервере | сервер — не рабочий стол |

Те же настройки в **PowerShell** (от имени администратора):

```text
Rename-Computer -NewName "SRV-DC01" -Restart
Get-NetAdapter
New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress 192.168.50.10 -PrefixLength 24 -DefaultGateway 192.168.50.1
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses 192.168.50.10
Set-TimeZone -Id "West Asia Standard Time"
Get-ComputerInfo | Select-Object CsName, WindowsProductName, OsVersion
```

В Server Core то же делается через меню `sconfig`: 2 — имя, 8 — сеть, 6 — обновления, 7 — Remote Desktop.

## Добавление ролей

Server Manager → **Manage → Add Roles and Features**:

1. **Role-based or feature-based installation**.
2. Выберите сервер (из пула).
3. Отметьте роли — например, **DHCP Server**, **DNS Server** (в A11), **File and Storage Services** (в A13). Нужные дополнительные компоненты предлагаются автоматически.
4. **Install**. После установки некоторые роли показывают жёлтый флажок «post-deployment configuration» — требуется дальнейшая настройка.

В PowerShell: `Install-WindowsFeature -Name DHCP, DNS -IncludeManagementTools`. Посмотреть установленное: `Get-WindowsFeature | Where-Object Installed`.

## Контрольный список

- [ ] Имя компьютера осмысленное, перезагрузка выполнена.
- [ ] Статический IP, маска, шлюз и DNS правильные (`ipconfig /all`).
- [ ] Часовой пояс и время правильные.
- [ ] Обновления установлены.
- [ ] Пароль администратора сложный и никому не раскрыт.
- [ ] Состояние ВМ сохранено снимком («Чистая установка»).

:::warning
**Частые ошибки**

- **Оставлять серверу адрес от DHCP.** Если адрес сменится, клиенты потеряют сервер; адрес сервера всегда статический.
- **Менять имя после установки ролей.** Особенно на контроллере домена это серьёзная проблема; имя задаётся в первую очередь.
- **Подключать тестовый DHCP-сервер к сети университета (Bridge).** Посторонний DHCP раздаст неправильные адреса всем компьютерам сети; в лаборатории используйте внутреннюю сеть.
- **Работать повседневно под Administrator и скачивать программы из Интернета на сервер.** Сервер — только для служб.
- **Делать крупное изменение без снимка.** После ошибки не будет пути назад.
:::

:::tip
Установите второй ВМ клиент Windows 10/11 и подключите его к той же внутренней сети. Назначьте клиенту адрес `192.168.50.20/24` и выполните `ping` сервера. Если ответа нет — причина обычно в том, что брандмауэр Windows закрыл ICMP; проверьте командой `Get-NetFirewallRule -DisplayName "*Echo*"`.
:::

## Итоги

- В лаборатории Windows Server устанавливается на виртуальную машину, во внутренней сети, со снимками.
- Редакция (Standard/Datacenter) и тип установки (Desktop Experience/Server Core) выбираются заранее.
- Начальная настройка: имя → статический IP и DNS → часовой пояс → обновления → удалённое управление.
- Роли добавляются через **Add Roles and Features** в Server Manager или командой `Install-WindowsFeature`.

## Проверьте себя

:::check
Q: Почему серверу назначают статический IP-адрес?
A: Клиенты должны находить его по постоянному адресу; адрес от DHCP может измениться.
Q: Чем в основном Server Core отличается от Desktop Experience?
A: Нет графического интерфейса — управление через командную строку, `sconfig` и PowerShell; меньше ресурсов и уязвимостей.
Q: Какой режим сети ВМ безопасен для тестового DHCP-сервера?
A: Внутренняя (Internal) или Host-only — сообщения DHCP не выходят в реальную сеть.
Q: Где в Server Manager меню добавления ролей?
A: Manage → Add Roles and Features.
Q: Как сменить имя компьютера в PowerShell?
A: `Rename-Computer -NewName "SRV-DC01" -Restart`.
:::
