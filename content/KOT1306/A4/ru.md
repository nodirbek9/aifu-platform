## Почему это важно

По кабелю передаются не «1» и «0», а изменения напряжения. Чтобы приёмник превратил их обратно в биты, обе стороны должны использовать один **код**. Но простой способ «1 — высокий, 0 — низкий» на длинных сериях нулей сбивает часы приёмника: 50 нулей можно прочитать как 49 или 51. На этом практическом занятии изучим основные линейные коды по временным диаграммам, а затем смоделируем программами **логическое кодирование** (4B/5B) и **битстаффинг**, которые решают эти проблемы.

:::note
**После этого занятия вы сможете:**

- объяснять требования к хорошему линейному коду (синхронизация, отсутствие постоянной составляющей, узкая полоса);
- рисовать временные диаграммы кодов NRZ, NRZI, Manchester, дифференциального Manchester, AMI и MLT-3;
- показывать, как кодирование 4B/5B устраняет длинные серии нулей;
- применять битстаффинг, чтобы флаг кадра не встречался внутри данных.
:::

## Требования к хорошему коду

| Требование | Смысл |
|---|---|
| **Самосинхронизация** | в сигнале должно быть достаточно переходов — по ним приёмник подстраивает часы |
| **Отсутствие постоянной составляющей** (DC balance) | высокий и низкий уровни в среднем должны быть равны — трансформаторы не пропускают постоянный ток |
| **Узкий спектр** | чем меньше изменений сигнала в секунду, тем ниже требования к кабелю |
| **Обнаружение ошибок** | в некоторых кодах запрещённые комбинации указывают на ошибку |
| **Простота и дешевизна** | кодер и декодер должны быть простыми |

## Основные линейные коды

Ниже — уровни для последовательности `10110001` (`+` — высокий, `-` — низкий, `0` — нулевой уровень). В манчестерском коде каждый бит состоит из двух полупериодов.

| Код | Правило | `1 0 1 1 0 0 0 1` |
|---|---|---|
| **NRZ-L** | 1 → `+`, 0 → `-` | `+ - + + - - - +` |
| **NRZI** | 1 → уровень меняется, 0 → сохраняется (начальный `-`) | `+ + - + + + + -` |
| **Manchester** (IEEE 802.3) | 0 → `+-`, 1 → `-+` (в середине бита всегда переход) | `-+ +- -+ -+ +- +- +- -+` |
| **AMI** | 0 → `0`, 1 → поочерёдно `+` и `-` | `+ 0 - + 0 0 0 -` |
| **MLT-3** | 0 → сохраняется, 1 → следующий уровень в цикле `0 → + → 0 → -` (начальный `0`) | `+ + 0 - - - - 0` |

| Код | Синхронизация | Баланс DC | Где применяется |
|---|---|---|---|
| NRZ-L | теряется на длинных сериях 0 и 1 | нет | RS-232, внутренние шины |
| NRZI | теряется на длинных сериях 0 (с единицами проблем нет) | нет | USB, 100BASE-FX (с 4B/5B) |
| Manchester | переход в каждом бите — **идеальна** | есть | 10BASE-T Ethernet |
| Дифференциальный Manchester | переход в каждом бите; 0 — дополнительный переход в начале бита | есть | Token Ring |
| AMI | теряется на длинных сериях 0 | есть | линии T1/E1 |
| MLT-3 | теряется на длинных сериях 0 | частично | 100BASE-TX (с 4B/5B) |

Цена манчестерского кода — частота изменений сигнала **вдвое** выше, чем у NRZ. Поэтому его использовал Ethernet 10 Мбит/с, а более быстрые стандарты пошли другим путём: NRZI или MLT-3 + **логическое кодирование**.

Реализация кодов NRZ, NRZI и Manchester в программе — **самостоятельное задание** этого занятия (KOT-A4 ниже).

## Логическое кодирование: 4B/5B

NRZI даёт переход на единицах, но молчит на длинных сериях нулей. **4B/5B** заменяет каждые 4 бита 5-битным кодовым словом; кодовые слова подобраны так, что в потоке **не бывает больше трёх нулей подряд** (в начале каждого слова не более одного нуля, в конце — не более двух). Цена — 25% лишних битов: для 100 Мбит/с данных нужна линия 125 Мбод.

| 4 бита | 5 битов | 4 бита | 5 битов |
|---|---|---|---|
| 0000 | 11110 | 1000 | 10010 |
| 0001 | 01001 | 1001 | 10011 |
| 0010 | 10100 | 1010 | 10110 |
| 0011 | 10101 | 1011 | 10111 |
| 0100 | 01010 | 1100 | 11010 |
| 0101 | 01011 | 1101 | 11011 |
| 0110 | 01110 | 1110 | 11100 |
| 0111 | 01111 | 1111 | 11101 |

Часть оставшихся 16 пятибитных комбинаций — управляющие символы (например, `11111` — IDLE, начало и конец кадра), остальные запрещены — их появление означает ошибку. В Gigabit Ethernet та же идея применяется в виде **8B/10B** (25% избыточности), в 10G — **64B/66B** (всего 3%). Другой подход — **скремблирование**: биты складываются по XOR с псевдослучайной последовательностью, и вероятность длинных одинаковых серий резко падает.

## Битстаффинг (bit stuffing)

В протоколах вроде HDLC и PPP начало и конец кадра отмечаются **флагом** `01111110`. Если шесть единиц подряд встретятся и внутри данных, приёмник примет их за флаг. Решение: отправитель **после пяти единиц подряд** всегда вставляет один `0`; приёмник удаляет `0`, идущий после пяти единиц. В итоге шесть единиц в данных никогда не встречаются.

## Разобранный пример 1: кодирование 4B/5B

В строке даны шестнадцатеричные цифры (каждая — 4 бита). В первой строке выведите 4-битные группы, во второй — кодовые слова 4B/5B, в третьей сравните самую длинную серию нулей до и после кодирования.

```python
JADVAL = ["11110", "01001", "10100", "10101", "01010", "01011", "01110", "01111",
          "10010", "10011", "10110", "10111", "11010", "11011", "11100", "11101"]


def eng_uzun_nollar(bitlar):
    eng, joriy = 0, 0
    for b in bitlar:
        joriy = joriy + 1 if b == "0" else 0
        eng = max(eng, joriy)
    return eng


satr = input().strip()
tort = [format(int(r, 16), "04b") for r in satr]
besh = [JADVAL[int(r, 16)] for r in satr]          # каждые 4 бита -> 5-битное слово
print(" ".join(tort))
print(" ".join(besh))
print("самая длинная серия нулей:", eng_uzun_nollar("".join(tort)), "->", eng_uzun_nollar("".join(besh)))
```
```java
import java.util.ArrayList;
import java.util.List;
import java.util.Scanner;

public class Main {
    static final String[] JADVAL = {"11110", "01001", "10100", "10101", "01010", "01011", "01110", "01111",
            "10010", "10011", "10110", "10111", "11010", "11011", "11100", "11101"};

    static int engUzunNollar(String bitlar) {
        int eng = 0, joriy = 0;
        for (char b : bitlar.toCharArray()) {
            joriy = b == '0' ? joriy + 1 : 0;
            eng = Math.max(eng, joriy);
        }
        return eng;
    }

    public static void main(String[] args) {
        String satr = new Scanner(System.in).nextLine().trim();
        List<String> tort = new ArrayList<>();
        List<String> besh = new ArrayList<>();
        for (char r : satr.toCharArray()) {
            int qiymat = Character.digit(r, 16);
            tort.add(String.format("%4s", Integer.toBinaryString(qiymat)).replace(' ', '0'));
            besh.add(JADVAL[qiymat]);                        // каждые 4 бита -> 5-битное слово
        }
        System.out.println(String.join(" ", tort));
        System.out.println(String.join(" ", besh));
        System.out.println("самая длинная серия нулей: " + engUzunNollar(String.join("", tort)) + " -> " + engUzunNollar(String.join("", besh)));
    }
}
```
```cpp
#include <algorithm>
#include <bitset>
#include <iostream>
#include <string>
using namespace std;

const string JADVAL[] = {"11110", "01001", "10100", "10101", "01010", "01011", "01110", "01111",
                         "10010", "10011", "10110", "10111", "11010", "11011", "11100", "11101"};

int engUzunNollar(const string& bitlar) {
    int eng = 0, joriy = 0;
    for (char b : bitlar) {
        joriy = b == '0' ? joriy + 1 : 0;
        eng = max(eng, joriy);
    }
    return eng;
}

int main() {
    string satr;
    cin >> satr;
    string tort, besh, tortQator, beshQator;
    for (char r : satr) {
        int qiymat = stoi(string(1, r), nullptr, 16);
        string t = bitset<4>(qiymat).to_string();
        tort += t;
        besh += JADVAL[qiymat];                              // каждые 4 бита -> 5-битное слово
        tortQator += (tortQator.empty() ? "" : " ") + t;
        beshQator += (beshQator.empty() ? "" : " ") + JADVAL[qiymat];
    }
    cout << tortQator << endl;
    cout << beshQator << endl;
    cout << "самая длинная серия нулей: " << engUzunNollar(tort) << " -> " << engUzunNollar(besh) << endl;
    return 0;
}
```

Ввод:

```text
00
```

Вывод:

```text
0000 0000
11110 11110
самая длинная серия нулей: 8 -> 1
```

Восемь нулей в NRZI были бы восемью периодами «тишины»; после 4B/5B в потоке подряд идёт не более одного нуля. Для `0F1` результат `0000 1111 0001` → `11110 11101 01001`, нули 4 → 2.

## Разобранный пример 2: битстаффинг

В каждой строке — последовательность битов. Для каждой выведите последовательность после битстаффинга и число вставленных нулей. Ввод читается до конца файла.

```python
import sys


def bit_qosh(bitlar):
    natija = []
    birlar = 0
    qoshildi = 0
    for b in bitlar:
        natija.append(b)
        if b == "1":
            birlar += 1
            if birlar == 5:                 # после пяти единиц вставляется 0
                natija.append("0")
                birlar = 0
                qoshildi += 1
        else:
            birlar = 0
    return "".join(natija), qoshildi


for satr in sys.stdin:
    satr = satr.strip()
    if satr:
        yangi, soni = bit_qosh(satr)
        print(satr + " -> " + yangi + " (+" + str(soni) + ")")
```
```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        while (in.hasNextLine()) {
            String satr = in.nextLine().trim();
            if (satr.isEmpty()) continue;
            StringBuilder natija = new StringBuilder();
            int birlar = 0;
            int qoshildi = 0;
            for (char b : satr.toCharArray()) {
                natija.append(b);
                if (b == '1') {
                    birlar++;
                    if (birlar == 5) {                  // после пяти единиц вставляется 0
                        natija.append('0');
                        birlar = 0;
                        qoshildi++;
                    }
                } else {
                    birlar = 0;
                }
            }
            System.out.println(satr + " -> " + natija + " (+" + qoshildi + ")");
        }
    }
}
```
```cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    string satr;
    while (cin >> satr) {
        string natija;
        int birlar = 0;
        int qoshildi = 0;
        for (char b : satr) {
            natija += b;
            if (b == '1') {
                birlar++;
                if (birlar == 5) {                      // после пяти единиц вставляется 0
                    natija += '0';
                    birlar = 0;
                    qoshildi++;
                }
            } else {
                birlar = 0;
            }
        }
        cout << satr << " -> " << natija << " (+" << qoshildi << ")" << endl;
    }
    return 0;
}
```

Ввод:

```text
01111110
1111111111
0101
```

Вывод:

```text
01111110 -> 011111010 (+1)
1111111111 -> 111110111110 (+2)
0101 -> 0101 (+0)
```

Первая строка — случай, когда внутри данных встретился сам флаг: после битстаффинга это уже не `01111110`, и приёмник не примет его за границу кадра. Приёмник выполняет обратное: отбрасывает `0`, идущий после пяти единиц.

:::warning
**Частые ошибки**

- **Читать уровень в NRZI как значение бита.** В NRZI данные — это **изменение** уровня: есть переход — 1, нет — 0.
- **Путать соглашения Manchester.** В IEEE 802.3 0 — сверху вниз, 1 — снизу вверх; в соглашении Г. Э. Томаса наоборот. Проверяйте, какое используется в задании.
- **Считать 4B/5B шифрованием.** Это замена по открытой таблице — её цель синхронизация, а не секретность.
- **Не обнулять счётчик единиц при битстаффинге.** После вставленного 0 счёт начинается заново; иначе на следующей единице снова вставится 0.
:::

Перед самостоятельным заданием нарисуйте в тетради диаграммы NRZ-L, NRZI и Manchester для `10110001` и сравните с таблицей выше. Если диаграмма верна, написать программу намного проще.

## Итоги

- Хороший линейный код самосинхронизируется, не имеет постоянной составляющей и работает в узкой полосе.
- NRZ прост, но теряет синхронизацию на длинных сериях; Manchester даёт переход в каждом бите, но требует вдвое более широкой полосы.
- 4B/5B (а также 8B/10B, 64B/66B) устраняет длинные серии нулей и работает вместе с NRZI или MLT-3.
- Битстаффинг вставляет 0 после пяти единиц, чтобы флаг `01111110` не встречался внутри данных.

Q: Почему NRZ-L может приводить к ошибкам на длинной серии нулей?
A: Сигнал не меняется, и нет переходов для подстройки часов приёмника — он может неверно подсчитать число битов.
Q: Каковы главное преимущество и недостаток манчестерского кода?
A: Переход в середине каждого бита даёт идеальную синхронизацию; но частота сигнала вдвое выше — нужна более широкая полоса.
Q: Каким кодовым словом заменяется `1010` в 4B/5B?
A: `10110`.
Q: Какая скорость линии нужна для передачи 100 Мбит/с данных с 4B/5B?
A: 125 Мбод (5 битов на каждые 4).
Q: Каков результат битстаффинга последовательности `0111110`?
A: `01111100` — после пяти единиц вставляется 0, затем идёт исходный последний 0.
