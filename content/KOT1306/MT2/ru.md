## Почему это важно

Работа сетевого инженера — не только подключение кабелей: это составление проекта, планирование адресов, проверка результата и **документирование**. Хорошо задокументированную сеть быстро поймёт и другой инженер; в сети без документации каждая неисправность превращается в «детективное расследование». Самостоятельные работы развивают именно эти навыки и составляют важную часть итоговой оценки.

:::note
**После этой самостоятельной работы вы сможете:**

- выбрать вид самостоятельной работы и выполнить её по требованиям;
- подготовить небольшой сетевой проект со схемой, адресным планом и проверками;
- знать критерии оценивания и проверять свою работу перед сдачей;
- находить ошибки в инвентаризации сети с помощью программы.
:::

## Виды самостоятельной работы

| Вид | Объём | Результат |
|---|---|---|
| **Реферат** | 8–12 страниц | аналитический текст по теме, не менее 5 источников, вывод |
| **Проект в Packet Tracer** | 1 файл `.pkt` + отчёт на 3–5 страниц | работающая сеть и её документация |
| **Лабораторный отчёт** | 2–4 страницы | шаги практического занятия, скриншоты, вывод |
| **Программное задание** | программа на Python, Java или C++ | решение, прошедшее автоматические тесты платформы |

### Темы рефератов (примеры)

1. Переход на IPv6: причины, механизмы (dual stack, туннели) и ситуация в Узбекистане.
2. Сравнение технологий 5G и Wi-Fi 7.
3. SDN (программно-определяемые сети) и OpenFlow.
4. DDoS-атаки и методы защиты от них.
5. Сетевая архитектура центров обработки данных (spine-leaf).
6. Технологии VPN: сравнение IPsec, WireGuard и OpenVPN.
7. Сетевые протоколы Интернета вещей (IoT): MQTT, CoAP, Zigbee.
8. Безопасность DNS: DNSSEC, DoH, DoT.

## Проект в Packet Tracer

**Образец задания**: трёхэтажный корпус факультета — на каждом этаже компьютерный класс (24 ПК), преподавательская (8 ПК), общий Wi-Fi; серверная (DHCP, DNS, веб-сервер); выход в Интернет.

Этапы выполнения:

1. **Анализ требований** — число устройств, службы, требования безопасности.
2. **Логическая схема** — топология (звезда или дерево), устройства и соединения.
3. **Адресный план** — подсети с VLSM, шлюзы, статические адреса серверов.
4. **Настройка** — маршрутизаторы, коммутаторы, DHCP, DNS, статические маршруты.
5. **Проверка** — `ping` и `tracert` из каждой подсети до серверов и Интернета, открытие веб-страницы.
6. **Документирование** — отчёт по шаблону ниже.

**Шаблон отчёта**:

```text
1. Задание и требования
2. Схема сети (рисунок)
3. Адресный план: подсеть | префикс | шлюз | диапазон DHCP | назначение
4. Перечень устройств: имя | модель | интерфейсы и адреса
5. Основные настройки (команды маршрутизаторов и коммутаторов)
6. Результаты проверок: проверка | ожидаемый результат | фактический результат
7. Вывод и предложения по улучшению
```

## Критерии оценивания

| Критерий | Доля |
|---|---|
| Выполнение требований задания (сеть работает, службы настроены) | 40% |
| Правильность и экономность адресного плана | 20% |
| Проверки и их результаты | 15% |
| Качество документации (схема, таблицы, понятный язык) | 15% |
| Самостоятельность и защита (ответы на вопросы) | 10% |

Работа, сданная после срока, принимается, но помечается «с опозданием». Списывание чужой работы или сдача без изменений текста, написанного искусственным интеллектом, — нарушение правил академической честности.

## Образец задания: поиск конфликтов в инвентаризации

В документации сети для каждого устройства записываются имя, IP и MAC-адрес. Если двум устройствам по ошибке дан один IP — **конфликт IP**; одинаковый MAC — клонированная виртуальная машина или ошибка в документах. Программа получает в первой строке число устройств, в следующих — «имя IP MAC», и для каждого повторяющегося IP и MAC выводит использующие его устройства (адреса и имена по алфавиту).

```python
n = int(input())
ip_lar = {}
mac_lar = {}
for _ in range(n):
    nom, ip, mac = input().split()
    ip_lar.setdefault(ip, []).append(nom)
    mac_lar.setdefault(mac.upper(), []).append(nom)   # регистр букв в MAC не важен
topildi = False
for sarlavha, jadval in (("конфликт IP", ip_lar), ("повтор MAC", mac_lar)):
    for manzil in sorted(jadval):
        if len(jadval[manzil]) > 1:
            topildi = True
            print(sarlavha + ": " + manzil + " -> " + ", ".join(sorted(jadval[manzil])))
if not topildi:
    print("конфликтов нет")
```
```java
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;
import java.util.Map;
import java.util.Scanner;
import java.util.TreeMap;

public class Main {
    static boolean chiqar(String sarlavha, Map<String, List<String>> jadval) {
        boolean topildi = false;
        for (Map.Entry<String, List<String>> e : jadval.entrySet()) {
            if (e.getValue().size() > 1) {
                topildi = true;
                List<String> nomlar = new ArrayList<>(e.getValue());
                Collections.sort(nomlar);
                System.out.println(sarlavha + ": " + e.getKey() + " -> " + String.join(", ", nomlar));
            }
        }
        return topildi;
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        Map<String, List<String>> ipLar = new TreeMap<>();
        Map<String, List<String>> macLar = new TreeMap<>();
        for (int i = 0; i < n; i++) {
            String nom = in.next(), ip = in.next(), mac = in.next();
            ipLar.computeIfAbsent(ip, k -> new ArrayList<>()).add(nom);
            macLar.computeIfAbsent(mac.toUpperCase(), k -> new ArrayList<>()).add(nom);   // регистр букв в MAC не важен
        }
        boolean birinchi = chiqar("конфликт IP", ipLar);
        boolean ikkinchi = chiqar("повтор MAC", macLar);
        if (!birinchi && !ikkinchi) System.out.println("конфликтов нет");
    }
}
```
```cpp
#include <algorithm>
#include <cctype>
#include <iostream>
#include <map>
#include <string>
#include <vector>
using namespace std;

bool chiqar(const string& sarlavha, map<string, vector<string>>& jadval) {
    bool topildi = false;
    for (auto& e : jadval) {
        if (e.second.size() > 1) {
            topildi = true;
            sort(e.second.begin(), e.second.end());
            string nomlar;
            for (size_t i = 0; i < e.second.size(); i++) nomlar += (i ? ", " : "") + e.second[i];
            cout << sarlavha << ": " << e.first << " -> " << nomlar << endl;
        }
    }
    return topildi;
}

int main() {
    int n;
    cin >> n;
    map<string, vector<string>> ipLar, macLar;
    for (int i = 0; i < n; i++) {
        string nom, ip, mac;
        cin >> nom >> ip >> mac;
        ipLar[ip].push_back(nom);
        for (auto& c : mac) c = toupper(c);                          // регистр букв в MAC не важен
        macLar[mac].push_back(nom);
    }
    bool birinchi = chiqar("конфликт IP", ipLar);
    bool ikkinchi = chiqar("повтор MAC", macLar);
    if (!birinchi && !ikkinchi) cout << "конфликтов нет" << endl;
    return 0;
}
```

Ввод:

```text
6
PC01 192.168.50.101 00:1A:2B:00:00:01
PC02 192.168.50.102 00:1a:2b:00:00:02
PRN1 192.168.50.150 00:1A:2B:00:00:50
PC03 192.168.50.102 00:1A:2B:00:00:03
VM-A 192.168.50.120 08:00:27:AA:BB:CC
VM-B 192.168.50.121 08:00:27:aa:bb:cc
```

Вывод:

```text
конфликт IP: 192.168.50.102 -> PC02, PC03
повтор MAC: 08:00:27:AA:BB:CC -> VM-A, VM-B
```

У PC02 и PC03 один и тот же адрес — один из них получит в сети сообщение «Windows has detected an IP address conflict». VM-A и VM-B склонированы с одной виртуальной машины без пересоздания MAC; если они в одном сегменте, MAC-таблица коммутатора запутается. Выполняйте такую проверку перед сдачей документов проекта.

## Задание

Выполните проект в Packet Tracer по образцу выше или по варианту преподавателя и подготовьте отчёт по шаблону. Пропустите перечень устройств через программу выше и подтвердите отсутствие конфликтов. Программные задания (KOT-A4, A7, A8, A9, A14) проверяются на платформе автоматически — сдайте каждое до его срока.

:::warning
**Частые ошибки**

- **Начинать настройку без схемы и адресного плана.** Потом адреса пересекаются, и всё приходится переделывать.
- **Не вносить проверки в отчёт.** «Работает» — не доказательство; нужны результаты `ping` и `tracert`.
- **Списывать реферат из одного источника.** Обязательны не менее 5 источников, цитаты и собственный вывод.
- **Откладывать сдачу на последний день.** Версия файла Packet Tracer может не совпасть или файл не сохранится — проверьте заранее.
:::

:::tip
Сохраняйте проект поэтапно (`loyiha-v1.pkt`, `loyiha-v2.pkt`): если какая-то настройка всё сломает, можно вернуться к предыдущей рабочей версии. Это простейшая форма контроля версий.
:::

## Проверьте себя

:::check
Q: Какие разделы должны быть в отчёте по сетевому проекту?
A: Задание, схема, адресный план, перечень устройств, основные настройки, результаты проверок, вывод.
Q: Как возникает конфликт IP и как он проявляется?
A: Когда двум устройствам назначен один IP; одно из них получает предупреждение, и связь работает с перебоями.
Q: Почему при сравнении MAC-адресов не учитывается регистр букв?
A: MAC — шестнадцатеричное число; `aa` и `AA` — одно значение, отличается только форма записи.
Q: Как документируются результаты проверок в проекте?
A: Таблицей: проверка, ожидаемый результат и фактический результат (например, вывод `ping` и `tracert`).
Q: Чему отводится наибольшая доля оценки самостоятельной работы?
A: Выполнению требований задания — работе сети и настройке служб.
