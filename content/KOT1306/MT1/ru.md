## Почему это важно

Сети — «многоуровневая» дисциплина: без IP-адресации не понять маршрутизацию, без TCP — HTTP и сокеты. Пропустишь одну тему — следующие станут сложнее. Часы самостоятельной работы отведены именно на то, чтобы закрыть эти пробелы, своими руками повторить увиденное на лекции и превратить знания в практический навык.

:::note
**После этой самостоятельной работы вы сможете:**

- составить личный недельный план освоения дисциплины;
- осваивать каждую лекцию методом активного чтения;
- повторять практические работы дома бесплатными средствами;
- проверять свои знания по каждому модулю вопросами.
:::

## Структура дисциплины и план освоения

| Неделя | Лекция | Практика | Главный результат самостоятельной работы |
|---|---|---|---|
| 1–2 | M1 Введение и классификация; M2 Топологии и устройства | A1 Устройства; A2 Топологии | таблица устройств и топологий, схема домашней сети |
| 3–4 | M3 Модель OSI; M4 Способы передачи и среды | A3 Эмуляторы; A4 Кодирование | нарисовать по памяти уровни OSI с PDU и устройствами |
| 5–6 | M5 Ethernet и MAC; M6 Token Ring, FDDI, Wi-Fi | A5 Снифферы; A6 Wi-Fi | разобрать кадр на поля в Wireshark |
| 7–8 | M7 TCP/IP и IP; M8 Адресация IPv4 | A7 Маски и VLSM | решить вручную 20 задач на подсети |
| 9–10 | M9 ARP, ICMP, DHCP, маршрутизация; M10 TCP, UDP, сокеты | A8 Маршрутизаторы; A9 Сокеты | схема из трёх маршрутизаторов в Packet Tracer, эхо-сервер |
| 11–12 | M11 HTTP, FTP, почта; M12 DNS | A10 Windows Server; A11 DHCP и DNS | анализ HTTP в F12 браузера, упражнения с `nslookup` |
| 13–14 | M13 Серверные ОС и домены; M14 Безопасность | A12 Пользователи; A13 Общие ресурсы; A14 Брандмауэр и VPN | сервер, пользователи и общие папки в ВМ |
| 15 | M15 Устранение неисправностей | A15 Утилиты | отчёт о неисправностях |

Планируйте 2–3 часа самостоятельной работы в неделю: **1 час** — перечитать лекцию и сделать конспект, **1 час** — повторить практическую работу, **0,5 часа** — вопросы «Проверьте себя» и тесты.

## Активное чтение лекции

1. **Просмотр** (5 минут): заголовки, таблицы, список «После этого занятия вы сможете».
2. **Вопросы**: превратите заголовок каждого раздела в вопрос («Как TCP обеспечивает надёжность?»).
3. **Чтение**: найдите ответ и кратко запишите своими словами. Перерисуйте таблицы — лучший способ запомнить.
4. **Запуск примеров**: запустите код разобранного примера на компьютере и попробуйте изменить ввод.
5. **Повторение**: через 1 день, 1 неделю и 1 месяц ответьте на вопросы «Проверьте себя» с закрытой книгой.

## Средства для практики дома

| Средство | Для чего | Стоимость |
|---|---|---|
| **Cisco Packet Tracer** | топологии, маршрутизация, DHCP, VLAN | бесплатно (учётная запись Netacad) |
| **Wireshark** | анализ пакетов | бесплатно |
| **VirtualBox** / Hyper-V | ВМ с Windows Server и Linux | бесплатно |
| **Windows Server Evaluation** | занятия A10–A14 | 180 дней бесплатно |
| **Ubuntu Server** | сетевые службы Linux | бесплатно |
| Командная строка | `ipconfig`, `ping`, `tracert`, `nslookup`, `netstat` | встроена в ОС |

Важное правило: экспериментируйте **только** на своём компьютере, в своей домашней сети и виртуальной лаборатории. Сканирование чужих сетей и перехват их трафика — правонарушение.

## Словарь ключевых понятий

| Понятие | Краткое пояснение |
|---|---|
| Протокол | правила взаимодействия одинаковых уровней |
| PDU | единица данных уровня: бит, кадр, пакет, сегмент, сообщение |
| MAC-адрес | 48-битный физический адрес, уровень 2 |
| IP-адрес | 32-битный (IPv4) или 128-битный (IPv6) логический адрес, уровень 3 |
| Маска / префикс | разделяет сетевую часть адреса и часть узла |
| Порт | 16-битный номер, определяющий программу, уровень 4 |
| Домен коллизий | сегмент, где сигналы могут столкнуться |
| Широковещательный домен | множество устройств, куда доходит одно широковещание |
| Шлюз | адрес маршрутизатора для выхода в другие сети |
| DHCP / DNS | автоматическое назначение адресов / преобразование имён в адреса |
| NAT | замена частных адресов публичным |
| Брандмауэр / VPN / IDS | фильтрация трафика / зашифрованный туннель / обнаружение атак |

## Самопроверка по модулям

1. Назовите семь уровней OSI, для каждого — PDU и один протокол.
2. Что делают с кадром или пакетом концентратор, коммутатор и маршрутизатор?
3. Поясните название 1000BASE-T. Почему минимальный кадр Ethernet — 64 байта?
4. Найдите вручную адрес сети и широковещательный адрес для 172.16.37.130/20.
5. Объясните процесс DORA в DHCP и ход запроса ARP.
6. Как меняются номера seq и ack при трёхэтапном установлении соединения TCP?
7. Какие протоколы работают между вводом `https://aifu.uz` в браузере и открытием страницы? (DNS → TCP → TLS → HTTP.)
8. Как действуют вместе разрешения share и NTFS?
9. Сравните назначение межсетевого экрана, VPN и IDS.
10. В ситуации «Интернет не работает» какие команды и в каком порядке вы выполните?

:::warning
**Частые ошибки**

- **Только читать, без практики.** Сети — практическая дисциплина: знания не закрепятся, пока вы сами не воспользуетесь `ping` и Wireshark.
- **Откладывать пропущенную тему «на потом».** Без IP-адресации следующие 8 тем станут непонятными.
- **Учить в ночь перед экзаменом.** С интервалами повторения (1 день, 1 неделя, 1 месяц) знания сохраняются надолго.
- **Экспериментировать в чужих сетях.** Только в своей лаборатории.
:::

:::tip
В конце каждого модуля составляйте одностраничную «шпаргалку»: главная таблица, формулы и команды. К концу семестра 15 страниц — лучший материал для подготовки к экзамену.
:::

## Проверьте себя

:::check
Q: Почему опасно пропустить тему IP-адресации?
A: Маршрутизация, DHCP, DNS, NAT, правила межсетевого экрана и поиск неисправностей — всё опирается на понимание IP-адресов и масок.
Q: Каков первый шаг активного чтения лекции?
A: Просмотр — знакомство с заголовками, таблицами и списком учебных результатов.
Q: Как бесплатно попробовать Windows Server дома?
A: Установить версию Evaluation (180 дней) на виртуальную машину в VirtualBox или Hyper-V.
Q: В каком порядке работают протоколы при открытии страницы в браузере?
A: DNS (имя в адрес) → TCP (соединение) → TLS (шифрование) → HTTP (запрос и ответ).
Q: В каких сетях можно сканировать и перехватывать трафик?
A: Только в своих или с разрешения владельца (лаборатория).
:::
