## Почему это важно

Интернет — объединение тысяч независимых сетей (провайдеров, университетов, компаний). Они построены на разных технологиях: одна на Ethernet, другая на Wi-Fi, третья на оптической магистрали. Объединяет их всех в один общий «язык» **протокол IP**. Каждый пакет идёт с заголовком IP, и каждый маршрутизатор принимает решение, глядя только на этот заголовок. Поэтому знать заголовок IP поле за полем — азбука сетевого инженера.

:::note
**После этого занятия вы сможете:**

- называть четыре уровня стека TCP/IP и основные протоколы каждого;
- объяснять принципы IP: датаграмма, без установления соединения, «по возможности»;
- читать поля заголовка IPv4 и объяснять их смысл;
- вычислять и проверять контрольную сумму заголовка IP;
- рассчитывать, как пакет больше MTU делится на фрагменты.
:::

## Стек TCP/IP

| Уровень | Протоколы | Единица данных | Адрес |
|---|---|---|---|
| **Прикладной** | HTTP, HTTPS, DNS, SMTP, FTP, SSH, DHCP | сообщение | доменное имя, URL |
| **Транспортный** | TCP, UDP | сегмент / датаграмма | порт |
| **Межсетевой** (Internet) | IP (v4, v6), ICMP, IGMP | пакет | IP-адрес |
| **Сетевого доступа** | Ethernet, Wi-Fi, PPP; ARP | кадр | MAC-адрес |

Стек имеет форму **«песочных часов»**: внизу много канальных технологий, наверху много приложений, а посередине — единственный **IP**. Принцип «всё поверх IP, IP поверх всего» (everything over IP, IP over everything) обеспечивает гибкость Интернета: появился новый тип кабеля — меняется только нижний уровень; появилось новое приложение — только верхний.

## Принципы межсетевого обмена

| Принцип | Смысл |
|---|---|
| **Датаграмма** | каждый пакет независим — несёт свой полный адрес; разные пакеты могут идти разными путями |
| **Без установления соединения** (connectionless) | перед отправкой соединение не устанавливается, сеть не хранит состояние «разговора» |
| **По возможности** (best effort) | IP старается доставить, но **ничего не гарантирует**: пакет может потеряться, продублироваться или прийти не по порядку |
| **Сквозной принцип** (end-to-end) | надёжность, порядок и повторная передача — задача конечных систем (TCP); ядро сети остаётся простым и быстрым |
| **Пошаговая маршрутизация** (hop-by-hop) | каждый маршрутизатор выбирает только **следующий шаг**, весь путь он не знает |

## Заголовок IPv4

Минимальный заголовок — **20 байт** (пять 32-битных слов):

| Байт | Поле | Бит | Смысл |
|---|---|---|---|
| 0 | Версия, IHL | 4 + 4 | версия = 4; IHL — длина заголовка в 4-байтных словах (обычно 5 → 20 байт) |
| 1 | DSCP/ECN (тип обслуживания) | 8 | приоритет и отметка перегрузки |
| 2–3 | Общая длина | 16 | заголовок + данные, в байтах (не более 65 535) |
| 4–5 | Идентификатор | 16 | для сборки фрагментов одного пакета |
| 6–7 | Флаги, смещение фрагмента | 3 + 13 | DF — «не фрагментировать», MF — «есть ещё фрагменты»; смещение в 8-байтных единицах |
| 8 | **TTL** | 8 | каждый маршрутизатор уменьшает на 1; при 0 пакет отбрасывается |
| 9 | Протокол | 8 | данные внутри: 1 — ICMP, 6 — TCP, 17 — UDP |
| 10–11 | Контрольная сумма | 16 | только для **заголовка** |
| 12–15 | IP источника | 32 | отправитель |
| 16–19 | IP получателя | 32 | получатель |

**TTL** (Time To Live) не даёт пакетам вечно циркулировать в петлях маршрутизации. Команда `tracert` (Windows) / `traceroute` (Linux) посылает пакеты с TTL = 1, 2, 3, … и определяет путь по сообщениям ICMP «TTL истёк» от каждого маршрутизатора.

## Контрольная сумма

Контрольная сумма заголовка IP вычисляется сложением **в обратном коде** (ones' complement):

1. Поле контрольной суммы принимается равным 0.
2. Заголовок делится на 16-битные слова, и все они складываются.
3. Часть сверх 16 бит (перенос) прибавляется обратно к младшим 16 битам — пока результат не уместится в 16 бит.
4. Результат инвертируется (вычитается из 0xFFFF).

Получатель так же складывает весь заголовок (вместе с контрольной суммой): если результат **0xFFFF** — заголовок не повреждён. Так как каждый маршрутизатор уменьшает TTL, он заново вычисляет и контрольную сумму.

## Фрагментация

У каждого канала есть **MTU** (Maximum Transmission Unit): у Ethernet — 1500 байт. Если пакет больше MTU канала, маршрутизатор делит его на **фрагменты** (если не установлен флаг DF):

- у каждого фрагмента свой заголовок IP, идентификатор одинаковый;
- часть данных кратна 8 (кроме последней), так как смещение записывается в 8-байтных единицах;
- во всех фрагментах, кроме последнего, MF = 1;
- фрагменты собираются только **у получателя**.

Пакет больше MTU с флагом DF отбрасывается, а отправителю возвращается сообщение ICMP «Fragmentation needed» — на этом основан метод **Path MTU Discovery**. В IPv6 маршрутизаторы вообще не фрагментируют.

## Кратко об ICMP и IPv6

**ICMP** (Internet Control Message Protocol) — «служебные сообщения» IP: `Echo Request/Reply` (`ping`), `Destination Unreachable`, `Time Exceeded` (истёк TTL), `Fragmentation Needed`. Сам ICMP передаётся внутри IP-пакета (протокол = 1).

**IPv6**: адрес 128 бит (`2001:db8::1`), заголовок фиксированные 40 байт и упрощён (нет контрольной суммы, фрагментация — только у отправителя), Hop Limit вместо TTL, multicast вместо широковещания. После исчерпания адресов IPv4 IPv6 быстро распространяется.

## Разобранный пример 1: разбор заголовка IPv4

На входе — 20 байт заголовка IPv4 в шестнадцатеричном виде. Выведите основные поля и проверьте контрольную сумму; если она неверна, выведите и правильное значение.

```python
import sys

b = [int(t, 16) for t in sys.stdin.read().split()]


def yigindi(baytlar):
    s = 0
    for i in range(0, len(baytlar), 2):
        s += baytlar[i] * 256 + baytlar[i + 1]
    while s > 0xFFFF:
        s = (s & 0xFFFF) + (s >> 16)          # добавляем перенос обратно
    return s


nomlar = {1: "ICMP", 6: "TCP", 17: "UDP"}
print("версия:", b[0] >> 4, "заголовок:", (b[0] & 15) * 4, "байт")
print("общая длина:", b[2] * 256 + b[3])
print("TTL:", b[8])
print("протокол: " + str(b[9]) + " (" + nomlar.get(b[9], "?") + ")")
print("источник:", ".".join(str(x) for x in b[12:16]))
print("получатель:", ".".join(str(x) for x in b[16:20]))
yozilgan = b[10] * 256 + b[11]
if yigindi(b[:20]) == 0xFFFF:
    print("контрольная сумма: 0x" + format(yozilgan, "04X") + " верна")
else:
    toza = b[:10] + [0, 0] + b[12:20]
    togrisi = 0xFFFF - yigindi(toza)
    print("контрольная сумма: 0x" + format(yozilgan, "04X") + " неверна, правильная 0x" + format(togrisi, "04X"))
```

Теперь изменим TTL с 64 на 63 (9-й байт `3f`), не обновляя контрольную сумму, — как будто маршрутизатор ошибся:

```text
45 00 00 3c 1c 46 40 00 3f 06 b1 e6 ac 10 0a 63 ac 10 0a 0c
```

Последняя строка вывода:

```text
контрольная сумма: 0xB1E6 неверна, правильная 0xB2E6
```

TTL уменьшился на 1 — контрольная сумма выросла на 0x0100 (TTL стоит в старшем байте 16-битного слова). Маршрутизаторы используют это свойство, чтобы обновлять контрольную сумму, не пересчитывая её целиком.

## Разобранный пример 2: фрагментация

В строке — длина части данных IP-пакета *L* (байт) и MTU канала. Заголовок — 20 байт. Для каждого фрагмента выведите номер, общую длину (с заголовком), смещение (в 8-байтных единицах) и флаг MF.

```python
l, mtu = map(int, input().split())
qism = (mtu - 20) // 8 * 8               # данные фрагмента кратны 8
joy = 0
raqam = 0
while joy < l:
    raqam += 1
    hajm = min(qism, l - joy)
    mf = 1 if joy + hajm < l else 0       # MF = 1 у всех, кроме последнего
    print(raqam, "len=" + str(hajm + 20), "offset=" + str(joy // 8), "MF=" + str(mf))
    joy += hajm
```
```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int l = in.nextInt();
        int mtu = in.nextInt();
        int qism = (mtu - 20) / 8 * 8;                       // данные фрагмента кратны 8
        int joy = 0;
        int raqam = 0;
        while (joy < l) {
            raqam++;
            int hajm = Math.min(qism, l - joy);
            int mf = joy + hajm < l ? 1 : 0;                  // MF = 1 у всех, кроме последнего
            System.out.println(raqam + " len=" + (hajm + 20) + " offset=" + joy / 8 + " MF=" + mf);
            joy += hajm;
        }
    }
}
```
```cpp
#include <algorithm>
#include <iostream>
using namespace std;

int main() {
    int l, mtu;
    cin >> l >> mtu;
    int qism = (mtu - 20) / 8 * 8;                           // данные фрагмента кратны 8
    int joy = 0;
    int raqam = 0;
    while (joy < l) {
        raqam++;
        int hajm = min(qism, l - joy);
        int mf = joy + hajm < l ? 1 : 0;                      // MF = 1 у всех, кроме последнего
        cout << raqam << " len=" << hajm + 20 << " offset=" << joy / 8 << " MF=" << mf << endl;
        joy += hajm;
    }
    return 0;
}
```

Ввод:

```text
4000 1500
```

Вывод:

```text
1 len=1500 offset=0 MF=1
2 len=1500 offset=185 MF=1
3 len=1060 offset=370 MF=0
```

4000 байт данных разделились на 1480 + 1480 + 1040. Смещение второго фрагмента — 185, то есть 185 × 8 = 1480 байт. При MTU = 576 данные во фрагменте будут не 556, а 552 байта (кратно 8).

:::warning
**Частые ошибки**

- **Читать IHL в байтах.** IHL = 5 — это 5 четырёхбайтных слов, то есть 20 байт.
- **Думать, что контрольная сумма IP защищает и данные.** Она проверяет только заголовок; для данных есть контрольная сумма TCP/UDP и CRC канального уровня.
- **Записывать смещение фрагмента в байтах.** Смещение — в 8-байтных единицах: 1480 байт → 185.
- **Считать, что фрагменты собирает маршрутизатор.** Фрагменты объединяются только у конечного получателя.
- **Думать, что IP гарантирует доставку.** IP работает «по возможности»; надёжность — задача TCP.
:::

:::tip
Выполните `tracert 8.8.8.8` (или `traceroute`) и посмотрите в Wireshark с фильтром `icmp` ответы «Time-to-live exceeded». Проверьте, каков TTL во вложенном заголовке IP каждого ответа.
:::

## Итоги

- TCP/IP — 4 уровня: прикладной, транспортный, межсетевой, сетевого доступа; посередине — единственный IP («песочные часы»).
- IP — датаграммный, без установления соединения, «по возможности»; надёжность — в конечных системах.
- Заголовок IPv4 — 20 байт: версия, IHL, длина, идентификатор, флаги и смещение, TTL, протокол, контрольная сумма, источник и получатель.
- Контрольная сумма — инвертированная сумма 16-битных слов в обратном коде; сумма правильного заголовка равна 0xFFFF.
- Пакет больше MTU делится на части, кратные 8; собирается у получателя по MF и смещению.

:::check
Q: Почему IP называют протоколом доставки «по возможности»?
A: Он старается доставить пакет, но не гарантирует ни доставку, ни порядок, ни отсутствие дубликатов.
Q: Какова длина заголовка IPv4, первый байт которого `46`?
A: IHL = 6 → 6 × 4 = 24 байта (с 4 байтами дополнительных полей).
Q: Зачем нужно поле TTL?
A: Чтобы пакет не циркулировал вечно в петле маршрутизации; каждый маршрутизатор уменьшает его на 1, при 0 пакет отбрасывается.
Q: На сколько фрагментов делятся 3000 байт данных в канале с MTU = 1500?
A: На 3: 1480 + 1480 + 40 байт данных.
Q: Если поле протокола равно 17, что внутри пакета?
A: Датаграмма UDP.
