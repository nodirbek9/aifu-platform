## Операции сравнения и логические операции

| Операция | Python | Java, C++ | Смысл |
|---|---|---|---|
| равно | `==` | `==` | `a == b` |
| не равно | `!=` | `!=` | |
| больше, меньше | `>`, `<` | `>`, `<` | |
| больше или равно, меньше или равно | `>=`, `<=` | `>=`, `<=` | |
| И | `and` | `&&` | оба условия истинны |
| ИЛИ | `or` | `\|\|` | хотя бы одно истинно |
| НЕ | `not` | `!` | обращает условие |

**Таблица истинности**:

| A | B | A И B | A ИЛИ B | НЕ A |
|---|---|---|---|---|
| истина | истина | истина | истина | ложь |
| истина | ложь | ложь | истина | ложь |
| ложь | истина | ложь | истина | истина |
| ложь | ложь | ложь | ложь | истина |

**Сокращённое вычисление**: в `A И B`, если A ложно, B не проверяется. Этим можно защищать опасные операции: `income > 0 and payment / income < 0.5` — деления на ноль не произойдёт.

## Формы ветвления

| Форма | Когда | Python |
|---|---|---|
| **Неполная** (if) | дополнительное действие, если условие истинно | `if balance < 0: warn()` |
| **Полная** (if-else) | один из двух путей | `if ... : A else: B` |
| **Цепочка** (if-elif-else) | много взаимоисключающих случаев | `if ...: elif ...: else:` |
| **Вложенная** | условие внутри условия | `if a: if b: ...` |
| **Выбор** (match / switch) | несколько точных значений одной переменной | тип счёта: «текущий», «депозит», «кредит» |

**В цепочке важен порядок**: условия проверяются сверху вниз, и после первого истинного остальные не проверяются. Поэтому самые узкие (строгие) условия пишутся первыми.

## Разобранный пример: решение по кредитной заявке

Таблица решений из MT11: если балл скоринга ≥ 600 и ежемесячный платёж ≤ 50% дохода — одобрить; балл достаточен, но нагрузка велика — предложить меньшую сумму; балл низкий, но нагрузка допустима — рассмотреть с поручителем; иначе — отказать. Если доход нулевой или отрицательный — ошибка ввода. В каждой строке: фамилия, балл, месячный доход, месячный платёж.

```python
import sys

MIN_BALL = 600        # порог скоринга
MAX_ULUSH = 50        # платёж не должен превышать этот процент дохода

for satr in sys.stdin.read().split("\n"):
    if not satr.strip():
        continue
    ism, ball, daromad, tolov = satr.split()
    ball, daromad, tolov = int(ball), int(daromad), int(tolov)
    if daromad <= 0:                                   # сначала проверка входных данных
        qaror = "ошибка — неверный доход"
    else:
        yuk_mos = tolov * 100 <= daromad * MAX_ULUSH   # сравнение в целых числах
        if ball >= MIN_BALL and yuk_mos:
            qaror = "одобрить"
        elif ball >= MIN_BALL:
            qaror = "предложить меньшую сумму"
        elif yuk_mos:
            qaror = "рассмотреть с поручителем"
        else:
            qaror = "отказать"
    print(f"{ism}: {qaror}")
```
```java
import java.util.Scanner;

public class Main {
    static final int MIN_BALL = 600;    // порог скоринга
    static final int MAX_ULUSH = 50;    // платёж не должен превышать этот процент дохода

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        while (in.hasNext()) {
            String ism = in.next();
            long ball = in.nextLong(), daromad = in.nextLong(), tolov = in.nextLong();
            String qaror;
            if (daromad <= 0) {                                    // сначала проверка входных данных
                qaror = "ошибка — неверный доход";
            } else {
                boolean yukMos = tolov * 100 <= daromad * MAX_ULUSH;   // сравнение в целых числах
                if (ball >= MIN_BALL && yukMos) qaror = "одобрить";
                else if (ball >= MIN_BALL) qaror = "предложить меньшую сумму";
                else if (yukMos) qaror = "рассмотреть с поручителем";
                else qaror = "отказать";
            }
            System.out.println(ism + ": " + qaror);
        }
    }
}
```
```cpp
#include <iostream>
#include <string>
using namespace std;

const int MIN_BALL = 600;    // порог скоринга
const int MAX_ULUSH = 50;    // платёж не должен превышать этот процент дохода

int main() {
    string ism;
    long long ball, daromad, tolov;
    while (cin >> ism >> ball >> daromad >> tolov) {
        string qaror;
        if (daromad <= 0) {                                       // сначала проверка входных данных
            qaror = "ошибка — неверный доход";
        } else {
            bool yukMos = tolov * 100 <= daromad * MAX_ULUSH;     // сравнение в целых числах
            if (ball >= MIN_BALL && yukMos) qaror = "одобрить";
            else if (ball >= MIN_BALL) qaror = "предложить меньшую сумму";
            else if (yukMos) qaror = "рассмотреть с поручителем";
            else qaror = "отказать";
        }
        cout << ism << ": " << qaror << "\n";
    }
    return 0;
}
```

Ввод:

```text
Aliyev 720 8000000 3000000
Karimova 650 6000000 3500000
Tursunov 580 10000000 2000000
Rahimov 540 4000000 2500000
Usmonova 600 7000000 3500000
Nazarov 610 0 1000000
```

Вывод:

```text
Aliyev: одобрить
Karimova: предложить меньшую сумму
Tursunov: рассмотреть с поручителем
Rahimov: отказать
Usmonova: одобрить
Nazarov: ошибка — неверный доход
```

Обратите внимание:

- **Usmonova** — граничный случай: балл ровно 600, платёж ровно 50%. Благодаря `>=` и `<=` заявка одобрена. Если бы было написано `>`, ей бы ошибочно отказали — поэтому в тестах обязательно должны быть граничные значения.
- **Nazarov** — доход 0: так как проверка стоит первой, программа не «падает» из-за деления на ноль или бессмысленного решения.
- Доля сравнивается **в целых числах** в виде `платёж * 100 <= доход * 50` — чтобы избежать ошибок вещественных чисел (MT12).
- Когда выполнение доходит до строки с `elif` для балла, проверка нагрузки уже заведомо ложна — предыдущее условие её «отфильтровало». Порядок цепочки — часть логики.

## Тестирование граничными значениями

Для каждого условия проверяются три значения: чуть ниже границы, ровно граница, чуть выше. Для балла: 599, 600, 601. Для доли платежа: 49%, 50%, 51%. Кроме того — неверный ввод: 0, отрицательное число, очень большое число. Каждый столбец таблицы решений из четырёх правил должен быть покрыт хотя бы одним тестом.

| Тест | Балл | Доля | Ожидаемое решение |
|---|---|---|---|
| 1 | 600 | 50% | одобрить |
| 2 | 599 | 50% | рассмотреть с поручителем |
| 3 | 600 | 51% | предложить меньшую сумму |
| 4 | 599 | 51% | отказать |

:::warning
**Частые ошибки**

- **Путать `=` и `==`.** `=` — присваивание, `==` — сравнение.
- **Неверный порядок условий.** Если широкое условие стоит первым, до узких очередь не дойдёт.
- **Пересечение диапазонов или пробелы между ними.** Например, `< 600` и `> 600` — ровно 600 не попадает ни в одну ветку.
- **Сравнивать вещественные числа через `==`.** Используйте целые числа или допустимую погрешность.
- **Не проверять входные данные.** Ноль, пустое или отрицательное значение ломает программу.
- **Несколько строк без фигурных скобок в Java и C++.** Без `{ }` после `if` к условию относится только первая строка.
:::

Q: Что такое сокращённое вычисление?
A: В операции И, если первое условие ложно (или в ИЛИ — истинно), второе не проверяется.
Q: Почему в цепочке if-elif-else важен порядок?
A: Условия проверяются сверху вниз, и после первого истинного остальные не выполняются.
Q: Какие граничные значения проверяются для условия «балл ≥ 600»?
A: 599, 600 и 601.
Q: Почему в примере доля сравнивается в целых числах?
A: Чтобы граничный случай не был оценён неверно из-за ошибок вещественных чисел.
