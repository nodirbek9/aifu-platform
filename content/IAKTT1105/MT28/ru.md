## Особенности мобильной коммерции

| Особенность | Содержание | Возможность для бизнеса |
|---|---|---|
| **Всегда под рукой** | телефон весь день с пользователем | покупка в любой момент, оперативные сообщения |
| **Местоположение** | определяется через GPS и Wi-Fi | ближайший магазин, адрес доставки, местные предложения |
| **Персональность** | одно устройство — один пользователь | персональные рекомендации |
| **Камера и датчики** | сканирование QR, съёмка документов | оплата, удалённая идентификация (S13) |
| **Биометрия** | отпечаток пальца, лицо | быстрое и безопасное подтверждение |
| **Маленький экран** | короткое внимание, неудобный ввод | простой интерфейс, оплата в одно касание |

**«Сначала мобильный»** (mobile first) — услуга сначала проектируется для телефона, затем адаптируется к большим экранам.

## Мобильные каналы

| Канал | Преимущество | Недостаток |
|---|---|---|
| **Нативное приложение** (iOS, Android) | самое быстрое и удобное, push-уведомления, возможности устройства | дорогая разработка, нужна установка, комиссия магазина |
| **Мобильный сайт** | без установки, находится через поиск | ограниченные возможности, медленнее |
| **PWA** (прогрессивное веб-приложение) | веб, но похоже на приложение: значок на экране, офлайн-режим | некоторые ограничения на iOS |
| **Мини-программа в суперприложении** | готовый доступ к миллионам пользователей, готовые оплата и идентификация | правила и комиссия платформы, клиент «принадлежит» платформе |
| **Бот в мессенджере** | простые заказы и услуги в мессенджерах вроде Telegram | неудобен для сложного каталога |

## Технологии мобильных платежей

- **NFC** — оплата прикладыванием телефона или часов к терминалу (бесконтактно).
- **QR-оплата**: **статический QR** — постоянный код магазина, покупатель вводит сумму сам; **динамический QR** — новый код с суммой для каждой покупки, касса подтверждает автоматически.
- **Токенизация** — в кошельке хранится не номер карты, а заменяющий его **токен**; даже при краже токена реальные данные карты не раскрываются (S14).
- **Цифровые кошельки** — Apple Pay, Google Pay, Samsung Pay; в Узбекистане — кошельки в платёжных и банковских приложениях.
- **Переводы между приложениями** — отправка денег по номеру телефона.

## Местоположение и push-уведомления

**Сервисы на основе местоположения**: ближайший филиал, местоположение курьера в реальном времени, предложение при входе в «геозону». **Push-уведомления**: статус заказа, акции, напоминание о брошенной корзине. И то и другое используется с **согласия** пользователя и в меру — слишком много сообщений приводит к удалению приложения.

## Экономика магазинов приложений

- App Store и Google Play берут **комиссию** с платежей за цифровые товары и подписки (обычно 15–30%, для небольших разработчиков и второго года подписки есть пониженные ставки).
- На оплату физических товаров (одежда, продукты) и услуг (такси) эта комиссия обычно не распространяется.
- Как сделать приложение заметным: рейтинг в магазине, отзывы и ключевые слова (**ASO** — оптимизация для магазина приложений).
- **CAC** клиента, пришедшего через приложение (реклама + установка), входит в юнит-экономику (MT26).

## Метрики приложения

| Метрика | Формула | Смысл |
|---|---|---|
| **Установки** | число загрузок | охват, но не активность |
| **DAU / MAU** | ежедневные / ежемесячные активные пользователи | «липкость»: 0,25 — средний пользователь заходит ~7,5 дней в месяц |
| **Удержание на N-й день** (retention) | вернувшиеся на N-й день / установившие | становится ли приложение привычкой |
| **Конверсия** | купившие / активные пользователи | M13 |
| **Доля удалений** | доля удаливших приложение | признак неудовлетворённости |

**Когортный анализ** — разделение пользователей на группы (когорты), установившие приложение в одно время (например, в одном месяце), и наблюдение за поведением каждой группы во времени. Если в новых когортах удержание растёт, приложение улучшается.

## Разобранный пример: удержание по когортам

В каждой строке — когорта (месяц установки), число установок и число пользователей, вернувшихся на 1-й, 7-й и 30-й день. Выведите проценты удержания по каждой когорте и в целом.

```python
import sys

kogortalar = []
for satr in sys.stdin.read().split("\n"):
    if not satr.strip():
        continue
    nom, ornatish, k1, k7, k30 = satr.split()
    kogortalar.append((nom, int(ornatish), int(k1), int(k7), int(k30)))

def foiz(qism, butun):
    return 100 * qism / butun

for nom, n, a, b, c in kogortalar:
    print(f"{nom}: день 1 {foiz(a, n):.1f}%, день 7 {foiz(b, n):.1f}%, день 30 {foiz(c, n):.1f}%")

# итого — взвешено по числу установок
n = sum(k[1] for k in kogortalar)
a = sum(k[2] for k in kogortalar)
b = sum(k[3] for k in kogortalar)
c = sum(k[4] for k in kogortalar)
print(f"Итого: день 1 {foiz(a, n):.1f}%, день 7 {foiz(b, n):.1f}%, день 30 {foiz(c, n):.1f}%")
```
```java
import java.util.Scanner;

public class Main {
    static double foiz(long qism, long butun) {
        return 100.0 * qism / butun;
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        long n = 0, a = 0, b = 0, c = 0;
        while (in.hasNext()) {
            String nom = in.next();
            long ornatish = in.nextLong(), k1 = in.nextLong(), k7 = in.nextLong(), k30 = in.nextLong();
            System.out.println(String.format("%s: день 1 %.1f%%, день 7 %.1f%%, день 30 %.1f%%", nom, foiz(k1, ornatish), foiz(k7, ornatish), foiz(k30, ornatish)));
            n += ornatish; a += k1; b += k7; c += k30;          // итого — взвешено по числу установок
        }
        System.out.println(String.format("Итого: день 1 %.1f%%, день 7 %.1f%%, день 30 %.1f%%", foiz(a, n), foiz(b, n), foiz(c, n)));
    }
}
```
```cpp
#include <cstdio>
#include <iostream>
#include <string>
using namespace std;

double foiz(long long qism, long long butun) {
    return 100.0 * qism / butun;
}

int main() {
    string nom;
    long long ornatish, k1, k7, k30, n = 0, a = 0, b = 0, c = 0;
    while (cin >> nom >> ornatish >> k1 >> k7 >> k30) {
        printf("%s: день 1 %.1f%%, день 7 %.1f%%, день 30 %.1f%%\n", nom.c_str(), foiz(k1, ornatish), foiz(k7, ornatish), foiz(k30, ornatish));
        n += ornatish; a += k1; b += k7; c += k30;               // итого — взвешено по числу установок
    }
    printf("Итого: день 1 %.1f%%, день 7 %.1f%%, день 30 %.1f%%\n", foiz(a, n), foiz(b, n), foiz(c, n));
    return 0;
}
```

Ввод:

```text

2026-03 3000 1500 1050 690
```

Вывод:

```text
2026-01: день 1 40.0%, день 7 25.0%, день 30 15.0%
2026-02: день 1 44.0%, день 7 28.0%, день 30 16.0%
2026-03: день 1 50.0%, день 7 35.0%, день 30 23.0%
Итого: день 1 45.3%, день 7 30.0%, день 30 18.5%
```

С каждой новой когортой удержание растёт: 23% установивших в марте пользуются приложением и через месяц (в январе — 15%). Это может показывать, что изменения, внесённые в марте (например, упрощённая регистрация или бонус за первую покупку), сработали. Если смотреть только на число установок, это важное улучшение осталось бы незамеченным.

## Мобильная безопасность

- Устанавливать приложения только из официальных магазинов; проверять запрашиваемые разрешения (контакты, SMS, местоположение).
- Никому не сообщать SMS-коды (S13); остерегаться мошенничества через приложения для демонстрации экрана.
- Для разработчика: токенизация, проверка сертификата, шифрованное хранение данных на телефоне, биометрическое подтверждение.

:::warning
**Частые ошибки**

- **Измерять только число установок.** Важны удержание и активные пользователи.
- **Слишком много push-уведомлений.** Пользователь удаляет приложение.
- **Не учитывать комиссию магазина приложений в юнит-экономике.**
- **Делать мобильную версию «уменьшенным сайтом».** Потребности мобильных пользователей другие.
:::

## Итоги

- Мобильная коммерция: всегда под рукой, местоположение, персональность, камера, биометрия; подход «сначала мобильный».
- Каналы: нативные приложения, мобильный веб, PWA, мини-программы суперприложений, боты.
- Платежи: NFC, статический и динамический QR, токенизация, цифровые кошельки.
- Метрики: DAU/MAU, удержание на N-й день, когортный анализ; комиссия магазина приложений и CAC входят в юнит-экономику.

## Проверьте себя

:::check
Q: Чем статическая QR-оплата отличается от динамической?
A: Статический QR постоянный, сумму вводит покупатель; динамический создаётся с суммой для каждой покупки и подтверждается автоматически.
Q: Зачем нужна токенизация?
A: В кошельке вместо номера карты хранится токен — даже при его краже реальные данные карты не раскрываются.
Q: Что означает DAU/MAU = 0,25?
A: Средний активный пользователь заходит в приложение примерно в четверть дней месяца (≈7–8 дней).
Q: Зачем нужен когортный анализ?
A: Чтобы сравнить поведение групп пользователей, пришедших в разное время, и понять, улучшается ли продукт.
:::
