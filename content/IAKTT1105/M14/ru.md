## Почему эта тема важна?

Для предприятия данные — актив, равноценный деньгам: клиентская база, бухгалтерия, договоры, банковские счета. Один сотрудник, поверивший мошенническому письму, сервер без резервной копии или необновлённая программа могут нанести компании большой ущерб. Вопрос для экономиста: **на какие меры защиты оправданно тратить деньги?**

- экономически оценивать риски через ALE и ROSI.
:::

## Понятие и триада

**Информационная безопасность** — состояние и меры защиты информации и обрабатывающих её систем от несанкционированного доступа, изменения, утраты и нарушения работы. Её три основных свойства (**триада CIA**):

| Свойство | Смысл | Пример нарушения |
|---|---|---|
| **Конфиденциальность** (Confidentiality) | данные видят только те, у кого есть право | утечка клиентской базы |
| **Целостность** (Integrity) | данные не изменены без разрешения | подмена банковских реквизитов в счёте-фактуре |
| **Доступность** (Availability) | данные и сервисы работают, когда нужны | остановка интернет-магазина из-за сбоя сервера |

## Источники угроз

| Источник | Примеры |
|---|---|
| **Человеческая ошибка** | удаление не того файла, письмо не тому адресату, пароль на стикере |
| **Мошенничество и социальная инженерия** | поддельные письма и страницы (фишинг), просьба перевести деньги «от имени руководителя», выманивание SMS-кода |
| **Вредоносные программы** | вирусы, программы-вымогатели, шифрующие файлы (ransomware), шпионские программы |
| **Внутренняя угроза** | вынос или злоупотребление данными со стороны сотрудника |
| **Технические сбои** | отказ диска, отключение электричества, ошибка программы |
| **Природные и физические** | пожар, затопление, кража оборудования |

:::tip
Многие инциденты начинаются не со сложной технической атаки, а с простой человеческой ошибки и мошенничества. Поэтому обучение сотрудников — одна из самых дешёвых и эффективных мер.
:::

## Методы защиты

| Группа | Меры |
|---|---|
| **Правовые** | законы, пункты о конфиденциальности в договорах, ответственность |
| **Организационные** | политика безопасности, роли и ответственные, обучение сотрудников, план реагирования на инциденты, немедленное закрытие учётной записи уволившегося сотрудника |
| **Технические и программные** | аутентификация, права доступа, шифрование (S14), антивирус, межсетевой экран (firewall), обновления, резервные копии, журналы |
| **Физические** | ограничение доступа в серверную, видеонаблюдение, источник бесперебойного питания (ИБП), пожарная безопасность |

## Основные технические меры

- **Аутентификация** — подтверждение личности пользователя. Длинные уникальные пароли (с менеджером паролей), **многофакторная аутентификация (MFA)**: пароль + код с телефона или подтверждение в приложении.
- **Права доступа** — принцип **минимальных привилегий**: каждый сотрудник видит только данные, нужные для работы (кассир не видит бухгалтерских отчётов).
- **Обновления** — известные ошибки ОС и программ исправляются обновлениями; устаревшая система — открытая дверь.
- **Резервные копии** — **правило 3-2-1**: 3 копии данных, на 2 разных носителях, 1 из них в другом месте (например, в облаке или офлайн). Восстановление из резервной копии нужно регулярно проверять.
- **Шифрование** — шифруются диски ноутбуков, резервные копии и сетевой трафик (HTTPS).
- **Журналы и мониторинг** — запись, кто, когда и к чему получал доступ, выявление подозрительных событий.

## Экономическая оценка рисков

**Риск** = вероятность инцидента × ущерб. Широко используемые в экономической оценке показатели:

| Показатель | Формула | Смысл |
|---|---|---|
| **SLE** (ущерб от одного случая) | стоимость актива × доля ущерба | сколько стоит один инцидент |
| **ARO** (годовая частота) | сколько раз в год ожидается | 0,5 = раз в два года |
| **ALE** (ожидаемые годовые потери) | SLE × ARO | сколько теряем в среднем за год |
| **ROSI** (рентабельность инвестиций в безопасность) | (снижение ALE − стоимость меры) / стоимость меры × 100% | окупается ли мера |

## Разобранный пример: выбор мер защиты

Компания рассматривает меры против четырёх угроз. В каждой строке: угроза, ущерб от одного инцидента (SLE, сум), частота до и после меры (**раз за 10 лет**), годовая стоимость меры. Для каждой угрозы вычислите ALE до и после, годовую выгоду и ROSI; если ROSI положителен — внедрить меру, иначе — пересмотреть.

```python
import sys

for satr in sys.stdin.read().split("\n"):
    if not satr.strip():
        continue
    nom, sle, oldin, keyin, narx = satr.split()
    sle, oldin, keyin, narx = int(sle), int(oldin), int(keyin), int(narx)
    ale_oldin = sle * oldin // 10                     # ожидаемые годовые потери
    ale_keyin = sle * keyin // 10
    foyda = ale_oldin - ale_keyin                     # предотвращённые потери за год
    rosi = (foyda - narx) * 100 // narx               # в процентах
    qaror = "внедрить" if rosi > 0 else "пересмотреть"
    print(f"{nom}: ALE {ale_oldin} -> {ale_keyin}, выгода {foyda}, ROSI {rosi}%, {qaror}")
```
```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        while (in.hasNext()) {
            String nom = in.next();
            long sle = in.nextLong(), oldin = in.nextLong(), keyin = in.nextLong(), narx = in.nextLong();
            long aleOldin = sle * oldin / 10;                  // ожидаемые годовые потери
            long aleKeyin = sle * keyin / 10;
            long foyda = aleOldin - aleKeyin;                  // предотвращённые потери за год
            long rosi = (foyda - narx) * 100 / narx;           // в процентах
            String qaror = rosi > 0 ? "внедрить" : "пересмотреть";
            System.out.println(nom + ": ALE " + aleOldin + " -> " + aleKeyin + ", выгода " + foyda + ", ROSI " + rosi + "%, " + qaror);
        }
    }
}
```
```cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    string nom;
    long long sle, oldin, keyin, narx;
    while (cin >> nom >> sle >> oldin >> keyin >> narx) {
        long long aleOldin = sle * oldin / 10;                 // ожидаемые годовые потери
        long long aleKeyin = sle * keyin / 10;
        long long foyda = aleOldin - aleKeyin;                 // предотвращённые потери за год
        long long rosi = (foyda - narx) * 100 / narx;          // в процентах
        string qaror = rosi > 0 ? "внедрить" : "пересмотреть";
        cout << nom << ": ALE " << aleOldin << " -> " << aleKeyin << ", выгода " << foyda
             << ", ROSI " << rosi << "%, " << qaror << "\n";
    }
    return 0;
}
```

Ввод:

```text
phishing 20000000 30 6 30000000
ransomware 300000000 2 1 40000000
outage 50000000 10 4 12000000
laptop 15000000 8 2 10000000
```

Вывод:

```text
phishing: ALE 60000000 -> 12000000, выгода 48000000, ROSI 60%, внедрить
ransomware: ALE 60000000 -> 30000000, выгода 30000000, ROSI -25%, пересмотреть
outage: ALE 50000000 -> 20000000, выгода 30000000, ROSI 150%, внедрить
laptop: ALE 12000000 -> 3000000, выгода 9000000, ROSI -10%, пересмотреть
```

Обучение сотрудников против фишинга (ROSI 60%) и резервное электропитание (150%) явно окупаются. Мера против ransomware по расчёту отрицательна — но осторожно: ALE описывает «средний» год, а один инцидент стоит 300 млн сумов, то есть может остановить компанию. Для таких редких, но катастрофических рисков нужно искать более дешёвую меру (например, резервные копии по правилу 3-2-1) или застраховать риск. Для ноутбуков можно пересчитать с более дешёвым решением — шифрованием диска.

## Стратегии реагирования на риск

| Стратегия | Содержание | Пример |
|---|---|---|
| **Снижение** | внедрить меру защиты | MFA, резервные копии |
| **Передача** | передать риск другому | киберстрахование, передача сервиса провайдеру |
| **Принятие** | ущерб мал, мера дорога | поломка старого принтера |
| **Уклонение** | отказаться от рискованной деятельности | не собирать ненужные данные |

## Политика безопасности и законодательство

**Политика безопасности** — письменные правила организации: пароли, устройства, категории данных и доступ к ним, резервное копирование, кого уведомлять об инцидентах. Международный стандарт — **ISO/IEC 27001** (система менеджмента информационной безопасности).

**В Узбекистане**: законы «Об информатизации», «О персональных данных», «О кибербезопасности»; действуют уполномоченный орган в сфере кибербезопасности и центр реагирования на киберинциденты. Организация несёт ответственность за утечку персональных данных.

:::warning
**Частые ошибки**

- **Думать «у нас нечего красть».** Малые компании тоже становятся целями фишинга и программ-вымогателей.
- **Не проверять резервные копии.** Копия, из которой нельзя восстановиться, — не копия.
- **Давать всем права администратора.** Одна ошибка или взломанная учётная запись затрагивает всю систему.
- **Опираться только на технические меры.** Необученный сотрудник может обойти даже лучшую защиту.
- **Оценивать риски только по ALE.** Редкие, но катастрофические инциденты рассматривайте отдельно.
:::

:::tip
Как изменится ROSI для угрозы «laptop» из примера, если взять меру — шифрование диска стоимостью 5 000 000 сумов в год (частота после меры — 2 раза за 10 лет)? Посчитайте.
:::

## Итоги

- Информационная безопасность — обеспечение конфиденциальности, целостности и доступности.
- Угрозы: человеческая ошибка, мошенничество, вредоносные программы, внутренние угрозы, сбои, природные события.
- Методы защиты: правовые, организационные, технические и программные, физические.
- Основные меры: MFA, минимальные привилегии, обновления, резервные копии 3-2-1, шифрование, обучение сотрудников.
- Риск оценивается экономически: ALE = SLE × ARO, ROSI показывает, окупается ли мера.

## Проверьте себя

:::check
Q: Каковы три основных свойства информационной безопасности?
A: Конфиденциальность, целостность и доступность.
Q: Что означает принцип минимальных привилегий?
A: Каждый пользователь имеет доступ только к данным и функциям, необходимым для работы.
Q: Что такое правило резервного копирования 3-2-1?
A: 3 копии данных, на 2 разных носителях, 1 из них хранится в другом месте.
Q: Если SLE = 40 млн сумов, а ARO = 0,5, чему равен ALE?
A: 40 млн × 0,5 = 20 млн сумов в год.
:::
