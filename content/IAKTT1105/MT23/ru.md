## Цель самостоятельной работы

Пример в M12 показал, как блоки связываются в цепочку через хеши. Но в реальном блокчейне есть и другие вопросы: кто и как подтверждает транзакцию, как тысячи транзакций в блоке превращаются в «один хеш», как договариваются незнакомые участники? Эта самостоятельная работа поэтапно показывает **внутренний принцип работы** блокчейна.

:::note
**После этой самостоятельной работы вы сможете:**

- объяснять путь транзакции от создания до подтверждения;
- называть элементы заголовка блока;
- показывать, зачем нужно дерево Меркла;
- сравнивать Proof of Work и Proof of Stake.
:::

## Жизненный цикл транзакции

1. **Создание**: Али хочет перевести Вали 500 единиц; программа-кошелёк создаёт транзакцию.
2. **Подпись**: транзакция подписывается **закрытым ключом** Али (S14). Любой может проверить подпись открытым ключом Али, но никто не может создать поддельную транзакцию от его имени.
3. **Распространение**: транзакция отправляется узлам сети; каждый узел проверяет подпись и остаток.
4. **Очередь ожидания** (mempool): прошедшие проверку транзакции ждут включения в блок; заплатившие большую комиссию обычно включаются быстрее.
5. **Включение в блок**: создатель блока (майнер или валидатор) собирает транзакции в блок и по правилам консенсуса предлагает его сети.
6. **Подтверждения**: по мере добавления новых блоков сверху изменить транзакцию становится практически невозможно. В Bitcoin обычно достаточными считаются 6 подтверждений.

## Структура блока

| Часть | Элемент | Назначение |
|---|---|---|
| **Заголовок** | хеш предыдущего блока | связь в цепочку (M12) |
| | корень Меркла | единый «отпечаток» всех транзакций блока |
| | метка времени | время создания блока |
| | сложность | цель для доказательства работы (PoW) |
| | nonce | число, подбираемое для выполнения условия сложности |
| **Тело** | список транзакций | подписанные переводы |

## Дерево Меркла

Транзакции хешируются попарно, результаты снова хешируются попарно — наверху остаётся один **корень Меркла**:

```text
                 корень = H(H12 + H34)
                /                    \
        H12 = H(H1 + H2)        H34 = H(H3 + H4)
         /         \              /         \
   H1 = H(tx1)  H2 = H(tx2)  H3 = H(tx3)  H4 = H(tx4)
```

**Зачем оно нужно?**

- Если меняется одна транзакция, меняется и корень — заголовок блока защищает всё тело.
- **Краткое доказательство**: чтобы проверить, что транзакция есть в блоке, нужны не все транзакции, а только «соседние» хеши на пути — всего ~20 хешей для 1 000 000 транзакций (идея log n из MT10). Поэтому кошельки в телефоне работают без загрузки всего блокчейна.

## Механизмы консенсуса

| Механизм | Кто создаёт блок | На чём основана безопасность | Недостаток |
|---|---|---|---|
| **Proof of Work** (доказательство работы) | майнер, первым решивший сложную вычислительную задачу | большая часть вычислительной мощности у честных участников | очень много электроэнергии |
| **Proof of Stake** (доказательство доли) | случайно выбранный валидатор пропорционально внесённому залогу | валидаторы боятся потерять залог (при нарушении он урезается) | сильнее влияние крупных владельцев |
| **Согласие с разрешениями** (типа BFT) | голосуют одобренные участники | честность более чем определённой доли участников | ограниченное число участников |

**Идея доказательства работы**: хеш заголовка блока должен удовлетворять определённому условию (например, несколько нулей в начале). Поскольку хеш нельзя предсказать, остаётся только перебирать nonce один за другим. При увеличении требуемого числа нулей на один среднее число попыток растёт в 16 раз (в шестнадцатеричной записи). Проверка же требует одного вычисления хеша — **создать трудно, проверить легко**.

**Подстройка сложности**: в Bitcoin сложность меняется каждые 2 016 блоков так, чтобы блок создавался в среднем раз в 10 минут — если мощность сети растёт, растёт и сложность.

## Разобранный пример: корень Меркла и доказательство работы

В каждой строке — одна транзакция. Вычислите корень Меркла, затем для заголовка `предыдущий|корень|nonce` найдите наименьший nonce, хеш которого начинается с 1, 2 и 3 нулей. В учебных целях используется хеш-функция FNV-1a из M12 (в реальных системах — SHA-256).

```python
import sys

def fnv1a(matn):                                     # учебная хеш-функция (в реальных системах SHA-256)
    h = 2166136261
    for b in matn.encode("utf-8"):
        h = ((h ^ b) * 16777619) & 0xFFFFFFFF
    return format(h, "08x")

tranzaksiyalar = [s.strip() for s in sys.stdin.read().split("\n") if s.strip()]
daraja = [fnv1a(t) for t in tranzaksiyalar]
while len(daraja) > 1:
    if len(daraja) % 2 == 1:
        daraja.append(daraja[-1])                    # если нечётно, последний повторяется
    daraja = [fnv1a(daraja[i] + daraja[i + 1]) for i in range(0, len(daraja), 2)]
ildiz = daraja[0]
print(f"Корень Меркла: {ildiz}")

for q in range(1, 4):                                # доказательство работы: q нулей в начале
    nonce = 0
    while True:
        xesh = fnv1a(f"00000000|{ildiz}|{nonce}")
        if xesh.startswith("0" * q):
            break
        nonce += 1
    print(f"сложность {q}: nonce {nonce}, хеш {xesh}, попыток {nonce + 1}")
```
```java
import java.nio.charset.StandardCharsets;
import java.util.ArrayList;
import java.util.List;
import java.util.Scanner;

public class Main {
    static String fnv1a(String matn) {                       // учебная хеш-функция (в реальных системах SHA-256)
        long h = 2166136261L;
        for (byte b : matn.getBytes(StandardCharsets.UTF_8)) h = ((h ^ (b & 0xff)) * 16777619L) & 0xFFFFFFFFL;
        return String.format("%08x", h);
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        List<String> daraja = new ArrayList<>();
        while (in.hasNextLine()) {
            String s = in.nextLine().trim();
            if (!s.isEmpty()) daraja.add(fnv1a(s));
        }
        while (daraja.size() > 1) {
            if (daraja.size() % 2 == 1) daraja.add(daraja.get(daraja.size() - 1));   // если нечётно, последний повторяется
            List<String> keyingi = new ArrayList<>();
            for (int i = 0; i < daraja.size(); i += 2) keyingi.add(fnv1a(daraja.get(i) + daraja.get(i + 1)));
            daraja = keyingi;
        }
        String ildiz = daraja.get(0);
        System.out.println("Корень Меркла: " + ildiz);

        for (int q = 1; q <= 3; q++) {                       // доказательство работы: q нулей в начале
            long nonce = 0;
            String xesh;
            while (true) {
                xesh = fnv1a("00000000|" + ildiz + "|" + nonce);
                if (xesh.startsWith("0".repeat(q))) break;
                nonce++;
            }
            System.out.println("сложность " + q + ": nonce " + nonce + ", хеш " + xesh + ", попыток " + (nonce + 1));
        }
    }
}
```
```cpp
#include <cstdint>
#include <cstdio>
#include <iostream>
#include <string>
#include <vector>
using namespace std;

string fnv1a(const string& matn) {                           // учебная хеш-функция (в реальных системах SHA-256)
    uint64_t h = 2166136261ULL;
    for (unsigned char b : matn) h = ((h ^ b) * 16777619ULL) & 0xFFFFFFFFULL;
    char buf[16];
    snprintf(buf, sizeof buf, "%08llx", (unsigned long long) h);
    return buf;
}

int main() {
    vector<string> daraja;
    string s;
    while (getline(cin, s)) {
        size_t a = s.find_first_not_of(" \t\r"), b = s.find_last_not_of(" \t\r");
        if (a != string::npos) daraja.push_back(fnv1a(s.substr(a, b - a + 1)));
    }
    while (daraja.size() > 1) {
        if (daraja.size() % 2 == 1) daraja.push_back(daraja.back());   // если нечётно, последний повторяется
        vector<string> keyingi;
        for (size_t i = 0; i < daraja.size(); i += 2) keyingi.push_back(fnv1a(daraja[i] + daraja[i + 1]));
        daraja = keyingi;
    }
    string ildiz = daraja[0];
    cout << "Корень Меркла: " << ildiz << "\n";

    for (int q = 1; q <= 3; q++) {                           // доказательство работы: q нулей в начале
        long long nonce = 0;
        string xesh;
        while (true) {
            xesh = fnv1a("00000000|" + ildiz + "|" + to_string(nonce));
            if (xesh.compare(0, q, string(q, '0')) == 0) break;
            nonce++;
        }
        cout << "сложность " << q << ": nonce " << nonce << ", хеш " << xesh << ", попыток " << nonce + 1 << "\n";
    }
    return 0;
}
```

Вывод:

Наблюдения:

- В среднем ожидается ~16 попыток для 1 нуля, ~256 для 2 и ~4 096 для 3. На этот раз для 1 нуля понадобилось 211 попыток — невезение: доказательство работы — случайный процесс, заранее известна лишь **средняя** сложность.
- Попробуйте заменить первую транзакцию на «Ali->Vali 900»: корень Меркла станет `2b924064`, а все nonce изменятся на совершенно другие значения. Подделка одной транзакции требует заново «добыть» блок — и все блоки после него.
- Проверяющему, если nonce известен, достаточно одного вычисления хеша.

## Ветвление цепочки и окончательность

Если два майнера одновременно найдут блок, цепочка временно **разветвляется** (fork). Узлы выбирают цепочку, в которую вложено больше всего работы (обычно самую длинную); блок короткой ветки отбрасывается, а его транзакции возвращаются в очередь. Поэтому в PoW окончательность **вероятностная**: с ростом числа подтверждений вероятность отмены транзакции резко падает. В согласии BFT в сетях с разрешениями окончательность **немедленная**: принятый блок не отменяется.

Безопасность системы опирается на одно ключевое условие: **большая часть** вычислительной мощности (PoW) или залога (PoS) должна принадлежать честным участникам. Поэтому небольшие сети уязвимее крупных.

:::warning
**Частые ошибки**

- **Думать, что «майнер может подделать транзакцию».** Без подписи он не может создать транзакцию; он лишь выбирает порядок и что включить.
- **Считать одно подтверждение окончательным.** Для крупных сумм ждут нескольких подтверждений.
- **Путать корень Меркла с простым хешем списка.** Дерево позволяет краткие доказательства.
- **Считать PoS «бесплатной безопасностью».** Он тоже опирается на экономические стимулы и залог.
:::

## Итоги

- Транзакция: создание → подпись → распространение → очередь → блок → подтверждения.
- Заголовок блока: предыдущий хеш, корень Меркла, время, сложность, nonce.
- Дерево Меркла защищает все транзакции одним корнем и даёт краткие доказательства.
- Консенсус: PoW (вычисления), PoS (залог), BFT с разрешениями; доказательство работы — создать трудно, проверить легко.
- В PoW окончательность вероятностная, в BFT — немедленная; безопасность опирается на честное большинство.

:::check
Q: Кто и каким ключом подписывает транзакцию?
A: Отправитель своим закрытым ключом; другие проверяют подпись его открытым ключом.
Q: Что такое корень Меркла?
A: Один хеш, полученный многократным попарным хешированием всех транзакций блока.
Q: Почему доказательство работы — «создать трудно, проверить легко»?
A: Чтобы найти nonce, удовлетворяющий условию, нужно много попыток, а для проверки достаточно одного вычисления хеша.
Q: Почему валидатор в Proof of Stake действует честно?
A: При нарушении правил он теряет внесённый залог.
