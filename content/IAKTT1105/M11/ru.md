## Почему эта тема важна?

Сегодня облачными сервисами пользуются и небольшой магазин, и крупный банк: почта и документы (Microsoft 365, Google Workspace), бухгалтерия и CRM (SaaS), серверы для сайтов и приложений. Облако позволяет предприятию получать ресурсы по мере необходимости и платить только за использованное, не покупая собственные серверы. Для экономиста главный вопрос — когда облако выгодно и какие у него риски.

## Понятие облачных вычислений

**Облачные вычисления** — модель быстрого и удобного доступа по сети, по требованию, к вычислительным ресурсам (серверы, память, программы). По NIST пять основных характеристик:

| Характеристика | Смысл |
|---|---|
| **Самообслуживание по требованию** | клиент сам заказывает ресурс без участия оператора |
| **Широкий сетевой доступ** | с любого устройства через интернет |
| **Объединение ресурсов** | ресурсы провайдера распределяются между многими клиентами |
| **Быстрая эластичность** | при росте нагрузки расширяется, при снижении сокращается |
| **Измеряемая услуга** | использование учитывается и оплачивается соответственно |

## Модели обслуживания

| Модель | Что даёт провайдер | Чем управляет клиент | Пример |
|---|---|---|---|
| **IaaS** (инфраструктура) | виртуальные серверы, хранилище, сеть | ОС, программы, данные | AWS EC2, Azure Virtual Machines |
| **PaaS** (платформа) | ОС, базы данных, среда выполнения | своё приложение и данные | Google App Engine, Azure App Service, управляемые СУБД |
| **SaaS** (программа) | готовая программа через браузер или приложение | только данные и настройки | Microsoft 365, Google Workspace, Salesforce, онлайн-бухгалтерия |
| **FaaS** (функции) | код запускается только при поступлении события | функции кода | AWS Lambda |

Простая аналогия — «пицца как услуга»: печёшь сам (собственный сервер), арендуешь готовое тесто и печь (IaaS), заказываешь доставку и ешь дома (PaaS), ешь в ресторане (SaaS).

## Модели развёртывания

| Модель | Описание | Для кого |
|---|---|---|
| **Публичное облако** | инфраструктура провайдера для многих клиентов | стартапы, малый и средний бизнес |
| **Частное облако** | только для одной организации (у неё или у провайдера) | банки, госорганы, конфиденциальные данные |
| **Гибридное облако** | публичное и частное вместе | конфиденциальные данные — в частном, пиковая нагрузка — в публичном |
| **Общественное облако** | для группы организаций с общими требованиями | госведомства, медицинские учреждения |

**Провайдеры**: глобальные — Amazon Web Services, Microsoft Azure, Google Cloud; местные — ЦОД в Узбекистане и облачные услуги телеком-операторов. По Закону «О персональных данных» персональные данные граждан Узбекистана должны храниться на серверах на территории страны — это влияет на выбор провайдера.

## Экономические аспекты

| Преимущество | Пояснение |
|---|---|
| **CAPEX → OPEX** | ежемесячная плата вместо крупных начальных вложений (M2) |
| **Плати за использование** | при сезонной нагрузке (например, «чёрная пятница») платишь только за дополнительные ресурсы |
| **Быстрый старт** | сервер готов за минуты, а не месяцы |
| **Масштабирование** | ресурсы наращиваются по мере роста бизнеса |
| **Снижение затрат на специалистов** | оборудованием и ЦОД управляет провайдер |

| Риск | Пояснение |
|---|---|
| **Удорожание в долгосрочной перспективе** | при постоянной большой нагрузке собственный сервер может быть дешевле (пример TCO в M2) |
| **Зависимость от провайдера** (vendor lock-in) | переход к другому провайдеру сложен и дорог |
| **Зависимость от интернета** | пропала связь — нет и сервиса |
| **Расположение данных и конфиденциальность** | требования закона, доступ третьих лиц |
| **Контроль затрат** | забытые ресурсы увеличивают счёт — нужны бюджетные оповещения |

## Модель разделённой ответственности

В облаке безопасность **распределяется между провайдером и клиентом**: провайдер защищает инфраструктуру (здания, оборудование, сеть, виртуализацию), клиент — свои данные, пользователей и права доступа, настройки. В SaaS доля клиента наименьшая, в IaaS — наибольшая. Многие утечки данных происходят не по вине провайдера, а из-за **ошибочной настройки клиента** (например, хранилище, оставленное открытым для всех) — подробно в MT21.

## Практическая работа: облачный офис

1. В Google Workspace или Microsoft 365 (OneDrive) создайте папку и откройте в ней таблицу и документ.
2. Дайте одному партнёру право **только на просмотр**, другому — на **редактирование**; посмотрите разницу между доступом по ссылке и доступом для конкретного человека.
3. Отредактируйте таблицу совместно и восстановите прежнее состояние из **истории версий**.
4. Включите двухэтапную аутентификацию в своей учётной записи.

:::warning
**Частые ошибки**

- **«В облаке — значит, безопасно и есть резервная копия».** За данные и права доступа отвечает клиент; проверяйте политику резервного копирования.
- **Делиться конфиденциальными файлами в режиме «всем, у кого есть ссылка».** Если ссылка распространится, прочитать смогут все.
- **Не следить за ресурсами и затратами.** Неиспользуемые серверы тоже стоят денег.
- **Не продумать стратегию выхода.** Заранее знайте, как и за сколько можно перенести данные в другое место.
:::

:::tip
В калькуляторах цен провайдеров (например, AWS Pricing Calculator) рассчитайте ежемесячные затраты на небольшой сайт и сравните их с затратами на собственный сервер методом TCO из M2.
:::

## Итоги

- Облачные вычисления — ресурсы по требованию через сеть: самообслуживание, широкий доступ, объединение ресурсов, эластичность, измеряемая услуга.
- Модели обслуживания: IaaS, PaaS, SaaS (и FaaS); развёртывание: публичное, частное, гибридное, общественное.
- Экономически: CAPEX → OPEX, плата за использование, быстрый старт; риски — удорожание, зависимость, конфиденциальность.
- Разделённая ответственность: провайдер — инфраструктура, клиент — данные, доступ и настройки.

## Проверьте себя

:::check
Q: Какая модель обслуживания означает использование готовой программы через браузер по подписке?
A: SaaS.
Q: Какая модель — аренда виртуальных серверов и хранилища?
A: IaaS.
Q: Что такое частное облако?
A: Облачная инфраструктура, выделенная только для одной организации.
Q: За что отвечает клиент в модели разделённой ответственности?
A: За свои данные, пользователей и права доступа, а также настройки.
