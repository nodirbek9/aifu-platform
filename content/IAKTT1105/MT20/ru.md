## «Всё как услуга» (XaaS)

| Модель | Что даёт провайдер | Чем управляет клиент | Пример |
|---|---|---|---|
| **IaaS** | виртуальные серверы, диски, сеть | ОС, программы, данные | Amazon EC2, Azure VM |
| **CaaS** (Containers) | платформа запуска контейнеров | образы контейнеров | сервисы Kubernetes (EKS, AKS, GKE) |
| **PaaS** | среда запуска приложений | код приложения и данные | Heroku, Google App Engine |
| **DBaaS** | управляемая база данных | таблицы и запросы | Amazon RDS, Azure SQL |
| **FaaS** (бессерверная) | выполнение функции по событию | только код функции | AWS Lambda, Azure Functions |
| **SaaS** | готовая программа | настройки и данные | Microsoft 365, Google Workspace, облачная CRM |
| **DaaS** (Desktop) | виртуальный рабочий стол | работа пользователя | Windows 365, Azure Virtual Desktop |
| **AIaaS** | готовые модели и API искусственного интеллекта | запросы и данные | распознавание речи, перевод, API языковых моделей |

Снизу вверх провайдер берёт на себя всё больше работы, а клиент управляет меньшим и имеет меньше гибкости.

## Базовые технологии

**Виртуализация** — на одном физическом сервере с помощью **гипервизора** работают несколько виртуальных машин (ВМ), у каждой своя операционная система. Это основа облака: провайдер делит физические ресурсы между многими клиентами.

**Контейнеры** (Docker) — приложение и его библиотеки упаковываются в одну «коробку»; контейнеры используют общее ядро ОС, поэтому легче ВМ и быстрее запускаются. **Kubernetes** — автоматическое управление тысячами контейнеров (запуск, масштабирование, восстановление при сбоях).

| | Виртуальная машина | Контейнер |
|---|---|---|
| Запуск | минуты | секунды |
| Размер | гигабайты | мегабайты |
| Изоляция | сильная (отдельная ОС) | легче (общее ядро) |
| Применение | старые приложения, разные ОС | микросервисы, современные приложения |

## Виды облачного хранения

| Вид | Устройство | Применение |
|---|---|---|
| **Блочное** | виртуальный диск, подключаемый к серверу | базы данных, диск ОС |
| **Файловое** | папки и файлы, общий сетевой диск | документы отдела, общие файлы |
| **Объектное** | файл + метаданные + уникальный адрес, неограниченный масштаб | резервные копии, архивы, фото и видео, озёра данных (MT9) |

В объектном хранении есть «классы»: часто используемые данные дороже, редко используемый архив (например, бухгалтерские документы, хранимые 7 лет) намного дешевле, но восстанавливается медленнее.

## Периферийные вычисления и мультиоблако

- **Периферийные вычисления** (edge computing) — обработка данных рядом с источником (завод, магазин, базовая станция): малая задержка (MT5), меньше сетевого трафика. Пример: камеры в магазине анализируют поток покупателей на месте и отправляют в облако только статистику.
- **Мультиоблако** (multi-cloud) — использование нескольких провайдеров: снижает зависимость от одного, но усложняет управление.
- **Гибридное облако** (M11) — конфиденциальные данные на своих серверах или в национальном ЦОД, остальное — в публичном облаке (требование локализации в S11).

## Модели цен

| Модель | Содержание | Когда выгодна |
|---|---|---|
| **По требованию** (on-demand) | за использованные часы или секунды | короткая или неравномерная нагрузка, тесты |
| **Резерв** (бронирование на 1–3 года) | большая скидка за обязательство заранее | постоянно работающие серверы |
| **Spot** (избыточные мощности) | очень дёшево, но провайдер может остановить в любой момент | расчёты, которым остановка не вредит |
| **Бессерверная** (по запросам) | только за выполненные функции и их время | редкие и случайно вызываемые задачи |
| **Подписка** (SaaS) | ежемесячно за пользователя | офис, CRM, бухгалтерия |

## Разобранный пример: по требованию или резерв?

Виртуальный сервер стоит по требованию 1 500 сумов в час или по резерву фиксированно 650 000 сумов в месяц. В каждой строке — имя сервера и сколько часов в месяц он работает. Определите точку безубыточности и более дешёвый вариант для каждого сервера.

```python
import sys

SOAT_NARXI = 1500       # по требованию, сумов/час
REZERV = 650000         # резерв, сумов/месяц (независимо от часов)

chegara = (REZERV + SOAT_NARXI - 1) // SOAT_NARXI    # округление вверх
print(f"Точка безубыточности (часов): {chegara}")
for satr in sys.stdin.read().split("\n"):
    if not satr.strip():
        continue
    nom, soat = satr.split()
    soat = int(soat)
    talab = soat * SOAT_NARXI
    tanlov = "по требованию" if talab <= REZERV else "резерв"
    print(f"{nom}: {soat} ч, по требованию {talab}, резерв {REZERV} -> {tanlov}")
```
```java
import java.util.Scanner;

public class Main {
    static final long SOAT_NARXI = 1500;      // по требованию, сумов/час
    static final long REZERV = 650000;        // резерв, сумов/месяц (независимо от часов)

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        long chegara = (REZERV + SOAT_NARXI - 1) / SOAT_NARXI;   // округление вверх
        System.out.println("Точка безубыточности (часов): " + chegara);
        while (in.hasNext()) {
            String nom = in.next();
            long soat = in.nextLong();
            long talab = soat * SOAT_NARXI;
            String tanlov = talab <= REZERV ? "по требованию" : "резерв";
            System.out.println(nom + ": " + soat + " ч, по требованию " + talab + ", резерв " + REZERV + " -> " + tanlov);
        }
    }
}
```
```cpp
#include <iostream>
#include <string>
using namespace std;

const long long SOAT_NARXI = 1500;      // по требованию, сумов/час
const long long REZERV = 650000;        // резерв, сумов/месяц (независимо от часов)

int main() {
    long long chegara = (REZERV + SOAT_NARXI - 1) / SOAT_NARXI;    // округление вверх
    cout << "Точка безубыточности (часов): " << chegara << "\n";
    string nom;
    long long soat;
    while (cin >> nom >> soat) {
        long long talab = soat * SOAT_NARXI;
        string tanlov = talab <= REZERV ? "по требованию" : "резерв";
        cout << nom << ": " << soat << " ч, по требованию " << talab << ", резерв " << REZERV << " -> " << tanlov << "\n";
    }
    return 0;
}
```

Ввод:

```text
test-server 120
report-server 400
crm-server 500
web-server 730
```

Вывод:

```text
Точка безубыточности (часов): 434
test-server: 120 ч, по требованию 180000, резерв 650000 -> по требованию
report-server: 400 ч, по требованию 600000, резерв 650000 -> по требованию
crm-server: 500 ч, по требованию 750000, резерв 650000 -> резерв
web-server: 730 ч, по требованию 1095000, резерв 650000 -> резерв
```

Для сервера, работающего больше 434 часов в месяц (~14 часов в день), выгоден резерв. Постоянно работающий веб-сервер (730 часов — весь месяц) по резерву экономит 445 000 сумов в месяц, 5,3 млн сумов в год. Тестовый сервер включается только в рабочее время и дёшев по требованию. Резерв — обязательство: он оплачивается, даже если сервер потом не нужен, поэтому нагрузку нужно анализировать заранее (FinOps в S11).

:::warning
**Частые ошибки**

- **Одна модель на всё.** Для постоянной нагрузки — резерв, для неравномерной — по требованию или бессерверная.
- **Не отключать неиспользуемые ресурсы.** «Забытый» сервер по требованию каждый месяц съедает деньги.
- **Хранить архив в дорогом классе хранения.** Переводите редко используемые данные в дешёвый класс.
- **Считать контейнер и ВМ одним и тем же.** Требования к изоляции и безопасности различаются.
:::

## Итоги

- XaaS: IaaS, CaaS, PaaS, DBaaS, FaaS, SaaS, DaaS, AIaaS — снизу вверх доля работы провайдера растёт.
- Основа: виртуализация (ВМ) и контейнеры (Docker, Kubernetes).
- Хранение: блочное, файловое, объектное; дешёвые классы для архивов.
- Периферийные вычисления, мультиоблако и гибрид — направления современной архитектуры.
- Модели цен: по требованию, резерв, spot, бессерверная, подписка; выбор — через точку безубыточности.

A: Контейнер использует общее ядро ОС, поэтому легче и быстрее запускается; у ВМ отдельная ОС и более сильная изоляция.

A: Только за число выполнений функции и их длительность.
Q: Какой вид хранения подходит для резервных копий?
A: Объектное хранение с дешёвым классом для редко используемых данных.
Q: В чём риск модели цены «резерв»?
A: Это обязательство — оно оплачивается, даже если ресурс перестал быть нужен.
