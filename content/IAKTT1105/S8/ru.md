## Цель семинара

На лекции M8 мы рассмотрели понятие и структуры алгоритмов. На семинаре потренируемся изображать алгоритм **графически** — в виде блок-схемы. Блок-схема — общий «язык» экономиста, программиста и руководителя: где в процессе принимаются решения и что повторяется, видно с первого взгляда. Затем превратим блок-схему в программу.

## Обозначения блок-схем

| Обозначение | Фигура | Смысл |
|---|---|---|
| **Начало / конец** | прямоугольник со скруглёнными углами (овал) | начало и конец алгоритма |
| **Ввод / вывод** | параллелограмм | ввод данных или вывод результата |
| **Процесс** | прямоугольник | вычисление, присваивание значения |
| **Решение** (условие) | ромб | вопрос «да/нет», два выхода |
| **Начало цикла** | шестиугольник (модификация) | параметры повторения |
| **Предопределённый процесс** | прямоугольник с двойными боковыми линиями | отдельно описанный вспомогательный алгоритм |
| **Соединитель** | круг | связь при разбиении большой схемы на части |
| **Линии потока** | стрелки | порядок выполнения (сверху вниз, слева направо) |

## Правила построения

- Один блок начала и хотя бы один блок конца.
- Из каждого блока (кроме решения) один выход; из решения — два выхода, чётко помеченные «да» и «нет».
- Линии не должны пересекаться; при необходимости используйте соединители.
- Надпись в блоке краткая и точная: `S ← n × p`, `n > 200?`.
- Цикл обязательно должен завершаться — проверьте, что условие цикла в итоге перестаёт выполняться.

## Три основные структуры на блок-схеме

**Линейная** (цена с НДС):

```text
( Начало ) → / ввод цены / → [ итог ← цена × 1,12 ] → / вывод итога / → ( Конец )
```

**Разветвляющаяся** (два пути в зависимости от условия):

```text
            / ввод значения /
                    |
              < условие выполнено? >
               да |          | нет
          [ расчёт 1 ]   [ расчёт 2 ]
                    \      /
              / вывод результата /
```

**Циклическая** (для каждого месяца):

```text
[ i ← 1, итог ← 0 ] → < i ≤ n ? > —нет→ / вывод итога /
                         | да
              [ итог ← итог + продажи(i) ]
              [ i ← i + 1 ] → (возврат к началу цикла)
```

## Разобранный пример: ступенчатый тариф на электроэнергию

Учебный пример (цены условные): до 200 кВт·ч в месяц — по 600 сумов, часть сверх 200 — по 1 000 сумов. Ступенчатый тариф поддерживает потребителей с малым расходом и стимулирует экономию.

Блок-схема:

```text
( Начало )
      |
/ ввод квт /
      |
< квт ≤ 200 ? >
 да |                         | нет
[ сумма ← квт × 600 ]   [ сумма ← 200 × 600 + (квт − 200) × 1000 ]
      \                      /
       / вывод суммы /
              |
          ( Конец )
```

Программа (повторяется для нескольких потребителей):

```python
import sys

CHEGARA, NARX1, NARX2 = 200, 600, 1000             # условный тариф для учебного примера

for t in sys.stdin.read().split():
    kvt = int(t)                                    # ввод
    if kvt <= CHEGARA:                              # условие (ромб)
        summa = kvt * NARX1
    else:
        summa = CHEGARA * NARX1 + (kvt - CHEGARA) * NARX2
    print(f"{kvt} кВт·ч: {summa} сум")          # вывод
```
```java
import java.util.Scanner;

public class Main {
    static final long CHEGARA = 200, NARX1 = 600, NARX2 = 1000;   // условный тариф для учебного примера

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        while (in.hasNextLong()) {
            long kvt = in.nextLong();                     // ввод
            long summa;
            if (kvt <= CHEGARA) {                         // условие (ромб)
                summa = kvt * NARX1;
            } else {
                summa = CHEGARA * NARX1 + (kvt - CHEGARA) * NARX2;
            }
            System.out.println(kvt + " кВт·ч: " + summa + " сум");   // вывод
        }
    }
}
```
```cpp
#include <iostream>
using namespace std;

const long long CHEGARA = 200, NARX1 = 600, NARX2 = 1000;          // условный тариф для учебного примера

int main() {
    long long kvt;
    while (cin >> kvt) {                                  // ввод
        long long summa;
        if (kvt <= CHEGARA) {                             // условие (ромб)
            summa = kvt * NARX1;
        } else {
            summa = CHEGARA * NARX1 + (kvt - CHEGARA) * NARX2;
        }
        cout << kvt << " кВт·ч: " << summa << " сум" << endl;   // вывод
    }
    return 0;
}
```

Ввод:

```text
150 200 201 350 0
```

Вывод:

```text
150 кВт·ч: 90000 сум
200 кВт·ч: 120000 сум
201 кВт·ч: 121000 сум
350 кВт·ч: 270000 сум
0 кВт·ч: 0 сум
```

Тестовые значения выбраны намеренно: сам порог (200), на единицу больше (201), значения ниже и выше порога, ноль. Граничные значения — место, где в разветвляющихся алгоритмах чаще всего прячутся ошибки (если написать «<» вместо «≤», 200 кВт·ч будут рассчитаны неверно).

## Средства

- **draw.io** (diagrams.net) — бесплатно, в браузере, с библиотекой фигур блок-схем.
- **Microsoft Visio**, **Lucidchart** — профессиональные диаграммы.
- **Фигуры Word/PowerPoint** и SmartArt — для простых схем.
- **Mermaid** — диаграммы из текста (в документации и вики).

## Практические задания

1. Нарисуйте блок-схему разобранного примера в draw.io и расширьте её до трёхступенчатого тарифа (например, до 200, 200–500, более 500).
2. Нарисуйте блок-схему программы «анализ месячных продаж» из M8 (два цикла).
3. Для задания платформы **«Разветвляющийся алгоритм: скидка на покупку»** сначала нарисуйте блок-схему (последовательность нескольких ромбов-условий), затем превратите её в программу. Тестовые данные для граничных значений составьте сами.
4. «Выполните» блок-схему, нарисованную напарником: пошагово рассчитайте результат для 3 входных значений и сравните с результатом программы.

:::warning
**Частые ошибки**

- **Рисовать один выход из условия.** Из ромба всегда выходят два пути: «да» и «нет».
- **Путь, не доходящий до блока конца.** Каждый путь в итоге должен прийти к концу.
- **Потеря граничного значения.** Разница между «≥» и «>» — самая частая ошибка.
- **Бесконечный цикл.** Если переменная цикла (i ← i + 1) не меняется, цикл не заканчивается.
- **Длинный текст в блоке.** Пишите короткую формулу, пояснение выносите в комментарий.
:::

:::tip
Лучший способ проверить блок-схему — «выполнить её на бумаге»: составьте таблицу (столбцы — переменные, строки — шаги) и записывайте значения после каждого блока.
:::

## Итоги

- Блок-схема — графическое представление алгоритма: овал (начало/конец), параллелограмм (ввод/вывод), прямоугольник (процесс), ромб (условие), шестиугольник (цикл), стрелки.
- Правила: одно начало, два выхода из условия, линии не пересекаются, цикл должен завершаться.
- Линейная, разветвляющаяся и циклическая структуры имеют одинаковую логику на блок-схеме и в программе.
- Проверка граничных значений — основной способ найти ошибки в разветвляющихся алгоритмах.
