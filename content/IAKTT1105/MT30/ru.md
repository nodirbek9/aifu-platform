## Инфраструктура открытых ключей (PKI)

В S14 мы видели, что сертификат подтверждает владельца открытого ключа. Но почему мы доверяем самому сертификату? На это отвечает **цепочка доверия**:

```text
Корневой удостоверяющий центр (Root CA)  — заранее установлен в ОС и браузере
        │ подписывает
Промежуточный удостоверяющий центр (Intermediate CA)
        │ подписывает
Сертификат пользователя или сайта (например, bank.uz)
```

При входе на сайт браузер проверяет цепочку снизу вверх: подписан ли сертификат сайта промежуточным центром, промежуточный — корневым, есть ли корневой в списке доверенных. Если какое-то звено не сходится, появляется предупреждение (S14).

## Жизненный цикл сертификата

| Этап | Содержание |
|---|---|
| **Запрос** | пользователь создаёт пару ключей и запрашивает сертификат с открытым ключом |
| **Проверка** | удостоверяющий центр проверяет лицо или организацию (документы, идентификация) |
| **Выдача** | центр подписывает открытый ключ вместе с данными владельца; устанавливается срок действия |
| **Использование** | подписание, шифрование, аутентификация |
| **Продление** | до истечения срока получают новый сертификат |
| **Отзыв** | при утере или краже ключа, увольнении сотрудника сертификат отзывается досрочно |

**Проверка отзыва**: **CRL** (список отозванных сертификатов) или **OCSP** (запрос статуса сертификата в реальном времени). Поэтому при утере ключа нужно немедленно сообщить в удостоверяющий центр — иначе подписи от имени владельца считаются действительными.

## ЭЦП в Узбекистане

- Ключи и сертификаты ЭЦП выдают уполномоченные **удостоверяющие центры** (для физических лиц и руководителей организаций).
- **Носитель** ключа: защищённый файл на компьютере, USB-токен или ID-карта; также **мобильная подпись** (через приложение на телефоне).
- **E-IMZO** — программа для работы с ЭЦП в браузере: подписание в налоговом кабинете (S15, MT31), госуслугах, системах банк-клиент, электронных счетах-фактурах.
- **Правила безопасности**: никому не передавать ключ и его пароль (за подписанный документ отвечает владелец ЭЦП); не оставлять USB-токен в компьютере; следить за сроком действия; при утере — немедленно отозвать.

## TLS: как браузер и сайт строят защищённый канал

1. Браузер подключается к сайту и сообщает поддерживаемые методы шифрования.
2. Сайт отправляет свой **сертификат**; браузер проверяет цепочку доверия и срок действия.
3. С помощью алгоритма **обмена ключами** стороны получают общий секретный **сеансовый ключ** — он не передаётся по сети.
4. Все дальнейшие данные шифруются **симметрично** этим ключом (гибридная схема из S14).

Результат: конфиденциальность (посторонний не прочтёт), целостность (нельзя изменить в пути) и подлинность сайта (сертификат).

## Безопасное хранение паролей

Система должна хранить не сам пароль, а его **хеш** (S14). Но простого хеша недостаточно:

- **Одинаковые пароли дают одинаковые хеши** — по базе видно, у кого одинаковый пароль; хеши популярных паролей есть в заранее составленных таблицах.
- **«Соль»** (salt) — случайное значение для каждого пользователя, добавляется к паролю перед хешированием и хранится вместе с хешем. В результате одинаковые пароли дают разные хеши, а готовые таблицы бесполезны.
- **Растяжение ключа** — хеширование повторяется тысячи раз или используется специальная медленная функция (**bcrypt, scrypt, Argon2**): одна проверка для пользователя незаметна, но перебор огромного числа вариантов становится намного дороже.

## Разобранный пример: хранение пароля с «солью»

Учебная программа: строка `reg логин соль пароль` регистрирует пользователя (хранится не пароль, а хеш `соль + пароль`, повторённый 1 000 раз), строка `login логин пароль` проверяет вход. Для наглядности используется FNV-1a из M12 — в реальных системах применяются только специальные функции вроде bcrypt, scrypt или Argon2, а соль создаётся генератором случайных чисел.

```python
import sys

TAKROR = 1000     # растяжение ключа (в реальных системах bcrypt, scrypt, Argon2)

def fnv1a(matn):                                     # учебная хеш-функция
    h = 2166136261
    for b in matn.encode("utf-8"):
        h = ((h ^ b) * 16777619) & 0xFFFFFFFF
    return format(h, "08x")

def xeshlash(tuz, parol):
    x = tuz + parol
    for _ in range(TAKROR):
        x = fnv1a(x)
    return x

ombor = {}                                           # логин -> (соль, хеш); сам пароль не хранится
for satr in sys.stdin.read().split("\n"):
    q = satr.split()
    if not q:
        continue
    if q[0] == "reg":
        _, login, tuz, parol = q
        ombor[login] = (tuz, xeshlash(tuz, parol))
        print(f"{login}: сохранено, соль {tuz}, хеш {ombor[login][1]}")
    else:
        _, login, parol = q
        saqlangan = ombor[login]
        togri = xeshlash(saqlangan[0], parol) == saqlangan[1]
        print(f"{login}: {'вход разрешён' if togri else 'неверный пароль'}")
```
```java
import java.nio.charset.StandardCharsets;
import java.util.HashMap;
import java.util.Map;
import java.util.Scanner;

public class Main {
    static final int TAKROR = 1000;     // растяжение ключа (в реальных системах bcrypt, scrypt, Argon2)

    static String fnv1a(String matn) {                               // учебная хеш-функция
        long h = 2166136261L;
        for (byte b : matn.getBytes(StandardCharsets.UTF_8)) h = ((h ^ (b & 0xff)) * 16777619L) & 0xFFFFFFFFL;
        return String.format("%08x", h);
    }

    static String xeshlash(String tuz, String parol) {
        String x = tuz + parol;
        for (int i = 0; i < TAKROR; i++) x = fnv1a(x);
        return x;
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        Map<String, String[]> ombor = new HashMap<>();               // логин -> (соль, хеш); сам пароль не хранится
        while (in.hasNextLine()) {
            String[] q = in.nextLine().trim().split("\\s+");
            if (q[0].isEmpty()) continue;
            if (q[0].equals("reg")) {
                ombor.put(q[1], new String[]{q[2], xeshlash(q[2], q[3])});
                System.out.println(q[1] + ": сохранено, соль " + q[2] + ", хеш " + ombor.get(q[1])[1]);
            } else {
                String[] saqlangan = ombor.get(q[1]);
                boolean togri = xeshlash(saqlangan[0], q[2]).equals(saqlangan[1]);
                System.out.println(q[1] + ": " + (togri ? "вход разрешён" : "неверный пароль"));
            }
        }
    }
}
```
```cpp
#include <cstdint>
#include <cstdio>
#include <iostream>
#include <map>
#include <sstream>
#include <string>
#include <utility>
using namespace std;

const int TAKROR = 1000;     // растяжение ключа (в реальных системах bcrypt, scrypt, Argon2)

string fnv1a(const string& matn) {                                   // учебная хеш-функция
    uint64_t h = 2166136261ULL;
    for (unsigned char b : matn) h = ((h ^ b) * 16777619ULL) & 0xFFFFFFFFULL;
    char buf[16];
    snprintf(buf, sizeof buf, "%08llx", (unsigned long long) h);
    return buf;
}

string xeshlash(const string& tuz, const string& parol) {
    string x = tuz + parol;
    for (int i = 0; i < TAKROR; i++) x = fnv1a(x);
    return x;
}

int main() {
    map<string, pair<string, string>> ombor;                         // логин -> (соль, хеш); сам пароль не хранится
    string satr;
    while (getline(cin, satr)) {
        istringstream ss(satr);
        string buyruq, login, a, b;
        if (!(ss >> buyruq)) continue;
        if (buyruq == "reg") {
            ss >> login >> a >> b;
            ombor[login] = {a, xeshlash(a, b)};
            cout << login << ": сохранено, соль " << a << ", хеш " << ombor[login].second << "\n";
        } else {
            ss >> login >> a;
            bool togri = xeshlash(ombor[login].first, a) == ombor[login].second;
            cout << login << ": " << (togri ? "вход разрешён" : "неверный пароль") << "\n";
        }
    }
    return 0;
}
```

Ввод:

```text
reg ali 7f3a Qwerty2026
reg vali 91c4 Qwerty2026
login ali Qwerty2026
login vali qwerty2026
```

Вывод:

```text
ali: сохранено, соль 7f3a, хеш c3fe1ad8
vali: сохранено, соль 91c4, хеш 70db8b04
ali: вход разрешён
vali: неверный пароль
```

Ali и Vali выбрали одинаковый пароль, но из-за разных солей хеши в базе совершенно разные — посмотревший базу этого не узнает. Vali написал пароль со строчной буквы — разница в один символ даёт совсем другой хеш, и вход отклонён. Система никогда не хранит сам пароль и не может «напомнить пароль» — можно лишь установить новый.

## Шифрование дисков, файлов и сообщений

- **Полное шифрование диска** (BitLocker, FileVault, шифрование в Android и iOS) — даже при утере ноутбука или телефона данные не прочитать (риск «laptop» в M14).
- **Шифрование архивов паролем** — при отправке файлов; пароль передавайте другим каналом (например, файл — по почте, пароль — по SMS).
- **Сквозное шифрование** (end-to-end) — в мессенджерах сообщение могут открыть только собеседники, даже сервер сервиса не может.

## Правила управления ключами

1. Ключи не хранятся открыто в коде, документах или письмах (MT21).
2. Отдельный ключ для каждой цели; регулярная смена.
3. Резервные копии ключей в надёжном месте — при утере ключа теряются и зашифрованные данные.
4. Учёт, у кого какие ключи; при увольнении сотрудника его ключи и сертификаты отзываются.

:::warning
**Частые ошибки**

- **Передавать ключ ЭЦП и пароль коллеге.** За подписанный документ отвечает владелец.
- **Не отзывать сертификат при утере ключа.**
- **Хранить пароли в открытом виде или как хеш без соли.**
- **Отправлять ключ шифрования вместе с зашифрованным файлом.**
- **Создавать «собственный шифр».** Только проверенные стандарты (S14).
:::

## Итоги

- Цепочка доверия PKI: корневой → промежуточный → сертификат пользователя; сертификаты выдаются, продлеваются и отзываются (CRL, OCSP).
- ЭЦП в Узбекистане: удостоверяющие центры, носители ключей, мобильная подпись, E-IMZO; ключ — личная ответственность владельца.
- TLS: проверка сертификата, обмен ключами, симметричное шифрование.
- Пароли хешируются с солью и растяжением ключа (bcrypt, scrypt, Argon2); диски, файлы и сообщения шифруются; ключи управляются по правилам.

A: Сертификат проверяется по цепочке доверия вплоть до корневого удостоверяющего центра, заранее установленного в браузере.
