## Электронный рынок

**Электронный рынок** — среда, в которой продавцы и покупатели договариваются о цене, количестве и условиях с помощью электронных средств.

| Вид | Как формируется цена | Пример |
|---|---|---|
| **Интернет-магазин** | продавец устанавливает фиксированную цену | сайт бренда |
| **Маркетплейс** | конкурируют многие продавцы | Uzum Market, Amazon (M13) |
| **Электронная биржа** | при встрече спроса и предложения | товарные и валютные биржи |
| **Аукцион** | покупатели повышают цену | eBay, торги конфискованным имуществом |
| **Обратный аукцион** | продавцы понижают цену | портал госзакупок, тендеры |
| **Площадка объявлений** | стороны договариваются между собой | C2C-сайты вроде OLX |

## Электронные товары

**Электронный (цифровой) товар** — товар, создаваемый, хранимый и доставляемый в цифровом виде: программы и приложения, электронные книги, музыка и видео, онлайн-курсы, шрифты и шаблоны, внутриигровые предметы, базы данных, цифровые билеты.

### Экономические свойства

| Свойство | Содержание | Следствие |
|---|---|---|
| **Высокие начальные и почти нулевые предельные издержки** | первая копия дорогая (разработка), следующие почти бесплатны | цену определяет ценность для покупателя, а не себестоимость |
| **Неконкурентность** | использование одной копии не мешает другим | копировать легко — нужна защита |
| **Товар опыта** | качество можно узнать только после использования | важны бесплатная проба, образцы, отзывы |
| **Сетевой эффект** | ценность растёт с числом пользователей (MT6) | «победитель получает почти всё» |
| **Эффект привязки** (lock-in) | затраты на переход к другому товару (файлы, привычки) | лояльность и сильная рыночная позиция |

## Стратегии ценообразования

| Стратегия | Содержание | Пример |
|---|---|---|
| **Версионирование** | версии одного продукта с разными возможностями по разной цене | «Базовая», «Pro», «Бизнес» |
| **Набор** (бандлинг) | несколько товаров вместе дешевле суммы раздельных цен | офисный пакет, стриминг + музыка |
| **Freemium** | базовые функции бесплатно, расширенные — платно | 15 ГБ облачного хранилища бесплатно |
| **Подписка** | ежемесячная или годовая плата, постоянный доступ | онлайн-кинотеатр, SaaS (M11) |
| **Динамическая цена** | меняется в зависимости от спроса, времени, клиента | авиабилеты, такси |
| **Микроплатежи** | небольшие суммы внутри приложения | внутриигровые предметы |

**Почему набор выгоден?** Покупатели ценят товары по-разному: один высоко ценит первый товар и низко второй, другой — наоборот. При раздельной продаже продавец должен выбрать одну цену на каждый товар и теряет часть покупателей. В наборе оценки складываются и сближаются — одной ценой можно охватить больше покупателей. Для цифровых товаров, где дополнительная копия почти бесплатна, эта стратегия особенно эффективна.

## Разобранный пример: раздельно или набором?

В каждой строке — покупатель и его оценка товаров A и B (тыс. сумов). Найдите для каждого товара цену, максимизирующую выручку (при равенстве — более высокую цену), затем лучшую цену набора и сравните. Покупатель покупает, если его оценка не ниже цены.

```python
import sys

def eng_yaxshi(qadrlar):
    # максимальная выручка; при равенстве — более высокая цена
    narx, eng_tushum = 0, 0
    for p in sorted(set(qadrlar)):
        t = p * sum(1 for q in qadrlar if q >= p)
        if t >= eng_tushum:
            narx, eng_tushum = p, t
    return narx, eng_tushum

a, b = [], []
for satr in sys.stdin.read().split("\n"):
    if not satr.strip():
        continue
    _, qa, qb = satr.split()
    a.append(int(qa))
    b.append(int(qb))

na, ta = eng_yaxshi(a)
nb, tb = eng_yaxshi(b)
nt, tt = eng_yaxshi([x + y for x, y in zip(a, b)])     # ценность набора для каждого покупателя
print(f"Товар A: цена {na}, выручка {ta}")
print(f"Товар B: цена {nb}, выручка {tb}")
print(f"Раздельная продажа: {ta + tb}")
print(f"Набор: цена {nt}, выручка {tt}")
print(f"Рекомендация: {'набор' if tt > ta + tb else 'раздельно'}")
```
```java
import java.util.ArrayList;
import java.util.List;
import java.util.Scanner;
import java.util.TreeSet;

public class Main {
    static long[] engYaxshi(List<Long> qadrlar) {
        // максимальная выручка; при равенстве — более высокая цена
        long narx = 0, engTushum = 0;
        for (long p : new TreeSet<>(qadrlar)) {
            long soni = 0;
            for (long q : qadrlar) if (q >= p) soni++;
            if (p * soni >= engTushum) { narx = p; engTushum = p * soni; }
        }
        return new long[]{narx, engTushum};
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        List<Long> a = new ArrayList<>(), b = new ArrayList<>(), t = new ArrayList<>();
        while (in.hasNext()) {
            in.next();
            long qa = in.nextLong(), qb = in.nextLong();
            a.add(qa);
            b.add(qb);
            t.add(qa + qb);                                  // ценность набора для каждого покупателя
        }
        long[] ra = engYaxshi(a), rb = engYaxshi(b), rt = engYaxshi(t);
        System.out.println("Товар A: цена " + ra[0] + ", выручка " + ra[1]);
        System.out.println("Товар B: цена " + rb[0] + ", выручка " + rb[1]);
        System.out.println("Раздельная продажа: " + (ra[1] + rb[1]));
        System.out.println("Набор: цена " + rt[0] + ", выручка " + rt[1]);
        System.out.println("Рекомендация: " + (rt[1] > ra[1] + rb[1] ? "набор" : "раздельно"));
    }
}
```

```cpp
#include <string>

pair<long long, long long> engYaxshi(const vector<long long>& qadrlar) {
    // максимальная выручка; при равенстве — более высокая цена
    long long narx = 0, engTushum = 0;
    for (long long p : set<long long>(qadrlar.begin(), qadrlar.end())) {
        long long soni = 0;
        for (long long q : qadrlar) if (q >= p) soni++;
        if (p * soni >= engTushum) { narx = p; engTushum = p * soni; }
    }
    return {narx, engTushum};
}

int main() {
    vector<long long> a, b, t;
    string ism;
    long long qa, qb;
    while (cin >> ism >> qa >> qb) {
        a.push_back(qa);
        b.push_back(qb);
        t.push_back(qa + qb);                                // ценность набора для каждого покупателя
    }
    auto ra = engYaxshi(a), rb = engYaxshi(b), rt = engYaxshi(t);
    cout << "Товар A: цена " << ra.first << ", выручка " << ra.second << "\n";
    cout << "Товар B: цена " << rb.first << ", выручка " << rb.second << "\n";
    cout << "Раздельная продажа: " << ra.second + rb.second << "\n";
    cout << "Набор: цена " << rt.first << ", выручка " << rt.second << "\n";
    cout << "Рекомендация: " << (rt.second > ra.second + rb.second ? "набор" : "раздельно") << "\n";
    return 0;
```

При раздельной продаже каждый товар покупают только двое (A — Ali и Sardor, B — Vali и Sardor). При цене набора 150 его покупают Ali (150), Vali (150) и Sardor (180) — выручка растёт на 25%. Вкусы Ali и Vali противоположны, но набор они ценят одинаково — в этом «магия» набора. Только Kamola (110) не покупает ни в одном случае.

## Двусторонние платформы

Маркетплейс, приложение такси, платёжная система — **двусторонние рынки**: они связывают две группы (продавцов и покупателей, водителей и пассажиров). Чем больше участников на одной стороне, тем ценнее платформа для другой (перекрёстный сетевой эффект). Поэтому платформы часто субсидируют одну сторону: бесплатная доставка для покупателей, бонусы для водителей, — а плату (комиссию) берут с другой.

## Авторское право и права потребителей

- **Авторское право**: цифровой товар легко копировать; незаконное распространение (пиратство) снижает доходы авторов. **DRM** (управление цифровыми правами) технически ограничивает копирование и распространение, но может создавать неудобства законным покупателям. Дешёвые и удобные легальные сервисы (подписка) оказались эффективным способом снизить пиратство.
- **Лицензия и собственность**: при покупке цифрового товара часто приобретается **лицензия на использование**, а не сам товар — при закрытии платформы доступ может пропасть.
- **Права потребителей**: точное описание товара, показ условий до оплаты, возможность легко отменить автоматическую подписку.

:::warning
**Частые ошибки**

- **Назначать цену цифрового товара от себестоимости.** Предельные издержки почти нулевые — цена определяется ценностью и конкуренцией.
- **Считать набор всегда выгодным.** Если покупатели ценят товары в одинаковом порядке, выгода мала или её нет.
- **Не оставлять в freemium причины для платной версии.** Если бесплатная версия слишком хороша, никто не платит.
- **Затруднять отмену подписки.** Нарушает права потребителей и разрушает доверие.
:::

A: Продажа версий одного продукта с разными возможностями по разной цене.
Q: Когда набор наиболее выгоден?
A: Когда покупатели ценят товары по-разному (противоположно).
