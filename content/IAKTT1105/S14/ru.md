## Задачи криптографии

| Задача | Смысл | Средство |
|---|---|---|
| **Конфиденциальность** | посторонний не может прочитать сообщение | шифрование |
| **Целостность** | сообщение не изменено в пути | хеш, подпись |
| **Аутентификация** | подтверждается, от кого действительно пришло сообщение | подпись, сертификат |
| **Неотказуемость** | автор не может отрицать, что подписал | электронная цифровая подпись |

Основные термины: **открытый текст** — исходное сообщение; **шифртекст** — зашифрованное сообщение; **ключ** — секретный параметр для шифрования и расшифрования. Основной принцип современной криптографии (**принцип Керкгоффса**): алгоритм может быть известен всем, безопасность держится только на секретности ключа.

## Классический шифр: шифр Цезаря

Каждая буква сдвигается по алфавиту на одинаковый шаг (ключ). При ключе 3: A → D, B → E, ..., X → A.

```text
Открытый текст:  BANK
Ключ:            3
Шифртекст:       EDQN
```

**Слабость**: в латинском алфавите всего 25 возможных ключей — перебрать их можно за секунды. Кроме того, сохраняется частота букв. Пример показывает, почему современные шифры используют очень большое пространство ключей.

## Симметричное шифрование

Для шифрования и расшифрования используется **один ключ**. Современный стандарт — **AES** (ключ 128 или 256 бит): перебрать 2^128 ключей практически невозможно. Преимущество — высокая скорость, удобно для шифрования больших объёмов данных (диски, резервные копии, трафик).

**Проблема — обмен ключами**: как отправителю и получателю безопасно договориться о ключе? Если ключ отправить по открытому каналу, перехвативший его сможет открыть все сообщения. Эту проблему решает асимметричная криптография.

## Асимметричное шифрование

У каждого пользователя **два ключа**: **открытый** (выдаётся всем) и **закрытый** (только у владельца). Сообщение, зашифрованное открытым ключом, может открыть только соответствующий закрытый ключ. Поэтому, если Али хочет отправить Вали секретное сообщение, он шифрует его **открытым ключом Вали**.

**Небольшой пример RSA** (реальные ключи — числа из сотен цифр; здесь для понимания взяты малые числа):

```text
1. Два простых числа: p = 5, q = 11
2. n = p × q = 55;  φ = (p − 1)(q − 1) = 40
3. Открытая степень e = 3 (нет общих делителей с 40)
4. Закрытая степень d: e × d ≡ 1 (mod 40) → d = 27, так как 3 × 27 = 81 = 2 × 40 + 1
   Открытый ключ: (e = 3, n = 55);  закрытый ключ: (d = 27, n = 55)

Шифрование (m = 8):  c = 8^3 mod 55 = 512 mod 55 = 17
Расшифрование:       m = 17^27 mod 55 = 8
```

Злоумышленник знает n = 55, но чтобы найти d, он должен разложить n на простые множители. Для 55 это легко, но для числа более чем из 600 цифр практически невозможно для существующих компьютеров — на этом основана безопасность RSA.

**На практике — гибридная схема**: асимметричная криптография медленная, поэтому её используют только для безопасного обмена случайным симметричным ключом, а сами данные шифруются AES. Именно так работает HTTPS.

## Хеш-функции

**Хеш-функция** из данных любой длины получает короткий «отпечаток» фиксированной длины (например, **SHA-256** — 256 бит). Свойства: одинаковый вход → одинаковый хеш; при изменении одного символа входа хеш меняется полностью; по хешу нельзя восстановить исходные данные. Применение: проверка целостности файлов, хранение паролей (не сам пароль, а его хеш), блокчейн (M12), подпись.

## Электронная цифровая подпись и сертификаты

**Электронная цифровая подпись (ЭЦП)**:

1. Отправитель вычисляет хеш документа и подписывает его **своим закрытым ключом**.
2. Получатель проверяет подпись **открытым ключом отправителя** и сам вычисляет хеш документа для сравнения.
3. Если совпадает — документ именно от этого автора и не изменён.

То, что открытый ключ действительно принадлежит данному лицу, подтверждает **сертификат** — его выдаёт доверенный **удостоверяющий центр**. В Узбекистане ключи и сертификаты ЭЦП выдают уполномоченные центры; по закону ЭЦП равнозначна собственноручной подписи (Закон об электронной цифровой подписи).

## Применение в экономике

| Сфера | Где используется криптография |
|---|---|
| **Банк** | HTTPS, чипы карт, подтверждение платежей, мобильный банкинг, межбанковские каналы |
| **Налоги** | подписание отчётности ЭЦП на my.soliq.uz, электронные счета-фактуры (ЭСФ) |
| **Электронный документооборот** | договоры, приказы, заявления на госуслуги (my.gov.uz) |
| **Предприятие** | диски ноутбуков, резервные копии, удалённая работа через VPN |

:::warning
**Частые ошибки**

- **Передавать ключ ЭЦП (флешку или файл) другим.** За документ, подписанный от его имени, отвечает владелец.
- **Создавать «собственный алгоритм шифрования».** Используются проверенные стандарты (AES, RSA, SHA-256); безопасность — в секретности ключа.
- **Хранить пароли в открытом виде.** Системы должны хранить специальный хеш пароля.
- **Игнорировать предупреждения браузера о сертификате.** Это может быть признаком поддельного сайта.
:::

## Практические задания

1. Зашифруйте шифром Цезаря (ключ 5) своё имя, затем обменяйтесь с соседом и попробуйте открыть его шифртекст без ключа (перебором всех ключей).
2. В примере RSA выше зашифруйте сообщение m = 2: c = 2^3 mod 55 = ?
3. Али отправляет Вали конфиденциальный документ и хочет его подписать. Каким ключом он шифрует, каким подписывает?
4. Откройте в браузере сайт любого банка, нажмите на значок замка и запишите, кому и кем выдан сертификат, срок его действия.
5. Перечислите, где в документообороте вашего предприятия можно использовать ЭЦП.

## Итоги

- Задачи криптографии: конфиденциальность, целостность, аутентификация, неотказуемость.
- Симметричное шифрование (AES) — один ключ, быстро; проблема — обмен ключами.
- Асимметричное шифрование (RSA) — открытый и закрытый ключи; на практике гибридная схема (HTTPS).
- Хеш — отпечаток данных; ЭЦП — подпись хеша закрытым ключом; сертификат подтверждает владельца открытого ключа.
- В экономике: банки, налоговая отчётность, ЭСФ, электронный документооборот.

## Проверьте себя

:::check
Q: В чём главная проблема симметричного шифрования?
A: В безопасном обмене ключом между отправителем и получателем.
Q: Каким ключом нужно зашифровать сообщение, чтобы его мог открыть только получатель?
A: Открытым ключом получателя.
Q: Что подтверждает электронная цифровая подпись?
A: Автора документа и то, что документ не изменялся после подписания.
Q: Что гласит принцип Керкгоффса?
A: Алгоритм может быть известен всем; безопасность держится только на секретности ключа.
