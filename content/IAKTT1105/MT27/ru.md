## Экосистема интернет-банкинга

- **Открытый банкинг** (Open Banking): банк с согласия клиента открывает его данные по счетам и платёжные функции другим лицензированным сервисам через **API**. В результате бухгалтерская программа автоматически получает выписку, а финансовое приложение показывает счета в нескольких банках на одном экране.
- **Финтех-компании** — платёжные сервисы, цифровые кошельки, онлайн-кредитование, денежные переводы; конкурируют и сотрудничают с банками.
- **Встроенные финансы** (embedded finance) — финансовая услуга внутри небанковского приложения: рассрочка на маркетплейсе, кошелёк в приложении такси, кредит в бухгалтерской программе.
- **«Купи сейчас — плати потом»** (BNPL): сумма покупки делится на несколько равных частей, часто «без процентов». Риски: легко влезть в долги, параллельные долги в нескольких сервисах, штрафы за просрочку, долговая нагрузка не учитывается. Вопрос экономиста: если «без процентов», откуда сервис получает доход? (Комиссия с продавца, штрафы за просрочку.)

## Экономика интернет-торговли

| Затраты | Содержание | Влияние |
|---|---|---|
| **Последняя миля** | доставка со склада до двери клиента | часто крупнейшая часть затрат на доставку; пункты выдачи и постаматы дешевле |
| **Возвраты** | клиент возвращает товар (особенно одежду) | повторная проверка, логистика, потеря стоимости товара |
| **Платёжная комиссия** | эквайринг и платёжные системы | процент с каждой продажи |
| **Комиссия маркетплейса** | доля платформы (MT26) | снижает маржу |
| **Привлечение клиентов** | реклама (CAC) | определяет юнит-экономику (MT26) |

Бесплатная доставка бесплатна для клиента, но не для продавца: её стоимость «спрятана» в цене товара или в минимальной сумме заказа.

## Интернет-страхование

- **Цена на основе риска**: чем больше данных, тем точнее страховая премия соответствует реальному риску каждого клиента.
- **Полисы на основе использования** (usage-based): «плати, сколько ездишь» — по пробегу автомобиля или телематике (S13).
- **Параметрическое страхование** (S12): событие определяется объективным показателем (количество осадков, сила землетрясения) — выплата быстрая.
- **Микрострахование**: полисы на небольшие суммы — например, на день поездки или на только что купленный телефон, внутри приложения.
- **Риск**: чрезмерная персонализация может сделать страховку очень дорогой для отдельных групп — вопрос справедливого использования данных.

## Интернет-маркетинг: атрибуция

Прежде чем купить, клиент контактирует с несколькими каналами: видит рекламу в Instagram, затем ищет в Google и в конце заходит на сайт напрямую и покупает. Какому каналу «записать» выручку? Это задача **атрибуции**.

| Модель | Правило | Преимущество / недостаток |
|---|---|---|
| **Последний клик** (last click) | вся выручка последнему каналу | просто; недооценивает каналы, создавшие осведомлённость |
| **Первый клик** | вся выручка первому каналу | показывает осведомлённость; игнорирует итоговое решение |
| **Линейная** | поровну всем каналам | выглядит справедливо; не каждый контакт одинаково важен |
| **Позиционная** (U-образная) | 40% первому, 40% последнему, 20% промежуточным | уравновешивает оба подхода |
| **На основе данных** | статистическая модель оценивает реальный вклад каналов | точнее; требует много данных |

## Разобранный пример: атрибуция по последнему клику и линейная

В каждой строке — сумма покупки и путь клиента (каналы через `>`, последний — перед покупкой). Рассчитайте выручку каждого канала по двум моделям.

```python
import sys

oxirgi, chiziqli = {}, {}
for satr in sys.stdin.read().split("\n"):
    if not satr.strip():
        continue
    summa, yol = satr.split()
    summa = int(summa)
    kanallar = yol.split(">")
    for k in kanallar:
        oxirgi.setdefault(k, 0)
        chiziqli[k] = chiziqli.get(k, 0) + summa // len(kanallar)   # равная доля
    oxirgi[kanallar[-1]] += summa                                   # всё последнему каналу

for k in sorted(oxirgi):
    print(f"{k}: последний клик {oxirgi[k]}, линейная {chiziqli[k]}")
```
```java
import java.util.Map;
import java.util.Scanner;
import java.util.TreeMap;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        TreeMap<String, Long> oxirgi = new TreeMap<>(), chiziqli = new TreeMap<>();
        while (in.hasNext()) {
            long summa = in.nextLong();
            String[] kanallar = in.next().split(">");
            for (String k : kanallar) {
                oxirgi.putIfAbsent(k, 0L);
                chiziqli.merge(k, summa / kanallar.length, Long::sum);   // равная доля
            }
            oxirgi.merge(kanallar[kanallar.length - 1], summa, Long::sum);   // всё последнему каналу
        }
        for (Map.Entry<String, Long> e : oxirgi.entrySet())
            System.out.println(e.getKey() + ": последний клик " + e.getValue() + ", линейная " + chiziqli.get(e.getKey()));
    }
}
```
```cpp
#include <iostream>
#include <map>
#include <sstream>
#include <string>
#include <vector>
using namespace std;

int main() {
    map<string, long long> oxirgi, chiziqli;
    long long summa;
    string yol;
    while (cin >> summa >> yol) {
        vector<string> kanallar;
        stringstream ss(yol);
        string k;
        while (getline(ss, k, '>')) kanallar.push_back(k);
        for (auto& x : kanallar) {
            oxirgi[x] += 0;
            chiziqli[x] += summa / (long long) kanallar.size();      // равная доля
        }
        oxirgi[kanallar.back()] += summa;                            // всё последнему каналу
    }
    for (auto& [k, v] : oxirgi) cout << k << ": последний клик " << v << ", линейная " << chiziqli[k] << "\n";
    return 0;
}
```

Ввод:

```text
120000 Instagram>Google>Direct
90000 Telegram>Direct
60000 Google
150000 Instagram>Telegram>Google>Direct
```

Вывод:

```text
Direct: последний клик 360000, линейная 122500
Google: последний клик 60000, линейная 137500
Instagram: последний клик 0, линейная 77500
Telegram: последний клик 0, линейная 82500
```

По «последнему клику» Instagram и Telegram не принесли никакой выручки — будто их рекламу можно отключить. Но линейная модель показывает, что они первыми привлекали клиентов и участвовали в 38% общей выручки. Если их отключить, заходов на «Direct» тоже может стать меньше. Для верного вывода нужно сравнивать несколько моделей и по возможности провести эксперимент (например, временно остановить рекламу в одном регионе) («корреляция — не причинность» из MT2).

## Конфиденциальность и согласие

- Браузеры ограничивают сторонние cookie; мобильные платформы запрашивают согласие на отслеживание — следить за клиентом между каналами становится труднее.
- Компании больше опираются на **собственные данные** (свой сайт, приложение, программа лояльности) и согласие клиентов.
- Законодательство о персональных данных (S11, MT17): цель сбора данных должна быть ясной, согласие — добровольным, отказ — простым.

:::warning
**Частые ошибки**

- **Распределять бюджет только по последнему клику.** Каналы, создающие осведомлённость, ошибочно выглядят «бесполезными».
- **Считать рассрочку «без процентов» бесплатной.** Есть риск штрафов и параллельных долгов.
- **Не учитывать стоимость бесплатной доставки.** Она всё равно попадает в юнит-экономику.
- **Собирать данные без согласия.** Правовой риск и потеря доверия.
:::
