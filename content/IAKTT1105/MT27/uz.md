## Internet-banking ekotizimi

- **Ochiq banking** (Open Banking): bank mijoz roziligi bilan uning hisob maʼlumotlari va toʻlov funksiyalarini **API** orqali boshqa litsenziyalangan xizmatlarga ochadi. Natijada buxgalteriya dasturi koʻchirmani avtomatik oladi, moliyaviy ilova bir nechta bankdagi hisoblarni bitta ekranda koʻrsatadi.
- **Fintex kompaniyalar** — toʻlov xizmatlari, raqamli hamyonlar, onlayn kreditlash, pul oʻtkazmalari; banklar bilan raqobatlashadi va hamkorlik qiladi.
- **Oʻrnatilgan moliya** (embedded finance) — moliyaviy xizmat bank boʻlmagan ilova ichida: marketpleysda muddatli toʻlov, taksi ilovasida hamyon, buxgalteriya dasturida kredit.
- **"Hozir sotib ol — keyin toʻla"** (BNPL): xarid summasi bir necha teng boʻlakka boʻlinadi, koʻpincha "foizsiz". Xavflar: oson qarzga botish, bir nechta xizmatda parallel qarzlar, kechikish jarimalari, qarz yuki hisobga olinmasligi. Iqtisodchi uchun savol: "foizsiz" boʻlsa, xizmat qayerdan daromad oladi? (Sotuvchidan komissiya, kechikish jarimalari.)

## Internet-savdo iqtisodiyoti

| Xarajat | Mazmuni | Taʼsiri |
|---|---|---|
| **Oxirgi milya** | ombordan mijoz eshigigacha yetkazish | koʻpincha yetkazish xarajatining eng katta qismi; topshirish punktlari va postamatlar arzonroq |
| **Qaytarishlar** | mijoz tovarni qaytaradi (ayniqsa kiyim-kechak) | qayta tekshirish, logistika, tovar qiymatining yoʻqolishi |
| **Toʻlov komissiyasi** | ekvayring va toʻlov tizimlari | har bir savdodan foiz |
| **Marketpleys komissiyasi** | platforma ulushi (MT26) | marjani kamaytiradi |
| **Mijozni jalb qilish** | reklama (CAC) | birlik iqtisodiyotini belgilaydi (MT26) |

Bepul yetkazib berish — mijoz uchun bepul, lekin sotuvchi uchun emas: uning narxi tovar narxiga yoki minimal buyurtma summasiga "yashiriladi".

## Internet-sugʻurta

- **Xavfga asoslangan narx**: maʼlumotlar qancha koʻp boʻlsa, sugʻurta mukofoti har bir mijozning real xavfiga shuncha yaqin hisoblanadi.
- **Foydalanishga asoslangan polislar** (usage-based): "qancha haydasang, shuncha toʻla" — avtomobil yurgan kilometr yoki telematika (S13) boʻyicha.
- **Parametrik sugʻurta** (S12): hodisa obyektiv koʻrsatkich bilan (yomgʻir miqdori, zilzila kuchi) aniqlanadi — toʻlov tez.
- **Mikrosugʻurta**: kichik summali polislar — masalan, sayohat kuniga yoki xarid qilingan telefon uchun, ilova ichida.
- **Xavf**: haddan tashqari shaxsiylashtirish ayrim guruhlar uchun sugʻurtani juda qimmat qilishi mumkin — maʼlumotlardan adolatli foydalanish masalasi.

## Internet-marketing: atributsiya

Mijoz xarid qilishdan oldin bir nechta kanal bilan aloqa qiladi: Instagram reklamasini koʻradi, keyin Google da qidiradi, oxirida saytga toʻgʻridan-toʻgʻri kirib sotib oladi. Tushumni qaysi kanalga "yozish" kerak? Bu — **atributsiya** masalasi.

| Model | Qoida | Afzallik / kamchilik |
|---|---|---|
| **Oxirgi bosish** (last click) | butun tushum oxirgi kanalga | oddiy; xabardorlik yaratgan kanallarni kamsitadi |
| **Birinchi bosish** | butun tushum birinchi kanalga | xabardorlikni koʻrsatadi; yakuniy qarorni eʼtiborsiz qoldiradi |
| **Chiziqli** | barcha kanallarga teng | adolatli koʻrinadi; har bir aloqa teng muhim emas |
| **Pozitsion** (U-shakl) | 40% birinchiga, 40% oxirgiga, 20% oraliqlarga | ikkalasini muvozanatlaydi |
| **Maʼlumotlarga asoslangan** | statistik model kanallarning haqiqiy hissasini baholaydi | aniqroq; koʻp maʼlumot talab qiladi |

## Ishlangan misol: oxirgi bosish va chiziqli atributsiya

Har bir satrda xarid summasi va mijoz yoʻli (kanallar `>` bilan, oxirgisi xariddan oldingi). Har bir kanal uchun tushumni ikki modelda hisoblang.

```python
import sys

oxirgi, chiziqli = {}, {}
for satr in sys.stdin.read().split("\n"):
    if not satr.strip():
        continue
    summa, yol = satr.split()
    summa = int(summa)
    kanallar = yol.split(">")
    for k in kanallar:
        oxirgi.setdefault(k, 0)
        chiziqli[k] = chiziqli.get(k, 0) + summa // len(kanallar)   # teng ulush
    oxirgi[kanallar[-1]] += summa                                   # hammasi oxirgi kanalga

for k in sorted(oxirgi):
    print(f"{k}: oxirgi bosish {oxirgi[k]}, chiziqli {chiziqli[k]}")
```
```java
import java.util.Map;
import java.util.Scanner;
import java.util.TreeMap;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        TreeMap<String, Long> oxirgi = new TreeMap<>(), chiziqli = new TreeMap<>();
        while (in.hasNext()) {
            long summa = in.nextLong();
            String[] kanallar = in.next().split(">");
            for (String k : kanallar) {
                oxirgi.putIfAbsent(k, 0L);
                chiziqli.merge(k, summa / kanallar.length, Long::sum);   // teng ulush
            }
            oxirgi.merge(kanallar[kanallar.length - 1], summa, Long::sum);   // hammasi oxirgi kanalga
        }
        for (Map.Entry<String, Long> e : oxirgi.entrySet())
            System.out.println(e.getKey() + ": oxirgi bosish " + e.getValue() + ", chiziqli " + chiziqli.get(e.getKey()));
    }
}
```
```cpp
#include <iostream>
#include <map>
#include <sstream>
#include <string>
#include <vector>
using namespace std;

int main() {
    map<string, long long> oxirgi, chiziqli;
    long long summa;
    string yol;
    while (cin >> summa >> yol) {
        vector<string> kanallar;
        stringstream ss(yol);
        string k;
        while (getline(ss, k, '>')) kanallar.push_back(k);
        for (auto& x : kanallar) {
            oxirgi[x] += 0;
            chiziqli[x] += summa / (long long) kanallar.size();      // teng ulush
        }
        oxirgi[kanallar.back()] += summa;                            // hammasi oxirgi kanalga
    }
    for (auto& [k, v] : oxirgi) cout << k << ": oxirgi bosish " << v << ", chiziqli " << chiziqli[k] << "\n";
    return 0;
}
```

Kirish:

```text
120000 Instagram>Google>Direct
90000 Telegram>Direct
60000 Google
150000 Instagram>Telegram>Google>Direct
```

Chiqish:

```text
Direct: oxirgi bosish 360000, chiziqli 122500
Google: oxirgi bosish 60000, chiziqli 137500
Instagram: oxirgi bosish 0, chiziqli 77500
Telegram: oxirgi bosish 0, chiziqli 82500
```

"Oxirgi bosish" boʻyicha Instagram va Telegram hech qanday tushum keltirmagan — ularning reklamasini oʻchirish mumkindek. Lekin chiziqli model koʻrsatadiki, ular mijozlarni birinchi boʻlib jalb qilgan va jami tushumning 38% ida ishtirok etgan. Agar ular oʻchirilsa, "Direct" ga keluvchilar ham kamayishi mumkin. Toʻgʻri xulosa uchun bir nechta modelni solishtirish va imkon boʻlsa tajriba (masalan, bitta hududda reklamani vaqtincha toʻxtatish) oʻtkazish kerak (MT2 dagi "korrelyatsiya sababiyat emas").

## Maxfiylik va rozilik

- Brauzerlar uchinchi tomon cookie fayllarini cheklamoqda; mobil platformalar kuzatuv uchun rozilik soʻraydi — kanallar boʻylab mijozni kuzatish qiyinlashmoqda.
- Kompaniyalar **birinchi tomon maʼlumotlari** (oʻz sayti, ilovasi, sodiqlik dasturi) va mijoz roziligiga koʻproq tayanmoqda.
- Shaxsiy maʼlumotlar qonunchiligi (S11, MT17): maʼlumot yigʻish maqsadi aniq, rozilik ixtiyoriy, rad etish oson boʻlishi kerak.

:::warning
**Koʻp uchraydigan xatolar**

- **Faqat oxirgi bosishga qarab byudjet taqsimlash.** Xabardorlik yaratuvchi kanallar notoʻgʻri "foydasiz" koʻrinadi.
- **"Foizsiz" muddatli toʻlovni bepul deb bilish.** Jarimalar va parallel qarzlar xavfi bor.
- **Bepul yetkazib berish xarajatini hisobga olmaslik.** U baribir birlik iqtisodiyotiga tushadi.
- **Rozilikisiz maʼlumot yigʻish.** Huquqiy xavf va ishonchni yoʻqotish.
:::

## Topshiriq

1. Misol dasturiga **birinchi bosish** modelini qoʻshing va uchta modelni solishtiring.
2. **Pozitsion** model (40/20/40) boʻyicha misoldagi kanallar tushumini qoʻlda hisoblang (bitta kanalli yoʻl uchun — 100%, ikki kanalli uchun — 50/50).
3. Ikki BNPL yoki muddatli toʻlov xizmatining shartlarini (jarimalar, muddatlar, komissiyalar) solishtiring va xaridor uchun xavflarni yozing.
4. Bitta internet-doʻkon uchun oxirgi milya xarajatini kamaytirish yoʻllarini taklif qiling.
