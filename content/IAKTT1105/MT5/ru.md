## Коммутация пакетов

В телефонной сети для звонка выделяется отдельная линия (коммутация каналов). В компьютерных сетях данные делятся на небольшие **пакеты** (обычно до 1 500 байт), каждый пакет отправляется отдельно с адресом и собирается заново у получателя. Преимущество: одним каналом одновременно пользуются многие, а при обрыве маршрута пакеты идут другим путём.

## Многоуровневые модели

Задачи сети делятся на уровни: каждый уровень делает только свою работу и «общается» с соседними. **OSI** — теоретическая 7-уровневая модель, **TCP/IP** — 4-уровневая модель, реально используемая в Интернете.

| Уровень TCP/IP | Уровни OSI | Задача | Примеры |
|---|---|---|---|
| **Прикладной** | 7 прикладной, 6 представления, 5 сеансовый | пользовательские сервисы | HTTP/HTTPS, SMTP, DNS, TLS |
| **Транспортный** | 4 транспортный | доставка между приложениями, надёжность | TCP (гарантированная), UDP (быстрая) |
| **Сетевой (межсетевой)** | 3 сетевой | адресация и маршрутизация | IP, маршрутизатор |
| **Канальный и физический** | 2 канальный, 1 физический | передача между соседними устройствами, сигнал | Ethernet, Wi-Fi, коммутатор, кабель |

**Аналогия — почта**: текст письма (прикладной) → вложить в конверт и отправить заказным (транспортный) → адрес и индекс (сетевой) → машина, поезд, самолёт (канальный и физический). Ни одному этапу не нужно знать, как устроен другой.

**TCP или UDP?** TCP проверяет, что каждый пакет дошёл, и повторно отправляет потерянные — для веб-страниц, почты, банковских платежей. UDP не проверяет, но быстр — для видеозвонков, онлайн-игр (один потерянный кадр не важен).

## Адресация

| Понятие | Содержание | Пример |
|---|---|---|
| **MAC-адрес** | заводской адрес сетевой карты, используется в локальной сети | `3C-52-82-1A-7F-04` |
| **IPv4-адрес** | 32 бита, 4 числа 0–255; ~4,3 млрд адресов — не хватает | `213.230.96.15` |
| **IPv6-адрес** | 128 бит, практически неограниченное число адресов | `2001:db8::1` |
| **Частные адреса** | только во внутренней сети, в Интернете не маршрутизируются | `192.168.x.x`, `10.x.x.x`, `172.16–31.x.x` |
| **NAT** | маршрутизатор выводит множество внутренних адресов в Интернет через один внешний | 10 устройств дома — 1 внешний IP |
| **DHCP** | автоматически выдаёт устройству IP-адрес, шлюз и DNS | при подключении к Wi-Fi |
| **Порт** | указывает, какому приложению на компьютере адресовано | 443 — HTTPS, 25 — SMTP |
| **Маска** | какая часть адреса — сеть, а какая — устройство | `255.255.255.0` (/24 — 254 устройства) |

## Классификация сетей

| Признак | Виды |
|---|---|
| **Территория** | PAN, LAN, MAN, WAN (M6) |
| **Топология** | звезда, шина, кольцо, ячеистая (mesh) |
| **Модель управления** | **клиент-сервер** (центральный сервер — корпоративная сеть, сайт) и **одноранговая** (равноправные узлы — обмен файлами, блокчейн, M12) |
| **Среда передачи** | проводные (медь, оптоволокно), беспроводные (Wi-Fi, мобильная, спутниковая) |
| **Доступ** | публичная (Интернет), частная (интранет), экстранет (для партнёров), виртуальная частная сеть через VPN |

## Показатели качества сети

| Показатель | Смысл | Единица |
|---|---|---|
| **Пропускная способность** (скорость) | сколько данных передаётся в секунду | Мбит/с, Гбит/с |
| **Задержка** (ping, latency) | время прохождения пакета туда и обратно | мс |
| **Джиттер** | изменчивость задержки | мс |
| **Потеря пакетов** | доля недошедших пакетов | % |

**Важно**: провайдер указывает скорость в **битах** (Мбит/с), а размер файла — в **байтах** (МБ); 1 байт = 8 бит. 100 Мбит/с ≈ 12,5 МБ/с. Реальная скорость обычно на 10–30% ниже теоретической («накладные расходы» протоколов, помехи Wi-Fi, скорость сервера).

Для видеозвонков важны задержка и джиттер (задержка больше 150 мс затрудняет разговор); для больших файлов — пропускная способность.

## Разобранный пример: время передачи файла

В каждой строке — имя файла, размер (МБ) и скорость канала (Мбит/с). Выведите теоретическое время передачи и практическое (при эффективности 80%) в виде часы:минуты:секунды, округляя секунды вверх.

```python
import sys

def vaqt_matni(soniya):
    return f"{soniya // 3600}:{soniya % 3600 // 60:02d}:{soniya % 60:02d}"

for satr in sys.stdin.read().split("\n"):
    if not satr.strip():
        continue
    nom, hajm, tezlik = satr.split()
    hajm, tezlik = int(hajm), int(tezlik)
    bit = hajm * 8                                      # МБ -> Мбит
    nazariy = (bit + tezlik - 1) // tezlik              # округление вверх
    amalda = (bit * 100 + tezlik * 80 - 1) // (tezlik * 80)   # эффективность 80%
    print(f"{nom}, {hajm} МБ, {tezlik} Мбит/с: теоретически {vaqt_matni(nazariy)}, на практике {vaqt_matni(amalda)}")
```
```java
import java.util.Scanner;

public class Main {
    static String vaqtMatni(long soniya) {
        return String.format("%d:%02d:%02d", soniya / 3600, soniya % 3600 / 60, soniya % 60);
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        while (in.hasNext()) {
            String nom = in.next();
            long hajm = in.nextLong(), tezlik = in.nextLong();
            long bit = hajm * 8;                                         // МБ -> Мбит
            long nazariy = (bit + tezlik - 1) / tezlik;                  // округление вверх
            long amalda = (bit * 100 + tezlik * 80 - 1) / (tezlik * 80);  // эффективность 80%
            System.out.println(nom + ", " + hajm + " МБ, " + tezlik + " Мбит/с: теоретически " + vaqtMatni(nazariy) + ", на практике " + vaqtMatni(amalda));
        }
    }
}
```
```cpp
#include <cstdio>
#include <iostream>
#include <string>
using namespace std;

string vaqtMatni(long long soniya) {
    char buf[32];
    snprintf(buf, sizeof buf, "%lld:%02lld:%02lld", soniya / 3600, soniya % 3600 / 60, soniya % 60);
    return buf;
}

int main() {
    string nom;
    long long hajm, tezlik;
    while (cin >> nom >> hajm >> tezlik) {
        long long bit = hajm * 8;                                        // МБ -> Мбит
        long long nazariy = (bit + tezlik - 1) / tezlik;                 // округление вверх
        long long amalda = (bit * 100 + tezlik * 80 - 1) / (tezlik * 80); // эффективность 80%
        cout << nom << ", " << hajm << " МБ, " << tezlik << " Мбит/с: теоретически " << vaqtMatni(nazariy)
             << ", на практике " << vaqtMatni(amalda) << "\n";
    }
    return 0;
}
```

Ввод:

```text

video.mp4 1500 100
video.mp4 1500 20
backup.zip 50000 100
backup.zip 50000 1000
```

Вывод:

```text
report.pdf, 25 МБ, 100 Мбит/с: теоретически 0:00:02, на практике 0:00:03
video.mp4, 1500 МБ, 100 Мбит/с: теоретически 0:02:00, на практике 0:02:30
video.mp4, 1500 МБ, 20 Мбит/с: теоретически 0:10:00, на практике 0:12:30
backup.zip, 50000 МБ, 100 Мбит/с: теоретически 1:06:40, на практике 1:23:20
backup.zip, 50000 МБ, 1000 Мбит/с: теоретически 0:06:40, на практике 0:08:20
```

Загрузка резервной копии 50 ГБ в облако по каналу 100 Мбит/с на практике займёт 1 час 23 минуты — в рабочее время это замедлит Интернет остальным сотрудникам. Решения: загружать копию ночью, отправлять только изменённые файлы (инкрементное копирование) или взять более быстрый канал. Такие расчёты нужны при выборе канала (M6) и в плане резервного копирования (M14).

## Простая диагностика

| Команда (Windows) | Что делает |
|---|---|
| `ipconfig` | IP-адрес компьютера, маска, шлюз |
| `ping 8.8.8.8` | доступность внешнего сервера и задержка |
| `ping google.com` | дополнительно проверяет работу DNS |
| `tracert google.com` | через какие маршрутизаторы проходит пакет |
| сайты speedtest | реальная скорость загрузки и отдачи, ping |

**Порядок**: если «нет Интернета» — сначала кабель или Wi-Fi, затем `ipconfig` (есть ли адрес?), затем `ping` шлюза, затем внешнего IP, затем домена. На каком шаге обрыв — там и проблема. Это помогает дать ИТ-отделу точную информацию.

:::warning
**Частые ошибки**

- **Путать Мбит/с и МБ/с.** Разница в 8 раз.
- **Путать скорость и задержку.** Даже на быстром канале спутниковая связь даёт большую задержку.
- **Думать, что к частному адресу (192.168...) можно обратиться из Интернета.** Он виден только во внутренней сети.
- **Считать обещанную провайдером скорость гарантией.** Проверьте SLA в договоре.
:::

## Проверьте себя

:::check
Q: В чём главное отличие TCP от UDP?
A: TCP гарантирует доставку и повторно отправляет потерянные пакеты; UDP не гарантирует, но работает быстрее.
Q: Зачем нужен NAT?
A: Чтобы выводить множество внутренних устройств в Интернет через один внешний IP-адрес (адресов IPv4 не хватает).
Q: За сколько секунд теоретически загрузится файл 100 МБ по каналу 100 Мбит/с?
A: 100 × 8 / 100 = 8 секунд.
Q: Что делает DHCP?
A: Автоматически выдаёт устройству IP-адрес, шлюз и настройки DNS.
