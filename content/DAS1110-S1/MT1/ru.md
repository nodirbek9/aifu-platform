## Почему это важно

Ставка налога зависит от дохода, плата за электричество — от потребления, скидка — от суммы покупки. Таких правил «по диапазонам» в жизни очень много, и записывать их в программе без ошибок — навык, которого ждут от каждого программиста. В этой самостоятельной работе вы от начала до конца решите задачу с диапазонами: алгоритм, программа и тесты.

:::note
**После этой самостоятельной работы вы сможете:**

- записывать условия задачи с диапазонами в правильном порядке;
- описывать алгоритм словами и в виде блок-схемы;
- составлять таблицу тестов для каждой ветви и граничного значения;
- писать решение на Python, Java или C++ и проходить автоматические тесты.
:::

## Краткое повторение темы

В задаче с диапазонами числовая ось разбита на несколько частей, и в каждой действует своё правило. Порядок решения:

1. **Выпишите диапазоны** и определите, к какому диапазону относятся границы (`<` или `<=`).
2. **Постройте цепочку**: `if` … `elif` / `else if` … `else`. Если писать условия с одной стороны (от меньшего к большему или наоборот), в каждом достаточно проверить одну границу.
3. **Тесты**: по одному значению изнутри каждого диапазона и значения с обеих сторон каждой границы.

| Ошибка | Последствие |
|---|---|
| Граница попала в два диапазона | результат противоречит условию |
| Граница не попала ни в один диапазон | для некоторых значений нет результата |
| Нарушен порядок условий | широкое условие «поглощает» узкое |

## Образец: тариф на электроэнергию

Вводится месячное потребление (кВт·ч, целое число). Вычислите плату: первые 100 кВт·ч — по 450 сумов, от 101 до 300 — по 900 сумов, сверх 300 — по 1350 сумов.

Алгоритм словами:

```text
1. прочитать q
2. если q <= 100: tolov = q * 450
3. иначе если q <= 300: tolov = 100 * 450 + (q - 100) * 900
4. иначе: tolov = 100 * 450 + 200 * 900 + (q - 300) * 1350
5. вывести tolov
```

На блок-схеме это два последовательных ромба: `q <= 100?` и `q <= 300?`, в ветви «да» каждого — одно вычисление.

```python
q = int(input())

if q <= 100:
    tolov = q * 450
elif q <= 300:
    tolov = 100 * 450 + (q - 100) * 900
else:
    tolov = 100 * 450 + 200 * 900 + (q - 300) * 1350

print(tolov)
```
```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int q = in.nextInt();

        long tolov;
        if (q <= 100) {
            tolov = q * 450L;
        } else if (q <= 300) {
            tolov = 100 * 450L + (q - 100) * 900L;
        } else {
            tolov = 100 * 450L + 200 * 900L + (q - 300) * 1350L;
        }

        System.out.println(tolov);
    }
}
```
```cpp
#include <iostream>
using namespace std;

int main() {
    long long q;
    cin >> q;

    long long tolov;
    if (q <= 100) {
        tolov = q * 450;
    } else if (q <= 300) {
        tolov = 100 * 450 + (q - 100) * 900;
    } else {
        tolov = 100 * 450 + 200 * 900 + (q - 300) * 1350;
    }

    cout << tolov << endl;
    return 0;
}
```

Таблица тестов — в самостоятельной работе требуется точно такая же (*tolov* — плата):

| Ввод | Диапазон | Ожидаемый результат | Комментарий |
|---|---|---|---|
| 0 | первый | 0 | нижняя граница |
| 100 | первый | 45000 | граница: входит в первый диапазон |
| 101 | второй | 45900 | значение сразу после границы |
| 150 | второй | 90000 | внутри диапазона |
| 300 | второй | 225000 | граница |
| 350 | третий | 292500 | внутри диапазона |

В Java `450L` — литерал типа `long`: чтобы при большом потреблении `int` не переполнился.

## Задание самостоятельной работы

Решите приведённую ниже задачу о **кусочной функции**. Что сдаётся:

1. **Алгоритм** — словами (как в образце) или рисунок блок-схемы.
2. **Программа** — на Python, Java или C++; отправляется в окне задания ниже и должна пройти автоматические тесты.
3. **Таблица тестов** — не меньше 6 тестов: по одному из каждого диапазона и около каждой границы (*x* = 0, *x* = 10); ожидаемый результат для каждого посчитан вручную.
4. **Вывод** — 3–5 предложений: на какой границе легко ошибиться и как вы это проверили.

:::warning
**Критерии оценки и частые ошибки**

- Алгоритм и программа должны соответствовать друг другу; программа без алгоритма полностью не оценивается.
- Граничные значения (*x* = 0 и *x* = 10) должны попадать в диапазон, указанный в условии: `0 ≤ x ≤ 10`.
- Ожидаемые результаты считаются вручную, а не копируются из вывода программы.
- Программа, скопированная из чужой работы, не принимается.
:::

:::tip
Сначала заполните таблицу тестов, потом пишите программу. Когда программа выдаёт все результаты из таблицы, отправьте её в окне задания.
:::

## Итоги

- В задаче с диапазонами сначала определите, к какому диапазону относятся границы.
- Упорядочивайте условия с одной стороны — тогда в каждом проверяется одна граница.
- Тесты: изнутри каждого диапазона и около каждой границы.
- Работа в порядке алгоритм → тесты → программа уменьшает число ошибок.

Q: По какому тарифу в образце считаются 300 кВт·ч?
A: По второму диапазону (`q <= 300`): 45 000 + 200 · 900 = 225 000 сумов.
Q: Сколько тестов как минимум нужно для задачи с тремя диапазонами?
A: Не меньше 3 (по одному из каждого диапазона), но для надёжной проверки добавляют тесты около каждой границы.
Q: Что будет, если условие `elif q <= 300` поставить раньше `if q <= 100`?
A: И потребление меньше 100 посчитается по второму тарифу: широкое условие «поглощает» узкое.
