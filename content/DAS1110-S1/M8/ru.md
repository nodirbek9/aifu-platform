## Почему это важно

В папке на компьютере бывают папки, а в них — снова папки. Как посчитать «размер папки»? Ответ прост: размер папки = размер файлов в ней + размер каждой вложенной папки. В определении участвует сам «размер папки» — это **рекурсия**.

Рекурсия — решение задачи через её меньшую копию. Это естественный инструмент для древовидных структур (папки, генеалогическое древо, элементы веб-страницы), алгоритмов «разделяй и властвуй» (быстрая сортировка, двоичный поиск) и многих математических определений. Некоторые задачи без рекурсии записываются намного сложнее.

:::note
**После этого занятия вы сможете:**

- выделять две части рекурсивной функции — базовый случай и рекурсивный шаг;
- объяснять, как работает стек вызовов и почему стек переполняется;
- решать рекурсивно задачи вроде факториала, возведения в степень, двоичной записи;
- решать задачу о Ханойских башнях с помощью рекурсии;
- обоснованно выбирать между рекурсией и циклом.
:::

## Понятие рекурсии

**Рекурсивная функция** — функция, которая вызывает саму себя. В правильной рекурсивной функции всегда есть две части:

| Часть | Назначение | На примере факториала |
|---|---|---|
| **Базовый случай (base case)** | самый простой случай, ответ известен сразу; здесь рекурсия останавливается | при *n* = 0, 0! = 1 |
| **Рекурсивный шаг** | задача сводится к своей меньшей копии | *n*! = *n* · (*n* − 1)! |

Каждый рекурсивный вызов должен **приближать** задачу к базовому случаю: *n* → *n* − 1 → … → 0. Иначе рекурсия будет бесконечной.

Рекурсивное мышление: «Если я верю, что умею решать меньшую задачу, как решить большую?» Для факториала: предположим, что (*n* − 1)! известен, тогда *n*! = *n* · (*n* − 1)!.

## Стек вызовов

При вызове функции компьютер выделяет в памяти **кадр (frame)** для её параметров и локальных переменных и кладёт его в **стек вызовов (call stack)**. Когда функция завершается, кадр снимается со стека. Стек — структура «последним пришёл — первым ушёл», как стопка тарелок.

При вызове `faktorial(3)`:

| Шаг | Стек (вершина справа) | Что происходит |
|---|---|---|
| 1 | f(3) | нужно вычислить 3 · f(2) — ждёт |
| 2 | f(3) f(2) | 2 · f(1) — ждёт |
| 3 | f(3) f(2) f(1) | 1 · f(0) — ждёт |
| 4 | f(3) f(2) f(1) f(0) | базовый случай: возвращает 1 |
| 5 | f(3) f(2) f(1) | возвращает 1 · 1 = 1 |
| 6 | f(3) f(2) | возвращает 2 · 1 = 2 |
| 7 | f(3) | возвращает 3 · 2 = 6 |

Рекурсия работает в два этапа: **спуск** (вызовы до базового случая) и **возврат** (результаты собираются в обратном порядке).

Размер стека ограничен. Слишком глубокая рекурсия или рекурсия без базового случая приводит к **переполнению стека**:

| Язык | Ошибка |
|---|---|
| Python | `RecursionError: maximum recursion depth exceeded` (предел обычно 1000) |
| Java | `StackOverflowError` |
| C++ | программа аварийно завершается (segmentation fault) |

## Рекурсия или цикл?

Любую рекурсию можно записать циклом и наоборот. Выбор зависит от задачи:

| Удобна рекурсия | Удобен цикл |
|---|---|
| структура древовидная (папки, генеалогия) | простая последовательность (сумма, факториал) |
| «разделяй и властвуй» (Ханой, быстрая сортировка) | глубина может быть очень большой |
| само определение рекурсивно | важны скорость и память |

Осторожно: «прямолинейная» рекурсия для чисел Фибоначчи `fib(n) = fib(n-1) + fib(n-2)` снова и снова вычисляет одни и те же значения и уже при *n* = 40 работает заметно медленно (число вызовов растёт экспоненциально). А циклом из A7 — мгновенно.

## Разобранный пример 1: рекурсивный факториал и сумма цифр

Вводится целое число *n* (0 ≤ *n* ≤ 20). Вычислите *n*! и сумму цифр *n* рекурсивными функциями.

```python
def faktorial(n):
    if n == 0:                       # базовый случай
        return 1
    return n * faktorial(n - 1)      # рекурсивный шаг


def raqamlar_yigindisi(n):
    if n < 10:                       # базовый случай: одна цифра
        return n
    return n % 10 + raqamlar_yigindisi(n // 10)


n = int(input())
print(faktorial(n), raqamlar_yigindisi(n))
```
```java
import java.util.Scanner;

public class Main {
    static long faktorial(int n) {
        if (n == 0) {                    // базовый случай
            return 1;
        }
        return n * faktorial(n - 1);     // рекурсивный шаг
    }

    static int raqamlarYigindisi(int n) {
        if (n < 10) {                    // базовый случай: одна цифра
            return n;
        }
        return n % 10 + raqamlarYigindisi(n / 10);
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        System.out.println(faktorial(n) + " " + raqamlarYigindisi(n));
    }
}
```
```cpp
#include <iostream>
using namespace std;

long long faktorial(int n) {
    if (n == 0) {                    // базовый случай
        return 1;
    }
    return n * faktorial(n - 1);     // рекурсивный шаг
}

int raqamlarYigindisi(int n) {
    if (n < 10) {                    // базовый случай: одна цифра
        return n;
    }
    return n % 10 + raqamlarYigindisi(n / 10);
}

int main() {
    int n;
    cin >> n;
    cout << faktorial(n) << " " << raqamlarYigindisi(n) << endl;
    return 0;
}
```

При вводе `5`: `faktorial(5)` = 5 · 4 · 3 · 2 · 1 · 1 = 120; `raqamlar_yigindisi(5)` («сумма цифр») = 5 (сразу базовый случай). Выводится: `120 5`.

При вводе `12`: 12! = 479001600; цифры: `12 % 10 + сумма(1)` = 2 + 1 = 3. Выводится: `479001600 3`.

В обеих функциях сначала проверяется базовый случай — это обычно первая строка рекурсивной функции.

## Разобранный пример 2: Ханойские башни

Есть три стержня: A, B, C. На стержне A — *n* дисков: больший внизу, меньший сверху. Нужно перенести все диски с A на C. Правила: за раз переносится только один диск; больший диск нельзя класть на меньший. Выведите все ходы.

Рекурсивная идея: чтобы перенести *n* дисков с A на C —

1. переносим верхние *n* − 1 дисков с A на B (C — вспомогательный);
2. переносим самый большой диск с A на C;
3. переносим *n* − 1 дисков с B на C (A — вспомогательный).

Базовый случай: *n* = 0 — ничего не делаем.

```python
def xanoy(n, qayerdan, qayerga, yordamchi):
    if n == 0:
        return
    xanoy(n - 1, qayerdan, yordamchi, qayerga)
    print(qayerdan, "->", qayerga)
    xanoy(n - 1, yordamchi, qayerga, qayerdan)


n = int(input())
xanoy(n, "A", "C", "B")
```
```java
import java.util.Scanner;

public class Main {
    static void xanoy(int n, char qayerdan, char qayerga, char yordamchi) {
        if (n == 0) {
            return;
        }
        xanoy(n - 1, qayerdan, yordamchi, qayerga);
        System.out.println(qayerdan + " -> " + qayerga);
        xanoy(n - 1, yordamchi, qayerga, qayerdan);
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        xanoy(n, 'A', 'C', 'B');
    }
}
```
```cpp
#include <iostream>
using namespace std;

void xanoy(int n, char qayerdan, char qayerga, char yordamchi) {
    if (n == 0) {
        return;
    }
    xanoy(n - 1, qayerdan, yordamchi, qayerga);
    cout << qayerdan << " -> " << qayerga << endl;
    xanoy(n - 1, yordamchi, qayerga, qayerdan);
}

int main() {
    int n;
    cin >> n;
    xanoy(n, 'A', 'C', 'B');
    return 0;
}
```

При вводе `3` выводится 7 ходов (*qayerdan* — откуда, *qayerga* — куда, *yordamchi* — вспомогательный):

```text
A -> C
A -> B
C -> B
A -> C
B -> A
B -> C
A -> C
```

Число ходов — 2ⁿ − 1: 3 диска — 7, 10 дисков — 1023, 64 диска — более 18 квинтиллионов. Рекурсивное решение состоит из трёх строк; решение циклом намного сложнее. Это классический пример рекурсии «на своём месте»: мы не продумываем каждый ход, а лишь говорим, как свести задачу к меньшей.

## Разобранный пример 3: двоичная запись

Вводится натуральное число *n*. Выведите его запись в двоичной системе счисления.

Двоичные цифры — остатки от деления на 2, но **в обратном порядке**: последний остаток — первая цифра. Рекурсия сама переворачивает порядок: сначала выводится двоичная запись *n* // 2, потом *n* % 2.

```python
def ikkilik(n):
    if n >= 2:
        ikkilik(n // 2)          # сначала старшие цифры
    print(n % 2, end="")         # затем последняя цифра


n = int(input())
ikkilik(n)
print()
```
```java
import java.util.Scanner;

public class Main {
    static void ikkilik(int n) {
        if (n >= 2) {
            ikkilik(n / 2);          // сначала старшие цифры
        }
        System.out.print(n % 2);     // затем последняя цифра
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        ikkilik(n);
        System.out.println();
    }
}
```
```cpp
#include <iostream>
using namespace std;

void ikkilik(int n) {
    if (n >= 2) {
        ikkilik(n / 2);          // сначала старшие цифры
    }
    cout << n % 2;               // затем последняя цифра
}

int main() {
    int n;
    cin >> n;
    ikkilik(n);
    cout << endl;
    return 0;
}
```

При вводе `13`: `ikkilik(13)` → `ikkilik(6)` → `ikkilik(3)` → `ikkilik(1)`. В базовом случае выводится `1`, затем при возврате: 3 % 2 = `1`, 6 % 2 = `0`, 13 % 2 = `1`. Выводится: `1101` (8 + 4 + 0 + 1 = 13).

Поскольку вывод стоит **после** рекурсивного вызова, цифры выводятся на этапе «возврата», то есть в обратном порядке. Если бы `print` стоял перед вызовом, результат был бы перевёрнут: `1011`.

:::warning
**Частые ошибки**

- **Нет базового случая или до него нельзя дойти.** Если `faktorial(n - 1)` вызывается с отрицательным *n* или `n == 0` не проверяется — стек переполняется.
- **Не возвращать результат рекурсивного вызова.** `faktorial(n - 1) * n` вычисляется, но без `return` — результат теряется.
- **Слишком глубокая рекурсия.** В Python глубина больше 1000 — `RecursionError`; в таких случаях используйте цикл.
- **Повторение одних и тех же вычислений.** Простая рекурсия для Фибоначчи при *n* = 40 делает сотни миллионов вызовов.
- **Накопление результата в глобальной переменной.** Пусть рекурсивная функция отдаёт результат через `return`.
:::

:::tip
Пишите рекурсивную функцию так: сначала базовый случай, затем рекурсивный шаг с мыслью «предположу, что меньшая задача уже решена». Не пытайтесь отследить работу функции на всю глубину — если один шаг верен, верна и вся рекурсия.
:::

## Итоги

- Рекурсивная функция вызывает сама себя; в ней обязательны базовый случай и рекурсивный шаг, уменьшающий задачу.
- Каждый вызов получает кадр в стеке вызовов; рекурсия спускается вниз, затем возвращается, собирая результаты.
- Стек ограничен: рекурсия без базового случая или слишком глубокая переполняет его.
- Рекурсия удобна в древовидных задачах и «разделяй и властвуй» (Ханойские башни: 2ⁿ − 1 ходов).
- Действия после вызова выполняются в обратном порядке (двоичная запись).
- Для простых последовательностей и большой глубины предпочтительнее цикл.

## Проверьте себя

:::check
Q: Какие две части обязательны в рекурсивной функции?
A: Базовый случай (простейший случай, где рекурсия останавливается) и рекурсивный шаг, приближающий задачу к базовому случаю.
Q: Какая ошибка в функции `def f(n): return n + f(n - 1)`?
A: Нет базового случая: рекурсия никогда не остановится, и стек переполнится (в Python — `RecursionError`).
Q: Сколько ходов нужно в задаче о Ханойских башнях для 5 дисков?
A: 2⁵ − 1 = 31.
Q: Что выведет `ikkilik(6)` из примера 3?
A: `110`.
Q: Почему вычислять числа Фибоначчи простой рекурсией медленно?
A: Одни и те же значения вычисляются многократно: и `fib(n-1)`, и `fib(n-2)` внутри вычисляют `fib(n-3)` и так далее; число вызовов растёт экспоненциально.
