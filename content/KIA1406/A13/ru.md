## Почему эта тема важна?

Сетевой администратор и специалист по безопасности должны **видеть, что происходит в сети**: какое устройство с кем общается, какие протоколы используются, не передаются ли пароли без шифрования, нет ли необычной активности. Анализ трафика — основной инструмент поиска неисправностей, проверки соблюдения политики и выявления инцидентов (на него же опираются IDS и SIEM из M14).

:::note
**После этого практического занятия вы сможете:**

- знать правила наблюдения за трафиком только в законных и разрешённых условиях;
- захватывать трафик в Wireshark и анализировать его фильтрами;
- видеть «картину» сети с помощью средств статистики;
- находить нешифрованные протоколы и предлагать замену безопасными аналогами;
- анализировать журналы потоков программой.
:::

:::warning
**Правовые и этические правила.** Наблюдайте трафик только в **своей**, **учебной** или **письменно разрешённой** сети. Перехват чужого трафика без разрешения нарушает неприкосновенность частной жизни, и за это законом предусмотрена ответственность (A3). В организации мониторинг определяется политикой безопасности, и сотрудники о нём уведомлены. Файлы захвата могут содержать пароли и персональные данные — храните их как конфиденциальные и удаляйте после работы.
:::

## Знакомство с Wireshark

**Wireshark** — бесплатный анализатор трафика с открытым кодом (Windows, Linux, macOS). Его окно состоит из трёх частей:

| Часть | Что показывает |
|---|---|
| **Список пакетов** | каждый пакет: время, источник, назначение, протокол, длина, краткое пояснение |
| **Детали пакета** | структура выбранного пакета по уровням (Ethernet → IP → TCP/UDP → приложение) |
| **Байты** | сырые байты пакета (шестнадцатеричные и текст) |

**Подготовка**: выбор интерфейса для захвата (Wi-Fi или Ethernet). **Неразборчивый режим** (promiscuous) — сетевая карта принимает все кадры сегмента, а не только адресованные ей; в современной коммутируемой сети вы всё равно видите в основном свой трафик (для наблюдения всего сегмента на коммутаторе настраивается зеркалирование порта — SPAN, это задача администратора).

## Фильтры захвата и отображения

- **Фильтр захвата** (capture filter, синтаксис BPF) ограничивает, что записывать, **до** захвата: `host 192.168.1.10`, `port 53`.
- **Фильтр отображения** (display filter) выбирает, что **показывать** из записанного:

| Фильтр | Что показывает |
|---|---|
| `http` | трафик HTTP |
| `dns` | DNS-запросы и ответы |
| `tls` | соединения TLS (HTTPS) |
| `ip.addr == 192.168.1.10` | пакеты с участием этого адреса |
| `tcp.port == 443` | TCP на порту 443 |
| `tcp.flags.syn == 1 && tcp.flags.ack == 0` | начало новых TCP-соединений |
| `http.request.method == "POST"` | HTTP-запросы POST |
| `!(arp or dns)` | всё, кроме ARP и DNS |

**Просмотр потока** (Follow → TCP Stream) показывает весь диалог одного соединения в виде текста.

## Средства статистики

| Меню (Statistics) | Польза |
|---|---|
| **Protocol Hierarchy** | распределение трафика по протоколам |
| **Conversations** | сколько данных передано между какими парами |
| **Endpoints** | самые активные адреса («самые разговорчивые») |
| **I/O Graph** | объём трафика во времени — видны резкие всплески |

## Практическая работа

**Лаборатория**: свой компьютер или учебная виртуальная машина; в учебных целях — **собственная тестовая страница**, работающая по HTTP и HTTPS (например, форма входа на учебном веб-сервере, не настоящий пароль: `test123`).

1. Начните захват, откройте несколько сайтов, затем остановите. В **Protocol Hierarchy** запишите, каких протоколов больше всего.
2. Фильтр `dns`: какие домены запрашивались? Есть ли незнакомые домены?
3. Отправьте форму входа на своей тестовой странице по **HTTP** и посмотрите запрос фильтром `http.request.method == "POST"` и через **Follow → TCP Stream**: `test123` виден открытым текстом. Повторите то же по **HTTPS** — с фильтром `tls` виден только зашифрованный поток. Вывод: почему все страницы входа должны работать только по HTTPS.
4. Найдите самые активные адреса через **Conversations** и **Endpoints**.
5. Запишите результаты в отчёт (без персональных данных) и удалите файл захвата.

## Нешифрованные протоколы и их замены

| Нешифрованный | Порт | Безопасная замена |
|---|---|---|
| HTTP | 80 | HTTPS (443) |
| FTP | 21 | SFTP или FTPS |
| Telnet | 23 | SSH (22) |
| POP3 / IMAP | 110 / 143 | POP3S / IMAPS (995 / 993) |
| SNMP v1/v2c | 161 | SNMPv3 |

Один из важных результатов мониторинга — найти такие протоколы в сети и составить план их замены.

## Признаки аномалий

- Много DNS-запросов к незнакомым или подозрительным доменам.
- Большой исходящий трафик в нерабочее время.
- Регулярные короткие соединения внутреннего устройства с незнакомым внешним адресом.
- Неожиданные протоколы (например, Telnet на IoT-устройстве — M15).
- Очень много попыток подключения с одного адреса.

При обнаружении таких признаков они проверяются через процесс реагирования на инциденты (M14).

## tcpdump и журналы потоков

- **tcpdump** — захват трафика в командной строке (на серверах без графического интерфейса): `sudo tcpdump -i eth0 port 53 -w dns.pcap` — результат потом можно открыть в Wireshark.
- **Журналы потоков** (NetFlow, IPFIX, облачные flow logs) — не каждый пакет, а краткие записи о соединениях: от кого, кому, какой порт, сколько байт. Они небольшие, хранятся долго и удобны для наблюдения за большими сетями.

## Разобранный пример: анализ журнала потоков

В каждой строке — соединение: IP источника, IP назначения, порт назначения, байты. Выведите суммарные байты по каждому хосту-источнику в порядке убывания, затем соединения по нешифрованным протоколам (21 — FTP, 23 — Telnet, 80 — HTTP, 110 — POP3, 143 — IMAP) в порядке ввода.

```python
import sys

OCHIQ = {"21": "FTP", "23": "Telnet", "80": "HTTP", "110": "POP3", "143": "IMAP"}

jami, ogohlantirish = {}, []
for satr in sys.stdin.read().split("\n"):
    if not satr.strip():
        continue
    manba, manzil, port, hajm = satr.split()
    jami[manba] = jami.get(manba, 0) + int(hajm)
    if port in OCHIQ:                                 # нешифрованный протокол
        ogohlantirish.append(f"{manba} -> {manzil}:{port} ({OCHIQ[port]})")

for host, h in sorted(jami.items(), key=lambda x: (-x[1], x[0])):
    print(f"{host}: {h} байт")
for o in ogohlantirish:
    print(f"Без шифрования: {o}")
```
```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Map<String, String> ochiq = Map.of("21", "FTP", "23", "Telnet", "80", "HTTP", "110", "POP3", "143", "IMAP");
        Scanner in = new Scanner(System.in);
        Map<String, Long> jami = new LinkedHashMap<>();
        List<String> ogohlantirish = new ArrayList<>();
        while (in.hasNext()) {
            String manba = in.next(), manzil = in.next(), port = in.next();
            long hajm = in.nextLong();
            jami.merge(manba, hajm, Long::sum);
            if (ochiq.containsKey(port))                          // нешифрованный протокол
                ogohlantirish.add(manba + " -> " + manzil + ":" + port + " (" + ochiq.get(port) + ")");
        }
        List<Map.Entry<String, Long>> royxat = new ArrayList<>(jami.entrySet());
        royxat.sort((a, b) -> !a.getValue().equals(b.getValue()) ? Long.compare(b.getValue(), a.getValue()) : a.getKey().compareTo(b.getKey()));
        for (Map.Entry<String, Long> e : royxat) System.out.println(e.getKey() + ": " + e.getValue() + " байт");
        for (String o : ogohlantirish) System.out.println("Без шифрования: " + o);
    }
}
```
```cpp
#include <algorithm>
#include <iostream>
#include <map>
#include <string>
#include <utility>
#include <vector>
using namespace std;

int main() {
    map<string, string> ochiq = {{"21", "FTP"}, {"23", "Telnet"}, {"80", "HTTP"}, {"110", "POP3"}, {"143", "IMAP"}};
    map<string, long long> jami;
    vector<string> ogohlantirish;
    string manba, manzil, port;
    long long hajm;
    while (cin >> manba >> manzil >> port >> hajm) {
        jami[manba] += hajm;
        if (ochiq.count(port))                                    // нешифрованный протокол
            ogohlantirish.push_back(manba + " -> " + manzil + ":" + port + " (" + ochiq[port] + ")");
    }
    vector<pair<string, long long>> royxat(jami.begin(), jami.end());
    sort(royxat.begin(), royxat.end(), [](auto& a, auto& b) {
        return a.second != b.second ? a.second > b.second : a.first < b.first;
    });
    for (auto& [host, h] : royxat) cout << host << ": " << h << " байт\n";
    for (auto& o : ogohlantirish) cout << "Без шифрования: " << o << "\n";
    return 0;
}
```

Вывод:

```text

192.168.1.10: 56800 байт
192.168.1.40: 15900 байт
Без шифрования: 192.168.1.10 -> 93.184.216.34:80 (HTTP)
Без шифрования: 192.168.1.25 -> 10.0.0.5:23 (Telnet)
Без шифрования: 192.168.1.40 -> 203.0.113.9:21 (FTP)
```

Результат анализа — план действий: управлять устройством `10.0.0.5` по SSH вместо Telnet, перевести FTP-сервер на SFTP, сделать HTTPS обязательным для HTTP-сайта. Самый активный хост `192.168.1.25` нужно проверить: соответствует ли его трафик ожидаемой работе.

:::warning
**Частые ошибки**

- **Захватывать трафик в сети без разрешения.** Нарушение закона.
- **Хранить или передавать файл захвата без защиты.** В нём могут быть пароли и персональные данные.
- **Путать фильтры захвата и отображения.** У них разный синтаксис.
- **Считать шифрованный трафик «невидимым, значит проблемой».** Не видеть содержимое TLS — нормально; метаданные (адреса, объём, время) всё равно анализируются.
:::

:::tip
В отчёте приводите только выводы, статистику и замаскированные адреса; не прикладывайте к заданию захваченный файл `.pcap`.
:::

## Итоги

- Трафик наблюдается только в своей, учебной или разрешённой сети; захваченные данные конфиденциальны.
- Wireshark: список пакетов, детали, байты; фильтры захвата (BPF) и отображения.
- Статистика: иерархия протоколов, диалоги, конечные точки, график I/O.
- Практический результат мониторинга — найти нешифрованные протоколы и перейти на HTTPS, SSH, SFTP и подобные, а также проверить аномалии.
- В больших сетях используются журналы потоков (NetFlow) и автоматический анализ.

Q: Чем фильтр захвата отличается от фильтра отображения?
A: Фильтр захвата заранее ограничивает, что записывается; фильтр отображения выбирает, что показывать из записанного.
Q: Почему пароль, отправленный по HTTP, виден в анализаторе трафика?
A: Трафик HTTP не шифруется.
Q: Какая безопасная замена Telnet?
A: SSH.
Q: Какое средство Wireshark показывает самые активные адреса?
A: Statistics → Endpoints (и Conversations).
