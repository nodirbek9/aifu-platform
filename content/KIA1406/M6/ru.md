## Почему это важно

Данные в вашем телефоне, трафик Wi-Fi, HTTPS-страницы, зашифрованные диски — всё это защищено симметричными шифрами, потому что они очень быстрые: современный процессор выполняет AES со скоростью гигабайты в секунду. Но «использовали AES» — ещё не безопасность: неверный режим (например, ECB) или повторённый IV делают бесполезным даже сильный алгоритм. На этой лекции рассмотрим внутреннее устройство симметричных шифров и правила их правильного применения.

- знать раундовую структуру и длины ключа AES;
- сравнивать режимы ECB, CBC, CTR и GCM;
- показывать, почему режим ECB раскрывает структуру данных.

## Принципы Шеннона

В 1949 году Клод Шеннон описал два свойства хорошего шифра:

- **Перемешивание** (confusion) — связь между ключом и шифртекстом должна быть как можно сложнее (подстановки, S-блоки).
- **Рассеивание** (diffusion) — один бит открытого текста должен влиять на многие биты шифртекста (перестановки, перемешивание). Результат — **лавинный эффект**: изменение одного бита меняет примерно половину шифртекста.

## Поточные шифры

Поточный шифр порождает из ключа длинный псевдослучайный **ключевой поток** и побитно складывает его с открытым текстом по **XOR**: *C* = *M* ⊕ *K*ₛ, *M* = *C* ⊕ *K*ₛ (шифрование и расшифрование — одна и та же операция).

- **Одноразовый блокнот** (one-time pad) — ключевой поток истинно случаен, длиной с текст и используется один раз: теоретически абсолютно стоек (доказал Шеннон), но доставка ключа на практике трудна.
- **Важное правило**: никогда не повторяйте ключевой поток. Если два сообщения зашифрованы одним потоком, *C*₁ ⊕ *C*₂ = *M*₁ ⊕ *M*₂ — о текстах многое можно узнать даже без ключа.

**LFSR** (регистр сдвига с линейной обратной связью) — простейший генератор ключевого потока: на каждом шаге регистр сдвигается на бит, новый бит — XOR выбранных «отводов». Хорошо подобранный *n*-битный LFSR имеет период 2ⁿ − 1. Но LFSR **линеен**: по 2*n* выходным битам его структура восстанавливается (алгоритм Берлекэмпа–Мэсси), поэтому сам по себе он небезопасен.

**A5/1** — поточный шифр мобильной связи GSM: три LFSR длиной 19, 22 и 23 бита, 64-битный ключ; регистры сдвигаются неравномерно по **правилу большинства**. В 2000-х его взломали на практике (за секунды с помощью заранее вычисленных таблиц) — поэтому в 3G/4G перешли на более сильные KASUMI, SNOW 3G, AES. Современный поточный шифр сегодня — **ChaCha20** (TLS, WireGuard, Android).

## Блочные шифры

Блочный шифр делит данные на блоки фиксированной длины и преобразует каждый ключом; повторяется несколько **раундов**.

**DES** (1977) — блок 64 бита, ключ 56 бит, **сеть Фейстеля** из 16 раундов. Из-за короткого ключа в 1998 году взломан полным перебором; временное решение — 3DES (трижды DES), сегодня тоже устарел.

**AES** (Rijndael, стандарт США с 2001 года) — блок **128 бит**, ключ **128, 192 или 256** бит, раундов соответственно **10, 12, 14**. Блок рассматривается как матрица «состояния» 4×4 байта; каждый раунд состоит из четырёх шагов:

| Шаг | Назначение | Свойство Шеннона |
|---|---|---|
| **SubBytes** | каждый байт заменяется по таблице S-блока (единственный нелинейный шаг) | перемешивание |
| **ShiftRows** | строки сдвигаются влево на 0, 1, 2, 3 байта | рассеивание |
| **MixColumns** | каждый столбец умножается на матрицу в поле GF(2⁸) | рассеивание |
| **AddRoundKey** | состояние складывается по XOR с раундовым ключом | привязка к ключу |

В последнем раунде MixColumns нет. Раундовые ключи получаются из основного ключа процедурой **расширения ключа**. В современных процессорах есть специальные инструкции для AES (AES-NI).

## Режимы работы

Сообщение обычно длиннее одного блока — **режим** определяет, как связываются блоки.

| Режим | Идея | Особенность |
|---|---|---|
| **ECB** | каждый блок шифруется отдельно | одинаковые блоки → одинаковый шифртекст; **не используйте** |
| **CBC** | каждый блок перед шифрованием складывается по XOR с предыдущим блоком шифртекста; первый — с **IV** | нужен случайный IV, последовательный, нужно дополнение |
| **CTR** | зашифрованный счётчик даёт ключевой поток (превращает блочный шифр в поточный) | параллельный, дополнение не нужно; счётчик не должен повторяться |
| **GCM** | CTR + тег аутентификации | конфиденциальность и целостность вместе (AEAD); стандарт в TLS 1.3 |

**Дополнение** (padding): если последний блок неполный, он дополняется по PKCS#7 (не хватает *k* байт — добавляется *k* байт со значением *k*). **IV** (вектор инициализации) не секретен, но должен быть новым и непредсказуемым для каждого сообщения.

## Разобранный пример 1: LFSR и поточный шифр

16-битный LFSR (обратная связь: XOR битов 0, 2, 3, 5, сдвиг вправо) порождает ключевой поток из начального состояния. Каждый выходной байт — биты, 8 раз взятые из младшего бита регистра. Байты сообщения складываются по XOR с ключевым потоком; повторное выполнение восстанавливает сообщение.

```python
def kalit_oqimi(holat, n):
    natija = []
    for _ in range(n):
        bayt = 0
        for _ in range(8):
            yangi = (holat ^ (holat >> 2) ^ (holat >> 3) ^ (holat >> 5)) & 1   # обратная связь
            bayt = (bayt << 1) | (holat & 1)
            holat = (holat >> 1) | (yangi << 15)
        natija.append(bayt)
    return natija


holat = int(input().strip(), 16)
xabar = input()
oqim = kalit_oqimi(holat, len(xabar))
shifr = [ord(c) ^ k for c, k in zip(xabar, oqim)]
ochilgan = "".join(chr(c ^ k) for c, k in zip(shifr, oqim))   # повторный XOR даёт исходный текст
print("ключевой поток: " + " ".join(format(k, "02x") for k in oqim))
print("шифртекст: " + " ".join(format(c, "02x") for c in shifr))
print("расшифровано: " + ochilgan)
```
```java
import java.util.Scanner;

public class Main {
    static int[] kalitOqimi(int holat, int n) {
        int[] natija = new int[n];
        for (int i = 0; i < n; i++) {
            int bayt = 0;
            for (int j = 0; j < 8; j++) {
                int yangi = (holat ^ (holat >> 2) ^ (holat >> 3) ^ (holat >> 5)) & 1;   // обратная связь
                bayt = (bayt << 1) | (holat & 1);
                holat = (holat >> 1) | (yangi << 15);
            }
            natija[i] = bayt;
        }
        return natija;
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int holat = Integer.parseInt(in.nextLine().trim(), 16);
        String xabar = in.nextLine();
        int[] oqim = kalitOqimi(holat, xabar.length());
        StringBuilder k = new StringBuilder(), s = new StringBuilder(), o = new StringBuilder();
        for (int i = 0; i < xabar.length(); i++) {
            int c = xabar.charAt(i) ^ oqim[i];
            k.append(i > 0 ? " " : "").append(String.format("%02x", oqim[i]));
            s.append(i > 0 ? " " : "").append(String.format("%02x", c));
            o.append((char) (c ^ oqim[i]));                        // повторный XOR даёт исходный текст
        }
        System.out.println("ключевой поток: " + k);
        System.out.println("шифртекст: " + s);
        System.out.println("расшифровано: " + o);
    }
}
```

#include <iostream>

vector<int> kalitOqimi(unsigned holat, size_t n) {
    vector<int> natija;
    for (size_t i = 0; i < n; i++) {
        int bayt = 0;
        for (int j = 0; j < 8; j++) {
            unsigned yangi = (holat ^ (holat >> 2) ^ (holat >> 3) ^ (holat >> 5)) & 1;   // обратная связь
            bayt = (bayt << 1) | (holat & 1);
            holat = (holat >> 1) | (yangi << 15);
        }

    }
    return natija;
}

int main() {
    string satr, xabar;
    getline(cin, satr);
    getline(cin, xabar);
    unsigned holat = stoul(satr, nullptr, 16);

        int c = (unsigned char) xabar[i] ^ oqim[i];

        k += (i ? " " : "") + string(buf);
        snprintf(buf, sizeof buf, "%02x", c);
        s += (i ? " " : "") + string(buf);
        o += (char) (c ^ oqim[i]);                                // повторный XOR даёт исходный текст
    }
    cout << "ключевой поток: " << k << endl;
    cout << "шифртекст: " << s << endl;
    cout << "расшифровано: " << o << endl;

Пример показывает **идею** поточного шифра; на практике применяются ChaCha20 или AES-CTR.

## Разобранный пример 2: различие ECB и CBC

В учебных целях возьмём 8-битный «блочный шифр»: *E*(*b*) = (*b* ⊕ *k*), циклически сдвинутое влево на 3 бита. Примените его в режимах ECB и CBC и сравните результаты для повторяющегося текста. Ввод: ключ и IV (шестнадцатеричные), открытый текст.

```python
def shifr(b, k):
    x = b ^ k
    return ((x << 3) | (x >> 5)) & 0xFF         # циклический сдвиг влево на 3 бита


k = int(input().strip(), 16)
iv = int(input().strip(), 16)
matn = input()
ecb = [shifr(ord(c), k) for c in matn]          # каждый блок отдельно
cbc = []
oldingi = iv
for c in matn:
    oldingi = shifr(ord(c) ^ oldingi, k)         # сцепление с предыдущим шифртекстом
    cbc.append(oldingi)
print("ECB: " + " ".join(format(x, "02x") for x in ecb))
print("CBC: " + " ".join(format(x, "02x") for x in cbc))
```
```java
import java.util.Scanner;

public class Main {
    static int shifr(int b, int k) {
        int x = b ^ k;
        return ((x << 3) | (x >> 5)) & 0xFF;                      // циклический сдвиг влево на 3 бита
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int k = Integer.parseInt(in.nextLine().trim(), 16);
        int iv = Integer.parseInt(in.nextLine().trim(), 16);
        String matn = in.nextLine();
        StringBuilder ecb = new StringBuilder(), cbc = new StringBuilder();
        int oldingi = iv;
        for (int i = 0; i < matn.length(); i++) {
            int c = matn.charAt(i);
            ecb.append(i > 0 ? " " : "").append(String.format("%02x", shifr(c, k)));   // каждый блок отдельно
            oldingi = shifr(c ^ oldingi, k);                       // сцепление с предыдущим шифртекстом
            cbc.append(i > 0 ? " " : "").append(String.format("%02x", oldingi));
        }
        System.out.println("ECB: " + ecb);
        System.out.println("CBC: " + cbc);
    }
}
```
```cpp
#include <cstdio>
#include <iostream>
#include <string>
using namespace std;

int shifr(int b, int k) {
    int x = b ^ k;
    return ((x << 3) | (x >> 5)) & 0xFF;                          // циклический сдвиг влево на 3 бита
}

string hex2(int x) {
    char buf[4];
    snprintf(buf, sizeof buf, "%02x", x);
    return buf;
}

int main() {
    string satr, matn;
    getline(cin, satr);
    int k = stoi(satr, nullptr, 16);
    getline(cin, satr);
    int iv = stoi(satr, nullptr, 16);
    getline(cin, matn);
    string ecb, cbc;
    int oldingi = iv;
    for (size_t i = 0; i < matn.size(); i++) {
        int c = (unsigned char) matn[i];
        ecb += (i ? " " : "") + hex2(shifr(c, k));               // каждый блок отдельно
        oldingi = shifr(c ^ oldingi, k);                          // сцепление с предыдущим шифртекстом
        cbc += (i ? " " : "") + hex2(oldingi);
    }
    cout << "ECB: " << ecb << endl;
    cout << "CBC: " << cbc << endl;
    return 0;
}
```

Ввод:

```text
5C
37
AAAABBBB
```

Вывод:

```text
ECB: e8 e8 e8 e8 f0 f0 f0 f0
CBC: 51 62 fb 37 49 ba 25 d9
```

В ECB четыре `A` превратились в четыре одинаковых `e8` — даже не зная ключа, злоумышленник видит структуру текста (известный пример — изображение пингвина, зашифрованное в ECB, на котором остаётся виден контур). В CBC каждый блок зависит от предыдущего, повторы скрыты. В настоящем AES то же самое происходит на уровне 16-байтных блоков.

:::warning
**Частые ошибки**

- **Использовать режим ECB.** Одинаковые блоки дают одинаковый шифртекст — структура раскрывается.
- **Повторять IV или счётчик CTR.** В поточных режимах и CTR это равносильно повторному использованию ключевого потока — тексты раскрываются.
- **Шифровать без проверки целостности.** CBC и CTR не обнаруживают изменения данных; нужен аутентифицированный режим вроде GCM или отдельный MAC.
- **Устаревшие алгоритмы (DES, RC4, A5/1).** Они взломаны на практике; используйте AES-GCM или ChaCha20-Poly1305.
- **Записывать ключ в код программы.** Ключи хранятся отдельно, в защищённом месте (хранилище ключей, HSM).
:::

:::tip
В онлайн-инструменте CyberChef (gchq.github.io/CyberChef) рецептом «AES Encrypt» зашифруйте текст из одинаковых 16-байтных блоков в режимах ECB и CBC и сравните результаты. Затем измените IV в CBC и посмотрите, как меняется весь шифртекст.
:::

## Итоги

- Хороший шифр обеспечивает перемешивание и рассеивание; лавинный эффект — изменение одного бита меняет половину шифртекста.
- Поточный шифр: *C* = *M* ⊕ ключевой поток; поток нельзя повторять; LFSR линеен, A5/1 взломан, сегодня — ChaCha20.
- AES: блок 128 бит, ключ 128/192/256 бит, 10/12/14 раундов; SubBytes, ShiftRows, MixColumns, AddRoundKey.
- Режимы: ECB (не использовать), CBC (случайный IV), CTR (неповторяющийся счётчик), GCM (конфиденциальность + целостность).
