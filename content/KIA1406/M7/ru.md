## Почему это важно

Симметричное шифрование быстрое, но остаётся вопрос: как двум сторонам, которые никогда не встречались, — например, вашему браузеру и серверу банка — договориться об общем секретном ключе? Отправить ключ по открытой сети нельзя. В 1976 году Диффи и Хеллман, а в 1977 году Ривест, Шамир и Адлеман решили эту задачу «математическим замком»: операцию легко выполнить, а обратить без секретной информации практически невозможно. Сегодня на этой идее держатся каждое HTTPS-соединение, цифровая подпись и мессенджер.

- знать преимущества и проблемы систем с открытым ключом и требования к длине ключа.

## Идея: открытый и закрытый ключ

У каждого пользователя есть **пара** ключей: **открытый** (публикуется для всех) и **закрытый** (только у владельца). Сообщение, зашифрованное открытым ключом, открывается только закрытым. Это похоже на почтовый ящик: письмо в щель может бросить любой, а открыть ящик — только владелец ключа.

Основа — **односторонняя функция**: вычислить *f*(*x*) легко, а найти *x* по *f*(*x*) трудно. Например, перемножить два больших простых числа — миллисекунды; разложить 600-значное произведение на простые множители — миллиарды лет. В функции с **лазейкой** (trapdoor) при наличии секретной дополнительной информации (*p* и *q*) обратная операция тоже становится лёгкой.

## Модульная арифметика

| Понятие | Определение | Пример |
|---|---|---|
| Вычет по модулю | *a* mod *n* — остаток от деления *a* на *n* | 17 mod 5 = 2 |
| Степень по модулю | *a*ᵇ mod *n* | 3⁴ mod 5 = 81 mod 5 = 1 |
| НОД | наибольший общий делитель; алгоритмом Евклида | НОД(48, 18) = 6 |
| Обратный элемент | *a*·*x* ≡ 1 (mod *n*); существует только при НОД(*a*, *n*) = 1; расширенным алгоритмом Евклида | 3·7 ≡ 1 (mod 10) |
| Функция Эйлера φ(*n*) | число чисел из 1..*n*, взаимно простых с *n*; для простых *p*, *q*: φ(*pq*) = (*p* − 1)(*q* − 1) | φ(15) = 2·4 = 8 |
| Теорема Эйлера | если НОД(*a*, *n*) = 1, то *a*^φ(*n*) ≡ 1 (mod *n*) | 2⁸ mod 15 = 1 |

Большие степени вычисляются методом **«возведи в квадрат и умножь»**: для *a*ᵇ по двоичной записи *b* основание на каждом шаге возводится в квадрат и на единичных битах умножается в результат — ~2048 шагов для 2048-битного показателя, а не 2²⁰⁴⁸.

## Обмен ключами Диффи–Хеллмана

1. Открытые параметры: большое простое *p* и генератор *g*.
2. Алиса выбирает секретное *a* и отправляет *A* = *g*ᵃ mod *p*; Боб с секретным *b* отправляет *B* = *g*ᵇ mod *p*.
3. Алиса вычисляет *s* = *B*ᵃ mod *p*, Боб — *s* = *A*ᵇ mod *p*; оба равны *g*ᵃᵇ mod *p*.

Подслушивающий видит *p*, *g*, *A*, *B*, но чтобы найти *s*, он должен решить задачу **дискретного логарифма** (найти *a* по *A*) — практически невозможно для большого *p*. Важно: простой DH не проверяет **подлинность** сторон — против «человека посередине» его используют вместе с цифровой подписью или сертификатами (так в TLS).

## RSA

**Генерация ключей**:

1. Выбираются два больших простых числа *p* и *q* (~1024 бита каждое).
2. *n* = *p*·*q*, φ(*n*) = (*p* − 1)(*q* − 1).
3. Выбирается открытая экспонента *e*: НОД(*e*, φ(*n*)) = 1 (обычно *e* = 65537).
4. Закрытая экспонента *d* = *e*⁻¹ mod φ(*n*).
5. Открытый ключ — (*e*, *n*), закрытый — (*d*, *n*); *p*, *q*, φ(*n*) уничтожаются или держатся в секрете.

**Шифрование**: *c* = *m*ᵉ mod *n*; **расшифрование**: *m* = *c*ᵈ mod *n* (верно благодаря теореме Эйлера). **Подпись**: *s* = *h*ᵈ mod *n* (хеш сообщения закрытым ключом), проверка — *s*ᵉ mod *n* = *h*.

**Стойкость** основана на трудности разложения *n* на *p* и *q*: кто знает *p* и *q*, вычислит φ(*n*), а значит и *d*. Современная рекомендация — *n* не менее **2048 бит** (3072 бита после 2030 года). На практике «голый» RSA не используется: сообщение **дополняется** (OAEP — для шифрования, PSS — для подписи), иначе одинаковое сообщение даёт одинаковый шифртекст и возможны математические атаки. Программа генерации ключей, шифрования и расшифрования RSA — задание практического занятия A7.

## Эллиптические кривые (ECC)

Стойкость ECC основана на задаче дискретного логарифма на точках эллиптической кривой. Её преимущество — та же стойкость при гораздо более коротких ключах:

| Симметричный эквивалент | RSA / DH | ECC |
|---|---|---|
| 80 бит | 1024 бита | 160 бит |
| 128 бит | 3072 бита | 256 бит |
| 256 бит | 15360 бит | 512 бит |

Поэтому телефоны, смарт-карты и современные протоколы предпочитают ECC (ECDHE, ECDSA, Ed25519).

## Преимущества и проблемы

| Преимущества | Проблемы |
|---|---|
| решает проблему распределения ключей | в сотни–тысячи раз медленнее симметричных шифров |
| цифровая подпись и неотказуемость | длинные ключи |
| 2*n* ключей на *n* пользователей (у симметричных *n*(*n* − 1)/2) | нужно подтверждать подлинность открытого ключа (PKI, сертификаты) |
| | квантовые компьютеры (алгоритм Шора) могут взломать RSA и ECC — начался переход на постквантовые алгоритмы (ML-KEM, ML-DSA) |

## Разобранный пример 1: Диффи–Хеллман

Ввод: *p*, *g*, секрет Алисы *a* и секрет Боба *b*. Выведите открытые значения *A*, *B* и общий ключ, вычисленный каждой стороной. Степень вычисляйте методом «возведи в квадрат и умножь».

```python
def daraja(asos, kor, modul):
    natija = 1
    asos %= modul
    while kor > 0:
        if kor & 1:                               # единичный бит в двоичной записи
            natija = natija * asos % modul
        asos = asos * asos % modul                # возведение в квадрат
        kor >>= 1
    return natija


p, g, a, b = map(int, input().split())
A = daraja(g, a, p)                               # отправляет Алиса
B = daraja(g, b, p)                               # отправляет Боб
print("A = " + str(A) + ", B = " + str(B))
print("Алиса: " + str(daraja(B, a, p)) + ", Боб: " + str(daraja(A, b, p)))
```
```java
import java.util.Scanner;

public class Main {
    static long daraja(long asos, long kor, long modul) {
        long natija = 1;
        asos %= modul;
        while (kor > 0) {
            if ((kor & 1) == 1) {                                  // единичный бит в двоичной записи
                natija = natija * asos % modul;
            }
            asos = asos * asos % modul;                            // возведение в квадрат
            kor >>= 1;
        }
        return natija;
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        long p = in.nextLong(), g = in.nextLong(), a = in.nextLong(), b = in.nextLong();
        long A = daraja(g, a, p);                                  // отправляет Алиса
        long B = daraja(g, b, p);                                  // отправляет Боб
        System.out.println("A = " + A + ", B = " + B);
        System.out.println("Алиса: " + daraja(B, a, p) + ", Боб: " + daraja(A, b, p));
    }
}
```
```cpp
#include <iostream>
using namespace std;

long long daraja(long long asos, long long kor, long long modul) {
    long long natija = 1;
    asos %= modul;
    while (kor > 0) {
        if (kor & 1) {                                             // единичный бит в двоичной записи
            natija = natija * asos % modul;
        }
        asos = asos * asos % modul;                                // возведение в квадрат
        kor >>= 1;
    }
    return natija;
}

int main() {
    long long p, g, a, b;
    cin >> p >> g >> a >> b;
    long long A = daraja(g, a, p);                                 // отправляет Алиса
    long long B = daraja(g, b, p);                                 // отправляет Боб
    cout << "A = " << A << ", B = " << B << endl;
    cout << "Алиса: " << daraja(B, a, p) << ", Боб: " << daraja(A, b, p) << endl;
    return 0;
}
```

Ввод (классический учебный пример):

```text
23 5 6 15
```

Вывод:

```text
A = 8, B = 19
Алиса: 2, Боб: 2
```

Ни разу не передав ключ, обе стороны получили одинаковое `2`. Для большего числа вроде *p* = 2147483647 программа тоже работает мгновенно (*p* < 2³¹ берётся, чтобы произведения помещались в 64 бита); в реальных системах *p* — 2048 бит и больше, используются библиотеки больших чисел.

## Разобранный пример 2: взлом маленького модуля RSA

Если злоумышленник разложит *n* из открытого ключа на простые множители, он сможет вычислить закрытый ключ. Разложите *n* каждой строки пробным делением (до √*n*): `n = p * q` или `простое`.

```python
import sys

for satr in sys.stdin.read().split():
    n = int(satr)
    d = 2
    topildi = None
    while d * d <= n:                             # достаточно до √n
        if n % d == 0:
            topildi = d
            break
        d += 1
    if topildi is None:
        print(str(n) + ": простое")
    else:
        print(str(n) + " = " + str(topildi) + " * " + str(n // topildi))
```
```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        while (in.hasNextLong()) {
            long n = in.nextLong();
            long topildi = 0;
            for (long d = 2; d * d <= n; d++) {                    // достаточно до √n
                if (n % d == 0) {
                    topildi = d;
                    break;
                }
            }
            if (topildi == 0) {
                System.out.println(n + ": простое");
            } else {
                System.out.println(n + " = " + topildi + " * " + n / topildi);
            }
        }
    }
}
```
```cpp
#include <iostream>
using namespace std;

int main() {
    long long n;
    while (cin >> n) {
        long long topildi = 0;
        for (long long d = 2; d * d <= n; d++) {                   // достаточно до √n
            if (n % d == 0) {
                topildi = d;
                break;
            }
        }
        if (topildi == 0) {
            cout << n << ": простое" << endl;
        } else {
            cout << n << " = " << topildi << " * " << n / topildi << endl;
        }
    }
    return 0;
}
```

Ввод:

```text
3233
1022117
1000003
999962000357
```

Вывод:

```text
3233 = 53 * 61
1022117 = 1009 * 1013
1000003: простое
999962000357 = 999979 * 999983
```

Для разложения 12-значного *n* хватает ~10⁶ делений — меньше секунды. Каждая добавленная цифра увеличивает работу примерно в √10 ≈ 3 раза; даже лучшими алгоритмами (решето числового поля) разложить 2048-битное (617-значное) *n* сегодня невозможно. Стойкость RSA основана именно на этом разрыве.

:::warning
**Частые ошибки**

- **Путать закрытый и открытый ключи.** Шифруют **открытым** ключом получателя; подписывают **закрытым** ключом отправителя.
- **Короткие ключи.** RSA 1024 бита устарел; не менее 2048 бит или ECC 256 бит.
- **«Учебный» RSA без дополнения.** Одинаковое сообщение даёт одинаковый шифртекст и уязвимо к атакам; используйте OAEP/PSS.
- **Шифровать RSA большие данные.** RSA медленный и ограничен по длине; он нужен только для передачи симметричного ключа или подписи.
- **Использовать DH без аутентификации.** «Человек посередине» договаривается с каждой стороной об отдельном ключе и читает трафик.
:::

:::tip
Если установлен OpenSSL (он есть в Git Bash), создайте и рассмотрите настоящий ключ RSA командами `openssl genrsa -out kalit.pem 2048` и `openssl rsa -in kalit.pem -text -noout`: modulus (*n*), publicExponent (*e* = 65537), privateExponent (*d*), prime1 и prime2 (*p*, *q*). Никому не показывайте этот файл — это закрытый ключ.
:::

## Итоги

- Криптография с открытым ключом решает проблему распределения ключей и даёт цифровую подпись; основа — односторонние функции с лазейкой.
- Модульная арифметика: степень («возведи в квадрат и умножь»), НОД, обратный элемент, φ(*n*), теорема Эйлера.
- Диффи–Хеллман: *A* = *g*ᵃ, *B* = *g*ᵇ, общий *s* = *g*ᵃᵇ mod *p*; стойкость — дискретный логарифм; нужна аутентификация.
- RSA: *n* = *pq*, *ed* ≡ 1 (mod φ), *c* = *m*ᵉ, *m* = *c*ᵈ mod *n*; стойкость — трудность факторизации; 2048+ бит и дополнение.
- ECC — та же стойкость при коротких ключах; квантовая угроза требует перехода на постквантовые алгоритмы.

## Проверьте себя

:::check
Q: Какую главную задачу решает криптография с открытым ключом?
A: Безопасное согласование секретного ключа между сторонами, которые никогда не встречались (проблема распределения ключей).
Q: Если p = 11, q = 13, чему равны n и φ(n)?
A: n = 143, φ(n) = 10 · 12 = 120.
Q: На трудности какой математической задачи основана стойкость RSA?
A: Разложения большого числа на простые множители (факторизации).
Q: Что видит подслушивающий в Диффи–Хеллмане и почему не может найти ключ?
A: p, g, A и B; чтобы найти a или b, нужно решить задачу дискретного логарифма.
Q: Почему 256-битный ключ ECC считается равным 3072-битному RSA?
A: Для дискретного логарифма на эллиптических кривых не известны субэкспоненциальные алгоритмы, поэтому более короткий ключ даёт ту же стойкость.
