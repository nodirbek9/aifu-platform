## Почему это важно

На лекции M2 мы рассмотрели теорию матрицы рисков. На практике самое трудное — не применить формулу, а **последовательно оценить вероятность и последствия**: почему «4», а не «3»? Чтобы разные специалисты не оценивали один и тот же риск по-разному, для шкал записываются точные критерии. На этом занятии пошагово проведём полную оценку для небольшой организации и покажем результат на тепловой карте.

:::note
**После этого занятия вы сможете:**

- записывать точные критерии для шкал вероятности и последствий;
- составлять перечень рисков организации и последовательно их оценивать;
- изображать результат на тепловой карте;
- назначать для каждого риска владельца, меру и остаточный уровень;
- сравнивать результаты двух оценок и анализировать динамику рисков.
:::

## Критерии шкал

**Вероятность**:

| Балл | Уровень | Критерий |
|---|---|---|
| 1 | Редко | реже раза в 10 лет |
| 2 | Маловероятно | раз в 3–10 лет |
| 3 | Возможно | раз в 1–3 года |
| 4 | Вероятно | несколько раз в год |
| 5 | Почти неизбежно | раз в месяц и чаще |

**Последствия**:

| Балл | Уровень | Финансовые | Операционные | Репутация и право |
|---|---|---|---|---|
| 1 | Ничтожные | < 1 млн сумов | простой несколько минут | нет влияния |
| 2 | Малые | 1–10 млн | несколько часов | внутренние жалобы |
| 3 | Умеренные | 10–100 млн | 1 день | местные СМИ |
| 4 | Крупные | 100 млн – 1 млрд | несколько дней | штраф, национальные СМИ |
| 5 | Катастрофические | > 1 млрд | больше недели | потеря лицензии, уголовная ответственность |

Если последствия оцениваются по нескольким столбцам, берётся **наибольший** балл.

## Практическая работа: учебный центр «Bilim»

Организация: 40 сотрудников, 600 слушателей, один сервер (база слушателей и бухгалтерия), Wi-Fi, страница онлайн-оплаты.

1. **Активы**: база слушателей, бухгалтерия, сайт и страница оплаты, ноутбуки сотрудников, серверная, репутация.
2. **Пары угроза–уязвимость** (каждая — отдельный риск): фишинг (сотрудники не обучены), шифровальщик (нет резервных копий), кража ноутбука (диск не зашифрован), DDoS (нет защиты), внутренний нарушитель (широкие права), пожар (нет системы пожаротушения в серверной), простые пароли (нет политики), неисправность системы видеонаблюдения.
3. **Оценка**: каждому риску по критериям ставятся вероятность и последствия; двое-трое сотрудников оценивают независимо, результаты обсуждаются.
4. **Матрица и карта** — программой ниже.
5. **Меры и владельцы**: для критических и высоких рисков — план со сроками и ответственными.
6. **Остаточный риск**: ожидаемые вероятность и последствия после меры.

Программа, классифицирующая риски и упорядочивающая их по уровню, — самостоятельное задание этого занятия (KIA-A2).

## Разобранный пример 1: тепловая карта

В первой строке — число рисков, затем каждый риск: название, вероятность и последствия (1–5). Выведите карту 5×5: строки — вероятность от 5 до 1, столбцы — последствия от 1 до 5, в каждой ячейке — число рисков в ней (`.` — риска нет).

```python
n = int(input())
xarita = [[0] * 6 for _ in range(6)]           # [вероятность][последствия]
for _ in range(n):
    nom, e, t = input().split()
    xarita[int(e)][int(t)] += 1
print("  | 1 2 3 4 5")
for e in range(5, 0, -1):                       # вверху — самые вероятные
    kataklar = [str(xarita[e][t]) if xarita[e][t] else "." for t in range(1, 6)]
    print(str(e) + " | " + " ".join(kataklar))
print("всего: " + str(n))
```
```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        int[][] xarita = new int[6][6];                      // [вероятность][последствия]
        for (int i = 0; i < n; i++) {
            in.next();
            int e = in.nextInt();
            int t = in.nextInt();
            xarita[e][t]++;
        }
        System.out.println("  | 1 2 3 4 5");
        for (int e = 5; e >= 1; e--) {                       // вверху — самые вероятные
            StringBuilder qator = new StringBuilder(e + " |");
            for (int t = 1; t <= 5; t++) qator.append(" ").append(xarita[e][t] > 0 ? String.valueOf(xarita[e][t]) : ".");
            System.out.println(qator);
        }
        System.out.println("всего: " + n);
    }
}
```
```cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    int n;
    cin >> n;
    int xarita[6][6] = {};                                    // [вероятность][последствия]
    for (int i = 0; i < n; i++) {
        string nom;
        int e, t;
        cin >> nom >> e >> t;
        xarita[e][t]++;
    }
    cout << "  | 1 2 3 4 5" << endl;
    for (int e = 5; e >= 1; e--) {                            // вверху — самые вероятные
        string qator = to_string(e) + " |";
        for (int t = 1; t <= 5; t++) qator += " " + (xarita[e][t] > 0 ? to_string(xarita[e][t]) : string("."));
        cout << qator << endl;
    }
    cout << "всего: " << n << endl;
    return 0;
}
```

Ввод (названия рисков на узбекском: фишинг, шифровальщик, ноутбук, DDoS, инсайдер, пожар, простой пароль, камера):

```text
8
Fishing 4 3
Shifrlovchi 3 5
Noutbuk 3 2
DDoS 2 4
Insayder 2 5
Yongin 1 5
Oddiy_parol 4 3
Kamera 1 1
```

Вывод:

```text
  | 1 2 3 4 5
5 | . . . . .
4 | . . 2 . .
3 | . 1 . . 1
2 | . . . 1 1
1 | 1 . . . 1
всего: 8
```

Ячейки ближе к правому верхнему углу карты — самые опасные. Здесь два риска (фишинг и простые пароли) в одной ячейке — оба можно снизить одной мерой (обучение сотрудников + MFA). «Пожар» в правом нижнем углу маловероятен, но катастрофичен — такие риски нужно рассматривать отдельно по последствиям, а не только по баллу.

## Разобранный пример 2: динамика между двумя оценками

После принятия мер риски оценили повторно. В каждой строке: название, прежние вероятность и последствия, новые вероятность и последствия. Для каждого риска выведите изменение уровня (`снизился`, `вырос`, `не изменился`) и сумму уровней.

```python
import sys

oldin_jami = keyin_jami = 0
for satr in sys.stdin.read().strip().split("\n")[1:]:
    nom, e1, t1, e2, t2 = satr.split()
    oldin = int(e1) * int(t1)
    keyin = int(e2) * int(t2)
    oldin_jami += oldin
    keyin_jami += keyin
    holat = "снизился" if keyin < oldin else "вырос" if keyin > oldin else "не изменился"
    print(nom + ": " + str(oldin) + " -> " + str(keyin) + " " + holat)
print("всего: " + str(oldin_jami) + " -> " + str(keyin_jami))
```
```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        int oldinJami = 0, keyinJami = 0;
        for (int i = 0; i < n; i++) {
            String nom = in.next();
            int oldin = in.nextInt() * in.nextInt();
            int keyin = in.nextInt() * in.nextInt();
            oldinJami += oldin;
            keyinJami += keyin;
            String holat = keyin < oldin ? "снизился" : keyin > oldin ? "вырос" : "не изменился";
            System.out.println(nom + ": " + oldin + " -> " + keyin + " " + holat);
        }
        System.out.println("всего: " + oldinJami + " -> " + keyinJami);
    }
}
```
```cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    int n;
    cin >> n;
    int oldinJami = 0, keyinJami = 0;
    for (int i = 0; i < n; i++) {
        string nom;
        int e1, t1, e2, t2;
        cin >> nom >> e1 >> t1 >> e2 >> t2;
        int oldin = e1 * t1;
        int keyin = e2 * t2;
        oldinJami += oldin;
        keyinJami += keyin;
        string holat = keyin < oldin ? "снизился" : keyin > oldin ? "вырос" : "не изменился";
        cout << nom << ": " << oldin << " -> " << keyin << " " << holat << endl;
    }
    cout << "всего: " << oldinJami << " -> " << keyinJami << endl;
    return 0;
}
```

Ввод:

```text
4
Fishing 4 3 2 3
Shifrlovchi 3 5 3 2
DDoS 2 4 3 4
Kamera 1 1 1 1
```

Вывод:

```text
Fishing: 12 -> 6 снизился
Shifrlovchi: 15 -> 6 снизился
DDoS: 8 -> 12 вырос
Kamera: 1 -> 1 не изменился
всего: 36 -> 25
```

Обучение снизило **вероятность** фишинга, а резервное копирование — **последствия** шифровальщика: меры действуют на разные оси матрицы. Риск DDoS вырос: организация расширила онлайн-оплату, и теперь простой сайта наносит больше вреда — риски меняются не только из-за мер, но и из-за изменений в бизнесе.

:::warning
**Частые ошибки**

- **Оценивать без критериев.** «По-моему, 4» — разные люди дают разный результат; запишите для шкалы точный критерий.
- **Оценивать только угрозу, а не пару угроза–уязвимость.** «Вирусы» — слишком общо; «шифровальщик на сервере без резервных копий» — риск, который можно оценить.
- **Игнорировать маловероятные, но катастрофические риски.** Пожар или наводнение случаются редко, но могут уничтожить организацию.
- **Не переоценивать после меры.** Эффект меры можно узнать, только измерив остаточный риск.
:::

:::tip
Оцените по критериям выше 6–8 цифровых рисков для своей семьи или общежития (потеря телефона, утечка пароля, подключение постороннего к Wi-Fi и т. п.) и нарисуйте тепловую карту. Для двух самых высоких рисков запишите по одной недорогой мере.
:::

## Итоги

- Для шкал вероятности и последствий записываются точные измеримые критерии; последствия оцениваются по нескольким столбцам, берётся наибольший.
- Риск — пара угроза–уязвимость; каждая оценивается отдельно.
- Тепловая карта показывает распределение рисков и помогает найти группы, закрываемые одной мерой.
- Меры снижают вероятность или последствия; динамика рисков отслеживается повторной оценкой.

## Проверьте себя

:::check
Q: Зачем для шкалы вероятности записываются точные критерии (например, «несколько раз в год»)?
A: Чтобы разные оценщики давали одинаковый результат, а оценка была последовательной и воспроизводимой.
Q: Если финансовые последствия — 2, а репутационные — 4, какой балл берётся?
A: 4 — наибольший балл.
Q: Какую составляющую риска шифровальщика снижают резервные копии?
A: Последствия — данные восстанавливаются, простой сокращается.
Q: Где на тепловой карте располагаются самые опасные риски?
A: В правом верхнем углу — высокая вероятность и тяжёлые последствия.
Q: Почему уровень риска может вырасти, даже если меры не менялись?
A: Меняется бизнес или среда: новая услуга, новая угроза, рост стоимости актива.
:::
