## Почему это важно

Даже самый дорогой межсетевой экран не защитит организацию, если сотрудники пишут пароли на стикерах или у каждого есть права администратора. Безопасность строится **системно**: сначала руководство определяет, что и как нужно защищать (стратегия и политика), затем эти правила превращаются в технические решения и повседневные действия. На этой лекции познакомимся с чертежом «здания» безопасности — архитектурой и политиками.

## Принципы архитектуры

| Принцип | Смысл | Пример |
|---|---|---|
| **Эшелонированная защита** | несколько независимых слоёв защиты | межсетевой экран + сегментация + антивирус + шифрование |
| **Наименьшие привилегии** (least privilege) | каждому — только права, нужные для работы | бухгалтер имеет доступ только к папке финансов |
| **Разделение обязанностей** (separation of duties) | важное действие требует участия нескольких лиц | платёж вводит один, утверждает другой |
| **Запрет по умолчанию** (default deny) | запрещено всё, что явно не разрешено | последнее правило межсетевого экрана — «запретить всё» |
| **Безопасность по умолчанию** (secure by default) | система поставляется с безопасными настройками | смена стандартного пароля при первом входе обязательна |
| **Простота** | в сложной системе больше ошибок | отключение ненужных служб |
| **Нулевое доверие** (Zero Trust) | даже тем, кто внутри сети, не доверяют автоматически; каждый запрос проверяется | MFA и проверка состояния устройства при входе в каждое приложение |

## Стратегия безопасности

**Стратегия** — долгосрочные цели организации в области безопасности и пути их достижения: какие активы важнее всего, какой уровень риска допустим, какие ресурсы выделяются, какими показателями измеряется прогресс. Стратегия согласуется с целями бизнеса — безопасность не ради себя, а ради деятельности организации.

## Иерархия документов

| Уровень | Документ | Содержание | Пример |
|---|---|---|---|
| 1 | **Политика** (policy) | что делается и зачем; утверждается руководством; меняется редко | «Все конфиденциальные данные должны шифроваться» |
| 2 | **Стандарт** (standard) | обязательные конкретные требования | «Шифрование — AES-256, ключи меняются раз в год» |
| 3 | **Процедура** (procedure) | как выполнить пошагово | «Включение BitLocker на ноутбуке: 1) … 2) …» |
| 4 | **Руководство** (guideline) | рекомендации, необязательные | «Рекомендуется использовать парольную фразу вместо пароля» |
| — | **Базовый уровень** (baseline) | минимальные безопасные настройки систем | «CIS Benchmark для Windows Server» |

## Виды политик

- **Общая (программная) политика** — общий подход организации к безопасности, роли и ответственность; подписывает руководитель.
- **Проблемно-ориентированные политики** — по конкретному вопросу: использование Интернета и электронной почты, мобильные устройства (BYOD), удалённая работа.
- **Системные политики** — для конкретной системы: «правила доступа к бухгалтерской системе 1С».

Примеры политик:

| Политика | Основные правила |
|---|---|
| **AUP** (допустимое использование) | как можно и нельзя пользоваться ресурсами организации |
| **Политика паролей** | длина, сложность, смена, MFA, блокировка |
| **Управление доступом** | порядок выдачи и отзыва прав, регулярный пересмотр |
| **Классификация данных** | открытые, внутренние, конфиденциальные, строго конфиденциальные — и требования защиты для каждых |
| **Резервное копирование** | что, как часто и где хранить; проверка восстановления |
| **Реагирование на инциденты** | кто, в каком порядке и как быстро действует |

Хорошая политика: понятная, краткая, выполнимая, с назначенным ответственным и сроком пересмотра, доведённая до сотрудников (под подпись) и с указанием ответственности за нарушение.

## ISO/IEC 27001 и СУИБ

**СУИБ** (система управления информационной безопасностью, ISMS) — единая система политик, процессов, ролей и мер защиты. **ISO/IEC 27001** — стандарт требований к СУИБ; организация может получить сертификат соответствия. В его приложении (Annex A) 93 меры защиты разделены на 4 группы: организационные, связанные с персоналом, физические и технологические. СУИБ работает по циклу **PDCA**: Plan (планирование) → Do (выполнение) → Check (проверка) → Act (улучшение).

## Разобранный пример: аудит наименьших привилегий

Политика определяет права, нужные каждой роли. Аудит сравнивает фактические права каждого пользователя с требованиями его роли. В первой строке — число ролей, затем каждая роль: название и права через запятую. Затем число пользователей и каждый: имя, роль, фактические права. Для каждого пользователя выведите лишние (не требуемые ролью) и недостающие права в алфавитном порядке.

```python
rollar = {}
for _ in range(int(input())):
    nom, huquqlar = input().split()
    rollar[nom] = set(huquqlar.split(","))
for _ in range(int(input())):
    user, rol, huquqlar = input().split()
    bor = set(huquqlar.split(","))
    kerak = rollar.get(rol, set())
    ortiqcha = sorted(bor - kerak)                # нарушение наименьших привилегий
    yetishmaydi = sorted(kerak - bor)
    if not ortiqcha and not yetishmaydi:
        print(user + ": соответствует")
        continue
    qismlar = []
    if ortiqcha:
        qismlar.append("лишние " + ",".join(ortiqcha))
    if yetishmaydi:
        qismlar.append("недостаёт " + ",".join(yetishmaydi))
    print(user + ": " + "; ".join(qismlar))
```
```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.HashMap;
import java.util.List;
import java.util.Map;
import java.util.Scanner;
import java.util.TreeSet;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        Map<String, TreeSet<String>> rollar = new HashMap<>();
        int r = in.nextInt();
        for (int i = 0; i < r; i++) {
            String nom = in.next();
            rollar.put(nom, new TreeSet<>(Arrays.asList(in.next().split(","))));
        }
        int u = in.nextInt();
        for (int i = 0; i < u; i++) {
            String user = in.next();
            String rol = in.next();
            TreeSet<String> bor = new TreeSet<>(Arrays.asList(in.next().split(",")));
            TreeSet<String> kerak = rollar.getOrDefault(rol, new TreeSet<>());
            TreeSet<String> ortiqcha = new TreeSet<>(bor);
            ortiqcha.removeAll(kerak);                              // нарушение наименьших привилегий
            TreeSet<String> yetishmaydi = new TreeSet<>(kerak);
            yetishmaydi.removeAll(bor);
            if (ortiqcha.isEmpty() && yetishmaydi.isEmpty()) {
                System.out.println(user + ": соответствует");
                continue;
            }
            List<String> qismlar = new ArrayList<>();
            if (!ortiqcha.isEmpty()) qismlar.add("лишние " + String.join(",", ortiqcha));
            if (!yetishmaydi.isEmpty()) qismlar.add("недостаёт " + String.join(",", yetishmaydi));
            System.out.println(user + ": " + String.join("; ", qismlar));
        }
    }
}
```

```cpp
#include <algorithm>
#include <iostream>

set<string> ajrat(const string& s) {
    set<string> natija;
    stringstream ss(s);
    string h;
    while (getline(ss, h, ',')) natija.insert(h);
    return natija;
}

string birlashtir(const set<string>& s) {
    string natija;
    for (auto& h : s) natija += (natija.empty() ? "" : ",") + h;
    return natija;
}

int main() {
    map<string, set<string>> rollar;
    int r;
    cin >> r;
    for (int i = 0; i < r; i++) {
        string nom, huquqlar;
        cin >> nom >> huquqlar;
        rollar[nom] = ajrat(huquqlar);
    }
    int u;
    cin >> u;
    for (int i = 0; i < u; i++) {
        string user, rol, huquqlar;
        cin >> user >> rol >> huquqlar;
        set<string> bor = ajrat(huquqlar), kerak = rollar[rol], ortiqcha, yetishmaydi;
        set_difference(bor.begin(), bor.end(), kerak.begin(), kerak.end(), inserter(ortiqcha, ortiqcha.end()));   // нарушение наименьших привилегий
        set_difference(kerak.begin(), kerak.end(), bor.begin(), bor.end(), inserter(yetishmaydi, yetishmaydi.end()));
        if (ortiqcha.empty() && yetishmaydi.empty()) {
            cout << user << ": соответствует" << endl;
            continue;
```

Ввод (названия ролей на узбекском: бухгалтер, преподаватель, студент):

```text
3
buxgalter finance_read,finance_write
oqituvchi grades_read,grades_write,lms
talaba lms,grades_read
4
dilnoza buxgalter finance_read,finance_write
bobur oqituvchi grades_read,grades_write,lms,finance_read
aziz talaba lms,grades_read,grades_write
sardor oqituvchi lms
```

Вывод:

```text
dilnoza: соответствует
bobur: лишние finance_read
aziz: лишние grades_write
sardor: недостаёт grades_read,grades_write
```

Самая опасная находка — `aziz`: у студента есть право **изменять** оценки. Такое «накопление прав» обычно возникает, когда сотрудник переходит в другой отдел, а старые права у него не отзывают; поэтому политика доступа требует пересматривать права не реже раза в квартал.

:::warning
**Частые ошибки**

- **Копировать политику из Интернета.** Политика должна соответствовать реальным процессам и рискам организации, иначе её никто не выполняет.
- **Путать политику и процедуру.** Политика — «что и зачем», процедура — «как».
- **Не знакомить сотрудников с политикой.** Неизвестное правило выполнить нельзя; ознакомление фиксируется подписью.
- **Только добавлять права и никогда не отзывать.** Со временем у всех оказывается доступ «ко всему».
- **Считать нулевое доверие одним продуктом.** Zero Trust — архитектурный подход, а не продукт.
:::

Напишите одностраничный проект AUP для компьютерного класса вашего университета: разрешённое использование, запреты (установка посторонних программ, использование чужих учётных записей), персональные данные, ответственность за нарушения и ответственное лицо.

## Итоги

- Принципы архитектуры: эшелонированная защита, наименьшие привилегии, разделение обязанностей, запрет по умолчанию, безопасность по умолчанию, простота, нулевое доверие.
- Иерархия документов: политика → стандарт → процедура → руководство; базовый уровень — минимальные настройки.
- Виды политик: общая, проблемно-ориентированная, системная; примеры — AUP, пароли, доступ, классификация, резервное копирование, реагирование на инциденты.
- ISO/IEC 27001 — требования к СУИБ; цикл PDCA.
- Регулярный аудит прав выявляет нарушения принципа наименьших привилегий.

## Проверьте себя

:::check
Q: Какой документ находится на самом верхнем, общем уровне иерархии документов безопасности?
A: Политика (policy).
Q: «Сотруднику выдаются только права, необходимые для работы» — какой это принцип?
A: Наименьших привилегий (least privilege).
Q: Чем процедура отличается от политики?
A: Политика определяет, что и зачем делается, а процедура — как это сделать пошагово.
Q: Приведите пример разделения обязанностей.
A: Платёж вводит один сотрудник, утверждает другой — один человек не может в одиночку совершить мошенничество.
Q: Что устанавливает ISO/IEC 27001?
A: Требования к системе управления информационной безопасностью (СУИБ).
