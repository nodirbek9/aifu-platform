## Почему эта тема важна?

Как узнать, что скачанная программа не была изменена по дороге, что пароль, украденный из базы, всё равно нельзя прочитать, что электронный документ подписал именно этот руководитель? Ответ — **хеш-функции** и построенная на них **электронная цифровая подпись**. В Узбекистане налоговая отчётность, портал государственных услуг и электронный документооборот работают с ключами ЭЦП — каждый специалист должен знать, как они устроены.

## Хеш-функция

**Криптографическая хеш-функция** *H* превращает данные любой длины в значение фиксированной длины (хеш, «отпечаток пальца»).

| Свойство | Смысл |
|---|---|
| **Детерминированность** | одинаковый вход — всегда одинаковый хеш |
| **Односторонность** (preimage resistance) | найти *x* по *H*(*x*) практически невозможно |
| **Стойкость ко второму прообразу** | для данного *x* нельзя найти другой *x'* с *H*(*x'*) = *H*(*x*) |
| **Стойкость к коллизиям** | нельзя найти никакую пару с *H*(*x*) = *H*(*y*) |
| **Лавинный эффект** | изменение одного бита входа меняет около половины битов хеша |

| Алгоритм | Длина хеша | Состояние |
|---|---|---|
| MD5 | 128 бит | **взломан** (коллизии за секунды) — не используйте для безопасности |
| SHA-1 | 160 бит | **взломан** (коллизия SHAttered, 2017 год) |
| SHA-256, SHA-512 (SHA-2) | 256, 512 бит | надёжен, широко распространён |
| SHA-3 (Keccak) | 224–512 бит | надёжен, другое внутреннее устройство («губка») |
| O'z DSt 1106:2009 | 256 бит | национальный стандарт хеширования Узбекистана |

Применение: проверка целостности файлов (значения SHA-256 на страницах загрузки), хранение паролей, цифровая подпись, блокчейн, цифровая криминалистика.

**Парадокс дней рождения**: в группе из 23 человек вероятность совпадения дней рождения у двоих превышает 50%. С хешами так же: для *b*-битного хеша коллизию можно найти примерно за **2^(*b*/2)** попыток. Поэтому для стойкости к коллизиям хеш должен иметь не менее 256 бит (128-битная стойкость).

**Хранение паролей**: хранится не сам пароль, а его хеш. Но простого SHA-256 недостаточно — злоумышленник находит простые пароли с помощью готовых таблиц (rainbow tables) и миллиардов попыток в секунду. Правильный способ: добавлять случайную **соль** (salt) для каждого пользователя и использовать намеренно **медленные** алгоритмы — **bcrypt, scrypt, Argon2, PBKDF2**.

## MAC и HMAC

Хеш проверяет целостность, но вычислить его может каждый: злоумышленник может заменить и файл, и его хеш. **MAC** (Message Authentication Code) — контрольное значение, вычисляемое с **секретным ключом**: тот, кто не знает ключа и меняет сообщение, не сможет подобрать MAC. Самый распространённый — **HMAC** = *H*((*K* ⊕ opad) ‖ *H*((*K* ⊕ ipad) ‖ *M*)), например HMAC-SHA256 (токены JWT, подписи API). MAC даёт целостность и аутентификацию, но не **неотказуемость**: ключ есть у обеих сторон, и доказать, кто создал MAC, нельзя.

## Электронная цифровая подпись (ЭЦП)

ЭЦП основана на асимметричной криптографии: подпись может создать только владелец **закрытого ключа**, а проверить её **открытым ключом** может каждый.

1. **Подписание**: вычисляется хеш документа *h* = *H*(*M*); *h* подписывается закрытым ключом → подпись *S*.
2. **Отправка**: документ *M* и подпись *S* (и обычно сертификат).
3. **Проверка**: получатель сам вычисляет *H*(*M*) и проверяет подпись открытым ключом отправителя; если совпадает — документ не изменён и подписан именно владельцем этого ключа.

ЭЦП обеспечивает три услуги: **целостность**, **подлинность** и **неотказуемость**. Алгоритмы: RSA-PSS, ECDSA, EdDSA (Ed25519); в Узбекистане — национальный стандарт O'z DSt 1092:2009. Согласно Закону «Об электронной цифровой подписи», ЭЦП приравнивается к собственноручной подписи; ключи и сертификаты выдают уполномоченные центры (например, для государственных услуг и налоговой системы).

## PKI и сертификаты X.509

Как узнать, что открытый ключ действительно принадлежит «Банку X»? **PKI** (Public Key Infrastructure) решает эту задачу через доверенную третью сторону.

| Элемент | Назначение |
|---|---|
| **Удостоверяющий центр** (CA) | выдаёт за своей подписью сертификат, связывающий открытый ключ с владельцем |
| **Регистрационный центр** (RA) | проверяет личность владельца |
| **Корневой CA** | самоподписанный; его открытый ключ заранее установлен в ОС и браузерах |
| **Промежуточный CA** | подписан корневым CA; выдаёт сертификаты пользователям (корневой ключ хранится офлайн) |
| **Отзыв** | сертификаты, отозванные до истечения срока, — список CRL или служба OCSP |

**Цепочка доверия**: сертификат сайта → промежуточный CA → корневой CA. Браузер проверяет подпись каждого сертификата открытым ключом вышестоящего, а корневой должен быть в списке доверенных.

Поля **сертификата X.509**:

| Поле | Содержание |
|---|---|
| Version, Serial Number | версия (3), уникальный серийный номер |
| Signature Algorithm | алгоритм подписи CA (например, sha256WithRSAEncryption) |
| Issuer | CA, выдавший сертификат |
| Validity | срок действия (Not Before, Not After) |
| Subject | владелец (имя сайта, организация) |
| Subject Public Key Info | открытый ключ владельца |
| Extensions | Subject Alternative Name (домены), Key Usage, Basic Constraints и другие |
| Подпись CA | подпись хеша всех полей выше |

## Разобранный пример 1: лавинный эффект

В учебных целях возьмём простую 32-битную хеш-функцию **FNV-1a** (она не криптографическая, но хорошо показывает лавинный эффект): *h* = 2166136261; для каждого байта *h* = (*h* ⊕ байт) · 16777619 mod 2³². Выведите хеш каждой строки и число битов, которыми он отличается от хеша предыдущей строки.

```python
import sys


def fnv1a(matn):
    h = 2166136261
    for bayt in matn.encode("utf-8"):
        h = ((h ^ bayt) * 16777619) & 0xFFFFFFFF   # mod 2^32
    return h


oldingi = None
for satr in sys.stdin.read().split("\n"):
    if not satr:
        continue
    h = fnv1a(satr)
    qator = format(h, "08x") + " " + satr
    if oldingi is not None:
        qator += " (разница: " + str(bin(h ^ oldingi).count("1")) + " bit)"   # изменившиеся биты
    print(qator)
    oldingi = h
```
```java
import java.nio.charset.StandardCharsets;
import java.util.Scanner;

public class Main {
    static int fnv1a(String matn) {
        int h = 0x811C9DC5;                                       // 2166136261
        for (byte bayt : matn.getBytes(StandardCharsets.UTF_8)) {
            h = (h ^ (bayt & 0xFF)) * 16777619;                   // mod 2^32 (переполнение int)
        }
        return h;
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in, StandardCharsets.UTF_8);
        Integer oldingi = null;
        while (in.hasNextLine()) {
            String satr = in.nextLine();
            if (satr.isEmpty()) continue;
            int h = fnv1a(satr);
            String qator = String.format("%08x", h) + " " + satr;
            if (oldingi != null) {
                qator += " (разница: " + Integer.bitCount(h ^ oldingi) + " bit)";   // изменившиеся биты
            }
            System.out.println(qator);
            oldingi = h;
        }
    }
}
```
```cpp
#include <bitset>
#include <cstdint>
#include <cstdio>
#include <iostream>
#include <string>
using namespace std;

uint32_t fnv1a(const string& matn) {
    uint32_t h = 2166136261u;
    for (unsigned char bayt : matn) {
        h = (h ^ bayt) * 16777619u;                               // mod 2^32 (переполнение uint32_t)
    }
    return h;
}

int main() {
    string satr;
    bool bor = false;
    uint32_t oldingi = 0;
    while (getline(cin, satr)) {
        if (satr.empty()) continue;
        uint32_t h = fnv1a(satr);
        char buf[16];
        snprintf(buf, sizeof buf, "%08x", h);
        string qator = string(buf) + " " + satr;
        if (bor) {
            qator += " (разница: " + to_string(bitset<32>(h ^ oldingi).count()) + " bit)";   // изменившиеся биты
        }
        cout << qator << endl;
        oldingi = h;
        bor = true;
    }
    return 0;
}
```

Ввод:

```text
salom
Salom
salom!
parol123
```

Вывод:

```text
6883e297 salom
10b9bd37 Salom (разница: 16 bit)
3d9de482 salom! (разница: 15 bit)
1e16e5c5 parol123 (разница: 12 bit)
```

Изменение регистра одной буквы или добавление одного символа изменило около половины из 32 битов — по хешу нельзя понять, насколько «близки» входы. Но FNV-1a **не криптографическая**: целенаправленно находить в ней коллизии легко. Для настоящей проверки целостности используется SHA-256 — это задание практического занятия A8.

## Разобранный пример 2: парадокс дней рождения

В каждой строке — длина хеша *b* (бит) и число хешируемых объектов *k*. Выведите вероятность коллизии *P* ≈ 1 − e^(−*k*(*k*−1) / 2^(*b*+1)) и число объектов, нужное для вероятности 50%, ≈ 1,1774 · 2^(*b*/2).

```python
import math
import sys

for satr in sys.stdin.read().split("\n"):
    if not satr.strip():
        continue
    b, k = map(int, satr.split())
    ehtimol = -math.expm1(-k * (k - 1.0) / 2.0 ** (b + 1))   # точное вычисление 1 − e^(−x)
    yarim = 1.1774 * 2.0 ** (b / 2)
    print(f"{b} bit, {k} шт.: P = {ehtimol:.2e}, 50% при ~{yarim:.2e} шт.")
```
```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        while (in.hasNextInt()) {
            int b = in.nextInt();
            long k = in.nextLong();
            double ehtimol = -Math.expm1(-k * (k - 1.0) / Math.pow(2.0, b + 1));   // точное вычисление 1 − e^(−x)
            double yarim = 1.1774 * Math.pow(2.0, b / 2.0);
            System.out.println(String.format("%d bit, %d шт.: P = %.2e, 50%% при ~%.2e шт.", b, k, ehtimol, yarim));
        }
    }
}
```
```cpp
#include <cmath>
#include <cstdio>
#include <iostream>
using namespace std;

int main() {
    int b;
    long long k;
    while (cin >> b >> k) {
        double ehtimol = -expm1(-k * (k - 1.0) / pow(2.0, b + 1));    // точное вычисление 1 − e^(−x)
        double yarim = 1.1774 * pow(2.0, b / 2.0);
        printf("%d bit, %lld шт.: P = %.2e, 50%% при ~%.2e шт.\n", b, k, ehtimol, yarim);
    }
    return 0;
}
```

```text

32 100000
64 100000000
128 1000000000000
```

Вывод:

```text

32 bit, 100000 шт.: P = 6.88e-01, 50% при ~7.72e+04 шт.
64 bit, 100000000 шт.: P = 2.71e-04, 50% при ~5.06e+09 шт.
128 bit, 1000000000000 шт.: P = 1.47e-15, 50% при ~2.17e+19 шт.
```

Для 32-битного хеша (4 миллиарда значений) вероятность коллизии достигает 50% уже при 77 тысячах объектов — поэтому короткие хеши непригодны для безопасности. При 128 битах вероятность даже для триллиона объектов — 10⁻¹⁵, но если злоумышленник способен на 2⁶⁴ попыток, риск есть; современное требование — не менее 256 бит.

:::warning
**Частые ошибки**

- **Считать хеш шифрованием.** Хеш односторонний — его нельзя «расшифровать»; ключа тоже нет.
- **Хранить пароли с MD5 или SHA-256 без соли.** Готовые таблицы и GPU быстро находят простые пароли; используйте bcrypt или Argon2.
- **Использовать MD5 и SHA-1 для безопасности.** Оба взломаны в части коллизий.
- **Считать MAC подписью.** MAC не даёт неотказуемости — ключ у обеих сторон.
- **Игнорировать предупреждения о сертификатах.** «Недоверенный сертификат» может быть признаком атаки «человек посередине».
:::

:::tip
В Windows вычислите хеш любого файла командой `certutil -hashfile file.exe SHA256` (в PowerShell — `Get-FileHash file.exe`) и сравните его со значением, опубликованным на сайте, откуда скачана программа. В браузере нажмите на значок замка любого HTTPS-сайта и посмотрите цепочку сертификатов (сайт → промежуточный → корневой CA).
:::

## Итоги

- Хеш: фиксированная длина, односторонность, стойкость к коллизиям, лавинный эффект; MD5 и SHA-1 взломаны, SHA-2 и SHA-3 надёжны.
- Парадокс дней рождения: коллизия за ~2^(*b*/2) попыток; отсюда 256 бит.
- Пароли: соль + медленные алгоритмы (bcrypt, scrypt, Argon2, PBKDF2).
- MAC (HMAC) — целостность и аутентификация с ключом; ЭЦП — подпись закрытым ключом, проверка открытым, даёт неотказуемость.
- PKI: CA, RA, корневой и промежуточный CA, цепочка доверия, CRL/OCSP; сертификат X.509 связывает владельца и его открытый ключ подписью CA.

## Проверьте себя

:::check
Q: Что означает стойкость к коллизиям?
A: Найти два разных входа с одинаковым хешем практически невозможно.
Q: Почему для паролей рекомендуют bcrypt или Argon2, а не простой SHA-256?
A: Они намеренно медленные и используют соль — это делает готовые таблицы и скоростной перебор неэффективными.
Q: В чём главное отличие MAC от ЭЦП?
A: MAC вычисляется симметричным ключом и не даёт неотказуемости; ЭЦП создаётся закрытым ключом, и создать её может только владелец.
Q: Браузер проверяет, кто подписал сертификат сайта. Кто это?
A: Удостоверяющий центр (CA) — обычно промежуточный CA, который, в свою очередь, связан с корневым CA.
Q: Какое поле сертификата X.509 показывает, для каких доменов действителен сертификат?
A: Расширение Subject Alternative Name (SAN).
:::
