## Почему эта тема важна?

Отпечаток пальца — самый распространённый биометрический признак: он используется в телефонах, ноутбуках, банковских приложениях, системах контроля доступа и на паспортном контроле. ЭЦП придаёт электронному документу юридическую силу (M8). Эти технологии часто работают вместе: вы прикладываете палец к сканеру, а устройство подписывает запрос закрытым ключом внутри себя (FIDO2 из M10). Знание принципов их работы и ограничений — условие правильного применения.

## Признаки отпечатка пальца

Узор **папиллярных линий** на коже пальца формируется ещё до рождения и не меняется в течение жизни; он различается даже у близнецов.

| Уровень | Признаки | Применение |
|---|---|---|
| 1-й уровень (общий узор) | дуга, петля, завиток | классификация, быстрый поиск в базе |
| 2-й уровень (**минуции**) | окончания линий, раздвоения, их положение и направление | основной метод сравнения |
| 3-й уровень | поры, толщина линий | высокоточный криминалистический анализ |

## Сканеры

| Тип | Принцип работы | Особенности |
|---|---|---|
| **Оптический** | получение изображения пальца камерой | дешёвый; уязвимее к простым подделкам |
| **Ёмкостный** (capacitive) | разница электрической ёмкости между гребнями и впадинами | широко распространён в телефонах и ноутбуках |
| **Ультразвуковой** | ультразвуковая волна в кожу и отражённый сигнал | 3D-изображение, работает и с грязным или влажным пальцем |
| **Термический и др.** | разница температур | встречается редко |

## Регистрация и сравнение

1. **Регистрация** (enrollment): палец сканируется несколько раз, из изображения выделяются минуции и строится **шаблон**. Хранится не само изображение, а только шаблон.
2. **Сравнение**: по новому образцу строится шаблон и сравнивается с сохранённым → **оценка сходства** (или различия) → сравнение с **порогом**.
3. Различают **верификацию** (1:1 — «это Али?») и **идентификацию** (1:N — «кто это?», например в криминалистической базе); при 1:N вероятность ошибки растёт с размером базы.

Ошибки — как в M10: **FAR** — принят посторонний, **FRR** — отклонён владелец; порог их уравновешивает. Два сканирования никогда не совпадают полностью (нажим, угол, влажность) — поэтому проверяется близость, а не точное равенство.

## Вопросы безопасности

- **Поддельные пальцы** (силикон, желатин, копии, напечатанные на 3D-принтере) — защита: **проверка живости** (кровоток, пот, слои кожи, ультразвуковое 3D-изображение).
- **Незаменимость**: утёкший пароль меняют, утёкший отпечаток — навсегда. Поэтому шаблоны хранят не на центральном сервере, а в зашифрованном виде в **защищённом анклаве устройства** (Secure Enclave, TPM, TEE), и наружу они не выходят.
- **Принуждение**: заставить приложить палец проще, чем заставить назвать пароль — в особо важных системах биометрию сочетают с PIN.
- **Персональные данные**: биометрические данные защищены Законом «О персональных данных»; их сбор требует согласия и основания.

## Отпечаток пальца и ЭЦП

В современных устройствах отпечаток — **не сама ЭЦП**: он **открывает доступ к закрытому ключу** на устройстве:

1. На устройстве создаётся пара ключей; закрытый ключ не покидает защищённый анклав.
2. При запросе подписи или входа пользователь подтверждает действие отпечатком.
3. Анклав подписывает хеш документа или запроса закрытым ключом; сервер проверяет открытым ключом (M8).

Так биометрические данные вообще не попадают в сеть, а подпись криптографически стойкая. В Узбекистане ключ ЭЦП хранится в файле или в чипе ID-карты и защищается PIN/паролем; по закону ЭЦП приравнивается к собственноручной подписи, сертификаты выдают уполномоченные центры (M8, A8).

## Разобранный пример: сравнение шаблонов по расстоянию Хэмминга

Некоторые биометрические системы (например, коды радужной оболочки и некоторые шаблоны отпечатков) хранят признаки в виде **двоичного вектора** и сравнивают их по **нормированному расстоянию Хэмминга**: HD = число различающихся битов / число битов. Для случайных посторонних образцов HD ≈ 0,5; для образцов одного человека — гораздо меньше. В первой строке — порог, во второй — сохранённый шаблон, в следующих — «имя образец». Если HD ≤ порога — `совпадает`.

```python
import sys

satrlar = [s.split() for s in sys.stdin.read().split("\n") if s.strip()]
chegara = float(satrlar[0][0])
shablon = satrlar[1][0]
for nom, namuna in satrlar[2:]:
    farq = sum(1 for a, b in zip(shablon, namuna) if a != b)   # различающиеся биты
    hd = farq / len(shablon)                                    # нормированное расстояние Хэмминга
    print(f"{nom}: HD={hd:.3f} -> " + ("совпадает" if hd <= chegara else "не совпадает"))
```
```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        double chegara = Double.parseDouble(in.next());
        String shablon = in.next();
        while (in.hasNext()) {
            String nom = in.next(), namuna = in.next();
            int farq = 0;
            for (int i = 0; i < shablon.length(); i++) {
                if (shablon.charAt(i) != namuna.charAt(i)) farq++;   // различающиеся биты
            }
            double hd = (double) farq / shablon.length();             // нормированное расстояние Хэмминга
            System.out.println(String.format("%s: HD=%.3f -> %s", nom, hd, hd <= chegara ? "совпадает" : "не совпадает"));
        }
    }
}
```
```cpp
#include <cstdio>
#include <iostream>
#include <string>
using namespace std;

int main() {
    double chegara;
    string shablon, nom, namuna;
    cin >> chegara >> shablon;
    while (cin >> nom >> namuna) {
        int farq = 0;
        for (size_t i = 0; i < shablon.size(); i++) {
            if (shablon[i] != namuna[i]) farq++;                     // различающиеся биты
        }
        double hd = (double) farq / shablon.size();                  // нормированное расстояние Хэмминга
        printf("%s: HD=%.3f -> %s\n", nom.c_str(), hd, hd <= chegara ? "совпадает" : "не совпадает");
    }
    return 0;
}
```

Вывод:

```text
egasi_1: HD=0.000 -> совпадает
egasi_2: HD=0.100 -> совпадает
egasi_3: HD=0.125 -> совпадает
begona_1: HD=0.475 -> не совпадает
begona_2: HD=0.550 -> не совпадает
```

(egasi — владелец, begona — посторонний.) Образцы владельца отличались на 10–12,5% (из-за нажима и угла), посторонних — примерно наполовину, как случайные биты. Обратите внимание: `egasi_1` **в точности совпадает** с сохранённым шаблоном (HD = 0). При реальном сканировании такого почти не бывает — подобный результат может быть признаком повторной отправки ранее перехваченного шаблона, поэтому некоторые системы считают подозрительным и слишком малое различие. Если опустить порог ниже 0,25, вырастет FRR; если поднять — FAR.

:::warning
**Частые ошибки**

- **Считать отпечаток «паролем».** Он не секретен — мы оставляем его на всём, чего касаемся; это идентификатор и фактор удобства, а не секрет.
- **Хранить биометрические изображения на сервере.** Только защищённые шаблоны и по возможности на устройстве.
- **Требовать точного равенства.** Биометрия всегда приблизительна; нужны порог и баланс FAR/FRR.
- **Дешёвый сканер без проверки живости.** Его легко обмануть поддельным пальцем.
- **Хранить ключ ЭЦП без PIN.** При краже устройства или файла подпись подделают.
:::

:::tip
Настраивая разблокировку телефона отпечатком, сканируйте один и тот же палец много раз под разными углами — это снижает FRR. Для важных приложений (банк) включайте сочетание биометрии и PIN или пароля устройства.
:::

## Итоги

- Отпечатки сравниваются по минуциям; хранится шаблон, а не изображение.
- Сканеры: оптические, ёмкостные, ультразвуковые; против поддельных пальцев — проверка живости.
- Сравнение приблизительное: оценка сходства, порог, FAR и FRR; верификация 1:1 и идентификация 1:N.
- Шаблоны — в защищённом анклаве устройства; биометрию нельзя заменить.
- Отпечаток открывает закрытый ключ, а подпись создаёт криптография (ЭЦП).

Q: Какие признаки в основном используются при сравнении отпечатков?
A: Минуции — окончания и раздвоения линий, их положение и направление.
Q: Почему биометрические шаблоны хранят в защищённом анклаве устройства?
A: Биометрию нельзя заменить; утечка из центральной базы создаёт пожизненный риск.
Q: Что на самом деле создаёт подпись в ЭЦП, подтверждённой отпечатком?
A: Закрытый ключ на устройстве; отпечаток лишь открывает к нему доступ.
Q: Почему образец с расстоянием Хэмминга 0 может быть подозрительным?
A: Реальные сканирования всегда немного различаются; полностью совпадающий образец может быть повторно отправленным шаблоном.
