## Почему это важно

В обычной рекурсии функция вызывает себя с меньшим аргументом: *f*(*n* − 1). Во **вложенной рекурсии** сам аргумент тоже является вызовом этой функции: *f*(*f*(*n* + 11)). Такие функции записываются очень коротко, но предсказать число их вызовов и результат трудно — их изучают в теории вычислений, отвечая на вопрос «насколько мощна рекурсия?». В этой самостоятельной работе вы потренируетесь отслеживать вложенную рекурсию и анализировать её поведение.

:::note
**После этой самостоятельной работы вы сможете:**

- отличать вложенную рекурсию от обычной;
- пошагово отслеживать последовательность вложенных вызовов;
- измерять число вызовов с помощью глобального счётчика;
- правильно настраивать программу с учётом предела глубины рекурсии.
:::

## Краткое повторение темы

| Вид рекурсии | Вид записи | Пример |
|---|---|---|
| Линейная | один вызов | *n*! = *n* · (*n* − 1)! |
| Древовидная | несколько независимых вызовов | *F*(*n*) = *F*(*n* − 1) + *F*(*n* − 2) |
| Вложенная | результат вызова снова аргумент | *M*(*n*) = *M*(*M*(*n* + 11)) |

Вложенный вызов вычисляется **изнутри наружу**: сначала полностью вычисляется внутренний *M*(*n* + 11), и его результат становится аргументом внешнего *M*. Доказать, что такая рекурсия остановится, сложнее, чем для обычной: аргумент не всегда уменьшается (*n* + 11 — больше!).

Чтобы считать вызовы, **счётчик** объявляют вне функции и увеличивают в её первой строке: в Python — `global soni`, в Java — `static long soni`, в C++ — глобальная переменная.

## Образец: функция Маккарти 91

Функция, предложенная Джоном Маккарти (автором термина «искусственный интеллект»):

```text
M(n) = n − 10,          если n > 100
M(n) = M(M(n + 11)),    иначе
```

Дано *n* (0 ≤ *n* ≤ 200). Выведите *M*(*n*) и сколько всего раз была вызвана функция.

```python
import sys

sys.setrecursionlimit(10000)
soni = 0


def m(n):
    global soni
    soni += 1
    if n > 100:
        return n - 10
    return m(m(n + 11))             # вложенный вызов


n = int(input())
natija = m(n)
print(natija)
print(soni)
```
```java
import java.util.Scanner;

public class Main {
    static long soni = 0;

    static int m(int n) {
        soni++;
        if (n > 100) return n - 10;
        return m(m(n + 11));        // вложенный вызов
    }

    public static void main(String[] args) {
        int n = new Scanner(System.in).nextInt();
        int natija = m(n);
        System.out.println(natija);
        System.out.println(soni);
    }
}
```
```cpp
#include <iostream>
using namespace std;

long long soni = 0;

int m(int n) {
    soni++;
    if (n > 100) return n - 10;
    return m(m(n + 11));            // вложенный вызов
}

int main() {
    int n;
    cin >> n;
    int natija = m(n);
    cout << natija << endl;
    cout << soni << endl;
    return 0;
}
```

Последовательность вызовов — в самостоятельной работе требуется именно такая таблица (для *M*(99)):

| Шаг | Вызов | Что происходит |
|---|---|---|
| 1 | *M*(99) | 99 ≤ 100 → *M*(*M*(110)) |
| 2 | *M*(110) | 110 > 100 → 100 |
| 3 | *M*(100) | 100 ≤ 100 → *M*(*M*(111)) |
| 4 | *M*(111) | 111 > 100 → 101 |
| 5 | *M*(101) | 101 > 100 → **91** |

Тесты:

| Ввод | *M*(*n*) | Число вызовов |
|---|---|---|
| 99 | 91 | 5 |
| 87 | 91 | 29 |
| 150 | 140 | 1 |
| 0 | 91 | 203 |

Замечательное свойство: для **любого** *n* меньше 101 результат всегда 91 — отсюда название функции. Заранее это не видно, понять это можно лишь отслеживая вызовы или с помощью математического доказательства (*soni* — количество, *natija* — результат). В Python `setrecursionlimit` поднимает предел глубины: при *n* = 0 рекурсия уходит глубже 100 уровней.

## Задание самостоятельной работы

Решите задание ниже: **функция Аккермана**:

```text
A(0, n) = n + 1
A(m, 0) = A(m − 1, 1),               m > 0
A(m, n) = A(m − 1, A(m, n − 1)),     m > 0, n > 0
```

Даны *m* и *n* (0 ≤ *m* ≤ 3, 0 ≤ *n* ≤ 5); выведите *A*(*m*, *n*). Что сдаётся:

1. **Таблица вызовов** — вся последовательность вызовов для *A*(1, 2) (как в образце выше).
2. **Программа** — на Python, Java или C++; отправляется в окне задания ниже и должна пройти автоматические тесты.
3. **Таблица экспериментов** — результаты для *m* = 0, 1, 2, 3 и *n* = 0…3 и число вызовов (измеренное счётчиком).
4. **Вывод** — 3–5 предложений: как растут результат и число вызовов с ростом *m*; почему *A*(4, 2) вычислить нельзя.

:::warning
**Критерии оценки и частые ошибки**

- Функция должна проверять три случая определения именно в таком порядке: сначала *m* = 0, затем *n* = 0.
- В Python увеличьте `sys.setrecursionlimit`: для *A*(3, 5) глубина доходит до сотен уровней.
- Результат может быть большим, но в данных пределах помещается в `int` — проверьте это в выводе.
- Число вызовов в таблице экспериментов измеряется программой, а не угадывается.
:::

:::tip
Сначала вычислите несколько значений *A*(0, *n*), затем *A*(1, *n*) и *A*(2, *n*) и поищите закономерность (например, *A*(1, *n*) = *n* + 2). Найденные формулы помогут проверить результаты программы.
:::

## Итоги

- Во вложенной рекурсии результат вызова снова становится аргументом той же функции; вычисление идёт изнутри наружу.
- Результат и число вызовов таких функций заранее не видны — их изучают с помощью таблицы отслеживания и счётчика.
- Чтобы измерить число вызовов, счётчик вне функции увеличивается при каждом вызове.
- При глубокой рекурсии учитывайте ограничения языка: `setrecursionlimit` в Python, размер стека в Java и C++.

## Проверьте себя

:::check
Q: Чем вложенная рекурсия отличается от древовидной?
A: В древовидной вызовы независимы и их результаты складываются; во вложенной результат одного вызова — аргумент другого.
Q: Какой вызов выполняется первым в *M*(*M*(110))?
A: Внутренний *M*(110); его результат (100) передаётся внешнему *M*.
Q: Чему равно *M*(50)?
A: 91 — для любого *n* меньше 101 *M*(*n*) = 91.
Q: Почему счётчик вызовов объявляется вне функции, а не внутри?
A: Переменная внутри функции создаётся заново при каждом вызове; общий итог накапливается только во внешней (глобальной или статической) переменной.
:::
